Tier 3 — Expert 60 minConsensus / Distributed

Design a Distributed Database (like Google Spanner)

Spanner achieves the seemingly impossible: externally consistent, globally distributed transactions. The secret is TrueTime — GPS + atomic clocks that provide a globally monotonic clock with bounded uncertainty. Combined with Raft consensus, transactions are ordered by real time.

🏢 Google, CockroachDB, YugabyteDB
⏱️ 60 min interview
🌐 Global ACID

❓R — Requirements3–5 min

Functional Requirements

  • Relational data model with SQL query interface
  • ACID transactions across multiple rows, tables, and geographically distributed nodes
  • Strong consistency: reads always see the latest committed data
  • Horizontal partitioning (sharding) with automatic rebalancing
  • Multi-region deployment for low-latency global reads

Non-Functional Requirements

  • Scale: Petabytes of data, millions of QPS globally
  • Consistency: Linearizable (external consistency) — stronger than serializable
  • Availability: Survives single datacenter failures
  • Latency: Single-region reads: <10ms; cross-region: <100ms

🔢E — Estimation3–5 min

  • Data sharded into ~64MB "splits" (Spanner's tablets). PB database = 15M tablets.
  • Each tablet replicated to 5 Raft followers across regions (f=2 failure tolerance)
  • Raft commit: 3/5 acknowledgements needed → 1 cross-region round trip (~100ms)
  • TrueTime uncertainty: ~7ms globally → commits must wait this long to ensure ordering

🗄️S — Schema3–5 min

// Spanner's physical storage: tablets (sorted key ranges)
// Each tablet is a key range of a table, replicated via Raft
// Tablets are automatically split when they exceed ~64MB

// Logical schema (SQL DDL)
CREATE TABLE Accounts (
    account_id  STRING(36) NOT NULL,
    owner_id    STRING(36) NOT NULL,
    balance     INT64,        // stored in cents
    last_txn_ts TIMESTAMP,
    PRIMARY KEY (account_id)
) INTERLEAVE IN PARENT Customers ON DELETE CASCADE;
// Interleaving: child rows co-located with parent — avoids cross-tablet joins

// Transactions stored with commit timestamp from TrueTime
CREATE TABLE Transactions (
    txn_id      STRING(36),
    account_id  STRING(36),
    amount      INT64,
    commit_ts   TIMESTAMP,    // assigned by TrueTime at commit
    PRIMARY KEY (account_id, commit_ts)
);

🏗️H — High-level Design10 min

  • Zones: Each datacenter is a zone. Each zone has zone masters (Paxos-elected) and tablet servers.
  • Tablet Servers: Own a set of tablets. Each tablet is a Raft group with replicas across 3–5 zones.
  • Raft Consensus: All writes go to the Raft leader for a tablet. Leader replicates to majority of followers. Once majority acks, commit is durable.
  • TrueTime: Each server has TT.now() → [earliest, latest] bounded interval. Commit timestamp assigned from TrueTime. Server waits until TT.now().earliest > commit_ts before making commit visible (commit-wait).
  • 2PC for cross-tablet transactions: Transaction coordinator (one of the participant leaders) runs 2PC. Prepare → commit with TrueTime timestamp. Abort if any participant fails.
  • Read modes: Strong reads go to Raft leader. Stale reads (as of timestamp T) can go to any replica with data as of T.

🔬D — Deep Dive: Raft Consensus + TrueTime10 min

Raft consensus:

  1. Leader election: nodes vote for candidate with most up-to-date log. Majority required.
  2. Log replication: leader appends entry, sends AppendEntries to followers. Once majority ack, entry is committed.
  3. Safety: only nodes with all committed entries can become leader. Ensures no committed entry is lost.

TrueTime for global ordering:

  • Problem: distributed systems have no global clock. NTP has ±100ms drift.
  • TrueTime uses GPS receivers + atomic clocks in each datacenter. Uncertainty: ε ≈ 7ms typically.
  • TT.now() returns [t-ε, t+ε]. The real time is guaranteed within this interval.
  • Commit protocol: assign commit_ts = TT.now().latest. Then wait until TT.now().earliest > commit_ts (commit-wait, ~14ms). This ensures no future transaction can be assigned a timestamp before commit_ts.
  • Result: transactions are ordered by their commit timestamps, which are guaranteed to reflect real-time ordering. This is external consistency (stronger than serializable).

✅E — Evaluate3 min

  • Latency cost of TrueTime: Commit-wait adds ~14ms per write. Acceptable for most OLTP. For high-frequency trading: not acceptable — use a single-region DB.
  • Cross-region write latency: 2PC across regions = 1 round-trip ≈ 100ms. Mitigate with: write to local region leader + async replicate, at the cost of weaker consistency (see CockroachDB's approaches).

🚀D — Deliver2 min

We designed a globally distributed database with external consistency. Key components: Raft per tablet for durable replication, TrueTime with GPS/atomic clocks for globally ordered timestamps, commit-wait to guarantee temporal ordering, and 2PC across tablet leaders for distributed transactions.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Consensus algorithmRaftPaxosRaft is equivalent in safety but easier to understand and implement (strong leader, clear log). Paxos has no strong leader concept — harder to build on.
Global orderingTrueTime (GPS+atomic clock)Logical clocks (Lamport)Logical clocks prove ordering but don't give real-time semantics. TrueTime enables read-only transactions at a real timestamp without coordination.
Distributed transactions2PC with Raft leadersSaga / compensating transactionsSpanner targets strict ACID — 2PC provides atomicity across tablets. Saga only provides eventual consistency — not acceptable for financial data.

☕Java Implementation

/**
 * RaftNode — simplified Raft consensus participant.
 * Implements RequestVote and AppendEntries RPC stubs for illustrative purposes.
 * A real implementation would include log persistence, snapshotting, and network I/O.
 */
public class RaftNode {
    public enum NodeState { FOLLOWER, CANDIDATE, LEADER }

    private NodeState state = NodeState.FOLLOWER;
    private int currentTerm = 0;
    private String votedFor = null;
    private final List<LogEntry> log = new ArrayList<>();
    private int commitIndex = 0;
    private final String nodeId;
    private final List<String> peerNodeIds;

    public RaftNode(String nodeId, List<String> peerNodeIds) {
        this.nodeId = nodeId;
        this.peerNodeIds = peerNodeIds;
    }

    /**
     * RequestVote RPC — called by candidates during election.
     * Grants vote if: (a) candidate's term >= our term, AND
     *                 (b) we haven't voted yet (or voted for this candidate), AND
     *                 (c) candidate's log is at least as up-to-date as ours.
     */
    public RequestVoteResponse handleRequestVote(RequestVoteRequest request) {
        if (request.getTerm() < currentTerm) {
            return new RequestVoteResponse(currentTerm, false);
        }
        if (request.getTerm() > currentTerm) {
            currentTerm = request.getTerm();
            state = NodeState.FOLLOWER;
            votedFor = null;
        }
        boolean logIsUpToDate = isLogUpToDate(request.getLastLogIndex(), request.getLastLogTerm());
        boolean canVote = (votedFor == null || votedFor.equals(request.getCandidateId())) && logIsUpToDate;
        if (canVote) {
            votedFor = request.getCandidateId();
        }
        return new RequestVoteResponse(currentTerm, canVote);
    }

    /**
     * AppendEntries RPC — called by leader to replicate log entries.
     * Also serves as heartbeat (empty entries) to prevent election timeouts.
     */
    public AppendEntriesResponse handleAppendEntries(AppendEntriesRequest request) {
        if (request.getTerm() < currentTerm) {
            return new AppendEntriesResponse(currentTerm, false);
        }
        // Valid leader — reset election timeout (not shown: cancel timer)
        currentTerm = request.getTerm();
        state = NodeState.FOLLOWER;

        // Verify log consistency at prevLogIndex
        if (!logConsistencyCheck(request.getPrevLogIndex(), request.getPrevLogTerm())) {
            return new AppendEntriesResponse(currentTerm, false);
        }

        // Append new entries (removing conflicting entries first)
        appendNewEntries(request.getEntries(), request.getPrevLogIndex());

        // Update commit index
        if (request.getLeaderCommit() > commitIndex) {
            commitIndex = Math.min(request.getLeaderCommit(), log.size() - 1);
        }
        return new AppendEntriesResponse(currentTerm, true);
    }

    private boolean isLogUpToDate(int candidateLastIndex, int candidateLastTerm) {
        if (log.isEmpty()) return true;
        LogEntry lastEntry = log.get(log.size() - 1);
        if (candidateLastTerm != lastEntry.getTerm()) {
            return candidateLastTerm > lastEntry.getTerm();
        }
        return candidateLastIndex >= log.size() - 1;
    }

    private boolean logConsistencyCheck(int prevLogIndex, int prevLogTerm) {
        if (prevLogIndex < 0) return true;
        if (prevLogIndex >= log.size()) return false;
        return log.get(prevLogIndex).getTerm() == prevLogTerm;
    }

    private void appendNewEntries(List<LogEntry> newEntries, int prevLogIndex) {
        int insertIndex = prevLogIndex + 1;
        for (LogEntry entry : newEntries) {
            if (insertIndex < log.size()) {
                if (log.get(insertIndex).getTerm() != entry.getTerm()) {
                    log.subList(insertIndex, log.size()).clear();
                }
            }
            if (insertIndex >= log.size()) {
                log.add(entry);
            }
            insertIndex++;
        }
    }

    // Supporting record types (abbreviated)
    record LogEntry(int term, String command) { public int getTerm() { return term; } }
    record RequestVoteRequest(int getTerm, String getCandidateId, int getLastLogIndex, int getLastLogTerm) {}
    record RequestVoteResponse(int getTerm, boolean isVoteGranted) {}
    record AppendEntriesRequest(int getTerm, int getPrevLogIndex, int getPrevLogTerm,
                                List<LogEntry> getEntries, int getLeaderCommit) {}
    record AppendEntriesResponse(int getTerm, boolean isSuccess) {}
}
