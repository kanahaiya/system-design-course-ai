Tier 3 — Expert 60 minInfrastructure

Design a Content Delivery Network (like Cloudflare / Akamai)

A CDN is a globally distributed cache network. The key insight is the cache hierarchy: L1 edge nodes serve 90% of traffic, L2 origin shield collapses thousands of L1 misses into one origin request, and the origin only sees 1-5% of total traffic. Understanding anycast routing, cache key design, and TTL strategy by content type is what separates surface-level from deep answers at L6.

🏢 Cloudflare, Akamai, AWS CloudFront, Fastly
⏱️ 60 min interview
📊 100Tbps capacity, 200+ PoPs, 95%+ cache hit rate

❓R — Requirements3–5 min

Functional Requirements

  • Static asset delivery: serve JS, CSS, images, video, fonts from the edge with sub-10ms TTFB for cache hits.
  • Dynamic content acceleration: forward uncacheable requests to origin over optimized TCP connections (persistent connections, TLS session reuse, anycast routing to nearest PoP).
  • Cache control: respect origin Cache-Control headers. Support CDN-specific bypass headers. TTL configurable per content type.
  • Content purge: URL-level purge, tag-based purge (surrogate keys), wildcard purge. Propagate purge to all PoPs within 5 seconds.
  • SSL/TLS termination: terminate HTTPS at the edge PoP. Issue and manage TLS certificates (Let's Encrypt, custom certificates). Support TLS 1.3 with 0-RTT for repeat visitors.
  • DDoS mitigation: absorb volumetric attacks (100Gbps+) at edge. Rate limiting by IP, ASN, and user agent. CAPTCHA challenge pages. IP reputation scoring.
  • WebSocket and streaming: proxy long-lived connections through the CDN without buffering. TCP proxy mode for WebSocket, HTTP streaming for video.
  • Image optimization: resize, convert format (WebP, AVIF), compress on-the-fly at the edge based on Accept header and device type.
  • Analytics and logging: per-request logs with cache status (HIT/MISS/BYPASS/EXPIRED), latency, and country. Aggregated analytics dashboard.

Non-Functional Requirements

  • Availability: 99.999% (5 nines). Single PoP failure must not affect users — anycast routes them to next-closest PoP automatically.
  • Cache hit rate: ≥95% for static assets, ≥60% overall (mixing static + dynamic).
  • TTFB for cache hits: <10ms measured at the edge (not including user network latency).
  • Purge propagation: content purge reaches all 200+ PoPs within 5 seconds.
  • DDoS scale: sustain 100Tbps attack traffic (Cloudflare peak: 71Tbps absorbed in 2022).
  • Origin offload: CDN should handle ≥95% of traffic; origin receives ≤5%.

Out of Scope

  • Origin server implementation (CDN is a read-through cache proxy)
  • DNS hosting (separate concern, though CDN providers often bundle it)
  • Video encoding/transcoding (handled upstream before CDN ingestion)

🔢E — Estimation3–5 min

Traffic Scale

  • Top CDN players: Cloudflare serves 45M+ HTTP requests/sec. Akamai claims 15-30% of global internet traffic. We'll design for a mid-tier CDN at 10M req/sec.
  • Network capacity: 10M req/sec × 50KB avg object = 500GB/sec = 4Tbps egress. With DDoS headroom (10x): provision 40Tbps+ edge capacity across all PoPs.
  • PoP count: 200 PoPs globally. Average 20Gbps per PoP for normal traffic. 200Gbps peak capacity per PoP for DDoS absorption.
  • Cache storage per PoP: serve the "hot" working set. Top 1M URLs × 100KB avg = 100GB per edge node. 3 edge servers per PoP → 300GB per PoP (fits in RAM + SSD L2).
  • Origin shield: without origin shield at 10M req/sec with 60% hit rate, origin sees 4M miss req/sec. Origin shield at regional level (20 shield nodes) reduces origin to 10K req/sec — 400x reduction. This is the single biggest win of multi-tier caching.
💡 The origin shield math: Without shield: 4M cache misses/sec hit origin. With 20 shield nodes: each shield handles 200K misses/sec, but each unique URL only misses once per shield node — thundering herd of 100 edge nodes becomes 1 request per shield. If working set is 1M URLs: origin sees at most 1M / shield_cache_size requests before they're cached at shield. At shield TTL=60s: origin max load = 1M / 60 = ~16K req/sec. That's 250x reduction.

Anycast Routing Explained

Anycast is a network addressing scheme where the same IP address is announced from multiple locations via BGP (Border Gateway Protocol). When a user's DNS resolves cdn.example.com to 104.16.0.1, the internet's routing tables direct that user to the nearest network that announced that IP — which is the nearest CDN PoP. If that PoP goes down, BGP withdraws its announcement, and routers automatically reroute to the next-closest PoP. This provides both geographic load distribution and automatic failover without any DNS TTL delays.

  • No DNS changes needed on failover: the IP stays the same, BGP routing changes. Failover is sub-second vs 30-300 seconds for DNS TTL-based failover.
  • Natural DDoS mitigation: attack traffic is distributed across all PoPs globally (not concentrated at one IP), so the full CDN capacity absorbs the attack.
  • Unicast alternative: GeoDNS returns different IPs per region. Slower failover (DNS TTL), but allows more explicit traffic steering. CDNs use anycast for edge IPs and GeoDNS for control plane / non-anycast paths.

Cache Hierarchy: Why Two Tiers?

The thundering herd problem: a popular piece of content expires simultaneously on all 200 PoP edge nodes. All 200 nodes send a cache miss request to origin at the same time. Origin is overwhelmed. The origin shield solves this with the "collapse" pattern:

  • All L1 (edge) nodes for a region send their misses to the L2 (shield) node for that region instead of directly to origin.
  • The L2 shield collapses concurrent misses for the same cache key into a single origin request.
  • The L2 receives the origin response, caches it, and serves all the waiting L1 nodes.
  • Result: origin sees 1 request (from shield) instead of potentially thousands (from all L1 edges in region).

TTL Strategy by Content Type

TTL is the most consequential CDN configuration decision. Too short: low cache hit rate, origin overloaded. Too long: stale content served after deployments.

🔬D — Deep Dive10 min

Cache Key Design: The Most Critical Decision

The cache key determines when two requests share the same cached response. Wrong cache key design leads to either cache poisoning (serving wrong user's data) or unnecessary cache misses.

// Correct cache key: method + normalized URL + selected header values
// WRONG: include session cookies in cache key → each user has own cache entry → 0% hit rate
// WRONG: ignore Accept-Encoding → serve gzip to client that only accepts identity

// Good cache key formula:
cache_key = SHA256(
    http_method +            // GET vs POST (POST should bypass, but include for safety)
    normalize_url(url) +     // lowercase host, remove default ports, sort query params
    vary_header_values       // ONLY the headers in the origin's Vary response header
)

// URL normalization:
// 1. Lowercase scheme and host
// 2. Remove default port (80 for http, 443 for https)
// 3. Decode percent-encoding where safe (e.g., %41 → A, but keep %20 as-is or normalize to +)
// 4. Sort query parameters alphabetically (so ?b=2&a=1 and ?a=1&b=2 are same key)
// 5. Remove cache-busting timestamp params if configured (e.g., ?_=1234567890)

// Vary header handling — the most dangerous footgun:
// If origin returns: Vary: Accept-Encoding
//   → CDN creates separate cache entries for gzip, br, identity
//   → This is CORRECT and expected
// If origin returns: Vary: Cookie
//   → CDN creates separate cache entry for EVERY unique cookie string
//   → With session cookies, EVERY request is a cache miss
//   → CDN cache hit rate: effectively 0%
//   → This is a catastrophic misconfiguration
// CDN best practice: strip Cookie from Vary if you want caching.
//   For private content, use CDN-Cache-Control: no-store instead.

TLS/SSL at the Edge

Every PoP terminates TLS before forwarding to origin. This means:

  • Shorter TLS handshake: user connects to the nearest PoP (low RTT), not the origin (high RTT). TLS handshake latency = 1 RTT for TLS 1.3. User in Tokyo connecting to AWS us-east-1 origin would do ~200ms handshake; connecting to Tokyo PoP: ~5ms.
  • TLS 1.3 0-RTT resumption: returning users send data in the first message (no handshake round-trip). Reduces TTFB to near-zero for cached responses for returning visitors. Trade-off: 0-RTT is vulnerable to replay attacks for non-idempotent requests (POST). CDN should not use 0-RTT for POST/PUT/DELETE.
  • OCSP stapling: TLS certificate validity is checked via OCSP (Online Certificate Status Protocol). Without stapling, the browser makes an OCSP request on every new TLS connection, adding 50-200ms. With stapling, the CDN edge includes the pre-fetched OCSP response in the TLS handshake — browser doesn't need to make its own OCSP request.
  • Certificate management: CDN integrates with Let's Encrypt (ACME protocol) for automatic certificate issuance and renewal. Custom certificates uploaded via API. Multi-domain (SAN) and wildcard certificates shared across customer zones.
  • Certificate revocation: if a private key is compromised, the CDN must rotate the certificate across all 200+ PoPs within minutes. This is done by pushing new certificates via the control plane and having each PoP reload nginx/envoy config gracefully (zero connection interruption via nginx -s reload or Envoy xDS API).

DDoS Mitigation Architecture

CDNs absorb DDoS attacks in layers:

  • Layer 3/4 (network layer): anycast naturally distributes volumetric attack traffic across all PoPs globally. Cloudflare's 200 PoPs collectively have 100Tbps+ capacity — any attack below that is "absorbed." BGP blackholing can drop attack traffic at the routing level before it hits CDN infrastructure.
  • Layer 7 (application layer): rate limiting by IP, user agent, and ASN (autonomous system number). Suspicious traffic (high request rate, unusual user agent, known bad IPs) receives challenge pages (JavaScript challenge or CAPTCHA) rather than being served immediately.
  • IP reputation: shared threat intelligence across all CDN customers. An IP attacking Customer A is rate-limited for Customer B within minutes. Cloudflare's shared intelligence across 45M HTTP properties is a key competitive advantage.
  • Traffic fingerprinting: HTTP/2 and TLS fingerprinting to identify bots even when they fake headers. JA3 (TLS fingerprint), HTTP/2 stream settings, header order — all vary between legitimate browsers and bot frameworks.

Purge Propagation: How to Purge All 200 PoPs in <5s

Purge propagation is a distributed system challenge. When a customer purges a URL, the invalidation must reach every edge node that has that URL cached before the CDN serves it again.

// Purge architecture:
// 1. Customer calls POST /v1/zones/{zoneId}/purge (via control plane API)
// 2. Control plane writes PurgeJob to Kafka topic "purge-jobs"
// 3. Each PoP runs a consumer subscribed to "purge-jobs" topic
// 4. Each PoP consumer receives the purge message and:
//    a. For URL purge: delete cache entry for normalized URL hash
//    b. For surrogate key purge: look up all cache keys tagged with this key, delete them
//    c. For wildcard: iterate cache index and delete matching entries
// 5. PoP sends ack message to "purge-acks" topic with {purge_id, pop_id, completed_at}
// 6. Control plane tracks ack receipt, marks purge "complete" when all PoPs ack
// 7. If a PoP doesn't ack within 10s: retry or mark that PoP degraded

// Why Kafka works well here:
// - Durable: purge jobs survive PoP restarts (consumer re-reads from offset)
// - Ordered: purge then cache of new content won't race (purge before publish pattern)
// - Scalable: 200 consumer groups (one per PoP) all read from same topic

// Surrogate key lookup for bulk purge:
// Redis SMEMBERS "stag:{zone}:{surrogate_key}" → Set of cache keys to delete
// This lookup is O(tag_cardinality) — potentially expensive for large tag sets
// Optimization: batch delete in chunks of 1000, background job, not synchronous
⚠️ Dangerous cache key pitfall — Vary: Cookie: If your origin accidentally returns Vary: Cookie (often done by frameworks when any code reads a cookie), the CDN creates a separate cache entry for every unique set of cookies. Session cookies are unique per user, so every request is a cache miss and the CDN becomes a pure proxy. This is the #1 CDN misconfiguration in production. Fix: configure the CDN to strip Cookie from the Vary header for static assets, or use CDN-Cache-Control: no-store for dynamic content and only cache static paths.

Push vs Pull CDN Model

  • Pull CDN (most common): edge fetches content from origin on first request (cache miss). Edge is a read-through cache. No pre-warming needed. Works for unpredictably popular content. Cloudflare, Akamai, CloudFront are all pull-based.
  • Push CDN: origin explicitly pushes content to edge nodes before the first request. Required for content that must be available instantly (live video streams, real-time sports scores). Higher operational complexity (origin must know CDN topology). CDNs like BunnyCDN support push via API.
  • Hybrid: push high-value predictable content (latest software release, video on premiere day), pull everything else.

Data Plane / Control Plane Separation

This is a critical design principle: the data plane (edge nodes serving cached content) must operate completely independently of the control plane (configuration management, analytics, purge API). If the control plane goes down:

  • Edge nodes continue serving cached content from their local cache
  • Cache misses forward to origin using last-known configuration
  • Purge operations queue up and replay when control plane recovers
  • Config updates are delayed but cached at edge

This is why each PoP pulls zone config on startup and caches it locally with a long TTL (5-minute refresh). The edge never makes synchronous calls to the control plane in the request path.

🚀D — Deliver2 min

Summary for the interview:

A CDN is a globally distributed cache with anycast routing. Users connect to the nearest PoP via BGP anycast. The L1 edge node serves cache hits in <10ms; misses go to the L2 origin shield which collapses thousands of concurrent misses into a single origin request. Cache key = normalized URL + selected Vary headers (never Cookie for public content). TTL strategy: versioned static assets (1 year + immutable), HTML (5 min), API responses (60s), user data (no-store). Purge propagates via Kafka fan-out to all 200+ PoPs within 5 seconds. DDoS is absorbed by anycast distributing attack traffic across global capacity plus rate limiting at L7.

Phased delivery:

  • Phase 1: Single region, pull CDN with L1 cache, basic TTL rules, URL purge.
  • Phase 2: Multi-region, anycast routing, origin shield (L2), surrogate key purge, TLS at edge.
  • Phase 3: DDoS mitigation, image optimization, analytics, WAF, real-time streaming support.

☕Java Implementation

/**
 * CacheKeyBuilder — produces a normalized, deterministic cache key for each request.
 *
 * Design choices:
 * - Sort query params to treat ?a=1&b=2 and ?b=2&a=1 as the same cache entry.
 * - Include Vary header values (from origin response) to separate cache entries
 *   when origin returns different content for different Accept-Encoding values.
 * - Never include Cookie or Authorization in cache key for public content.
 */
public class CacheKeyBuilder {

    private final Set<String> trackingParamsToStrip;

    public CacheKeyBuilder(Set<String> trackingParamsToStrip) {
        this.trackingParamsToStrip = Set.copyOf(trackingParamsToStrip);
    }

    /**
     * Builds the cache key for a request.
     *
     * @param method       HTTP method (only GET/HEAD should be cached)
     * @param rawUrl       Full URL including query string
     * @param varyHeaders  Map of header-name to header-value for headers listed in Vary
     * @return SHA-256 hex string suitable as a cache key
     */
    public String build(String method, String rawUrl, Map<String, String> varyHeaders) {
        String normalizedUrl = normalizeUrl(rawUrl);
        String varyString = buildVaryString(varyHeaders);

        String keyInput = method.toUpperCase() + "|" + normalizedUrl + "|" + varyString;

        try {
            MessageDigest digest = MessageDigest.getInstance("SHA-256");
            byte[] hashBytes = digest.digest(keyInput.getBytes(StandardCharsets.UTF_8));
            return HexFormat.of().formatHex(hashBytes);
        } catch (NoSuchAlgorithmException impossible) {
            throw new RuntimeException("SHA-256 not available", impossible);
        }
    }

    private String normalizeUrl(String rawUrl) {
        try {
            URI uri = new URI(rawUrl);

            String scheme = uri.getScheme().toLowerCase();
            String host = uri.getHost().toLowerCase();
            int port = uri.getPort();
            String normalizedHost = isDefaultPort(scheme, port)
                ? host
                : host + ":" + port;

            String path = uri.getPath().isEmpty() ? "/" : uri.getPath();
            String normalizedQuery = normalizeQueryString(uri.getQuery());

            return scheme + "://" + normalizedHost + path +
                   (normalizedQuery.isEmpty() ? "" : "?" + normalizedQuery);
        } catch (URISyntaxException parseError) {
            // Fall back to raw URL if parsing fails
            return rawUrl.toLowerCase();
        }
    }

    private String normalizeQueryString(String rawQuery) {
        if (rawQuery == null || rawQuery.isEmpty()) return "";

        // Parse, filter tracking params, sort, reassemble
        return Arrays.stream(rawQuery.split("&"))
            .map(param -> param.split("=", 2))
            .filter(parts -> parts.length == 2)
            .filter(parts -> !trackingParamsToStrip.contains(parts[0].toLowerCase()))
            .sorted(Comparator.comparing(parts -> parts[0]))
            .map(parts -> parts[0] + "=" + parts[1])
            .collect(Collectors.joining("&"));
    }

    private String buildVaryString(Map<String, String> varyHeaders) {
        // Sort by header name for deterministic ordering
        return varyHeaders.entrySet().stream()
            .sorted(Map.Entry.comparingByKey())
            .map(entry -> entry.getKey().toLowerCase() + "=" + entry.getValue())
            .collect(Collectors.joining(";"));
    }

    private boolean isDefaultPort(String scheme, int port) {
        return port == -1
            || (scheme.equals("http") && port == 80)
            || (scheme.equals("https") && port == 443);
    }
}

// ─────────────────────────────────────────────────────────────────────────────
// CacheTtlPolicy — determines the appropriate TTL for a cached response
// based on response headers and content type.
// ─────────────────────────────────────────────────────────────────────────────
public class CacheTtlPolicy {

    private static final int TTL_STATIC_VERSIONED_S = 365 * 24 * 3600;  // 1 year
    private static final int TTL_STATIC_UNVERSIONED_S = 3600;            // 1 hour
    private static final int TTL_HTML_S = 300;                           // 5 minutes
    private static final int TTL_API_RESPONSE_S = 60;                    // 1 minute
    private static final int TTL_NO_CACHE = 0;                           // bypass

    private final Map<String, CacheRuleConfig> pathRules;

    public CacheTtlPolicy(Map<String, CacheRuleConfig> pathRules) {
        this.pathRules = pathRules;
    }

    /**
     * Determines TTL for caching a response.
     * Priority: CDN-specific override > Surrogate-Control > Cache-Control > Content-type heuristic.
     *
     * @return ttl in seconds. 0 = do not cache.
     */
    public int determineTtl(String requestPath, Map<String, String> responseHeaders, int statusCode) {
        // 5xx errors: never cache
        if (statusCode >= 500) return TTL_NO_CACHE;

        // CDN-Cache-Control header takes highest priority (allows different CDN vs browser TTL)
        String cdnCacheControl = responseHeaders.get("CDN-Cache-Control");
        if (cdnCacheControl != null) {
            if (cdnCacheControl.contains("no-store")) return TTL_NO_CACHE;
            int maxAge = extractMaxAge(cdnCacheControl);
            if (maxAge >= 0) return maxAge;
        }

        // Surrogate-Control (Fastly / Varnish convention)
        String surrogateControl = responseHeaders.get("Surrogate-Control");
        if (surrogateControl != null) {
            int maxAge = extractMaxAge(surrogateControl);
            if (maxAge >= 0) return maxAge;
        }

        // Standard Cache-Control header
        String cacheControl = responseHeaders.get("Cache-Control");
        if (cacheControl != null) {
            if (cacheControl.contains("no-store") || cacheControl.contains("private")) return TTL_NO_CACHE;
            int maxAge = extractMaxAge(cacheControl);
            if (maxAge >= 0) return maxAge;
        }

        // Heuristic TTL based on content type and path
        return heuristicTtl(requestPath, responseHeaders.get("Content-Type"));
    }

    private int heuristicTtl(String path, String contentType) {
        // Versioned assets (hash in filename): cache for 1 year
        if (path.matches(".*\\.[a-f0-9]{8,}\\.(js|css|png|jpg|woff2?).*")) {
            return TTL_STATIC_VERSIONED_S;
        }

        if (contentType == null) return TTL_HTML_S;

        if (contentType.startsWith("application/json")) return TTL_API_RESPONSE_S;
        if (contentType.startsWith("text/html")) return TTL_HTML_S;
        if (contentType.startsWith("image/") || contentType.startsWith("font/")) return TTL_STATIC_UNVERSIONED_S;
        if (contentType.startsWith("text/javascript") || contentType.contains("css")) return TTL_STATIC_UNVERSIONED_S;
        if (contentType.startsWith("video/") || contentType.startsWith("audio/")) return TTL_STATIC_VERSIONED_S;

        return TTL_HTML_S;  // Conservative default
    }

    private int extractMaxAge(String cacheControlValue) {
        // Parse "max-age=3600" from Cache-Control header value
        java.util.regex.Matcher matcher = java.util.regex.Pattern
            .compile("max-age=(\\d+)")
            .matcher(cacheControlValue);
        if (matcher.find()) return Integer.parseInt(matcher.group(1));
        return -1;  // Not found
    }
}

// ─────────────────────────────────────────────────────────────────────────────
// OriginShieldRouter — routes cache misses to the appropriate L2 origin shield node.
// Uses consistent hashing to ensure the same URL always hits the same shield node.
// ─────────────────────────────────────────────────────────────────────────────
public class OriginShieldRouter {

    private final List<String> shieldNodes;    // e.g., ["shield-iad.cdn.internal", "shield-fra.cdn.internal"]
    private final ConsistentHashRing hashRing;  // Virtual nodes for even distribution

    public OriginShieldRouter(List<String> shieldNodes) {
        this.shieldNodes = List.copyOf(shieldNodes);
        this.hashRing = new ConsistentHashRing(shieldNodes, 150);  // 150 virtual nodes per real node
    }

    /**
     * Returns the shield node that should handle a cache miss for the given cache key.
     *
     * Consistent hashing ensures: same cache key → same shield node.
     * This prevents thundering herd: 100 L1 edge nodes all missing the same URL
     * → all route to the same L2 shield node → shield collapses them into 1 origin request.
     */
    public String routeMissToShield(String cacheKey) {
        return hashRing.getNode(cacheKey);
    }

    private static class ConsistentHashRing {
        private final TreeMap<Integer, String> ring = new TreeMap<>();

        ConsistentHashRing(List<String> nodes, int virtualNodesPerNode) {
            for (String node : nodes) {
                for (int virtualNode = 0; virtualNode < virtualNodesPerNode; virtualNode++) {
                    int hash = hash(node + ":" + virtualNode);
                    ring.put(hash, node);
                }
            }
        }

        String getNode(String key) {
            if (ring.isEmpty()) throw new IllegalStateException("No shield nodes available");
            int keyHash = hash(key);
            // Find the first node with hash >= keyHash (clockwise on the ring)
            Map.Entry<Integer, String> entry = ring.ceilingEntry(keyHash);
            if (entry == null) entry = ring.firstEntry();  // Wrap around
            return entry.getValue();
        }

        private int hash(String input) {
            try {
                MessageDigest digest = MessageDigest.getInstance("MD5");
                byte[] bytes = digest.digest(input.getBytes(StandardCharsets.UTF_8));
                return ((bytes[0] & 0xFF) << 24) | ((bytes[1] & 0xFF) << 16)
                     | ((bytes[2] & 0xFF) << 8)  | (bytes[3] & 0xFF);
            } catch (NoSuchAlgorithmException impossible) {
                return input.hashCode();
            }
        }
    }
}

☕Extended Java: Edge Cache Manager

/**
 * EdgeCacheManager — manages a local LRU cache at a CDN edge node.
 * Handles cache lookup, storage, eviction, and TTL-based expiry.
 *
 * Two-tier: hot objects in ConcurrentHashMap (RAM), overflow on SSD (omitted for brevity).
 * LRU eviction using LinkedHashMap access-order mode wrapped in synchronization.
 */
public class EdgeCacheManager {

    private static final int MAX_ENTRIES = 200_000;  // ~100GB at 500KB avg

    // Access-ordered LinkedHashMap: LRU eviction when size exceeds MAX_ENTRIES
    private final Map<String, CachedObject> cacheStore;
    private final CacheTtlPolicy ttlPolicy;
    private final CacheKeyBuilder cacheKeyBuilder;

    // Metrics
    private final AtomicLong hitCount = new AtomicLong(0);
    private final AtomicLong missCount = new AtomicLong(0);
    private final AtomicLong evictionCount = new AtomicLong(0);

    public EdgeCacheManager(CacheTtlPolicy ttlPolicy, CacheKeyBuilder cacheKeyBuilder) {
        this.ttlPolicy = ttlPolicy;
        this.cacheKeyBuilder = cacheKeyBuilder;
        // LinkedHashMap with access order: eldest entry evicted when over capacity
        this.cacheStore = Collections.synchronizedMap(
            new LinkedHashMap<String, CachedObject>(MAX_ENTRIES, 0.75f, true) {
                @Override
                protected boolean removeEldestEntry(Map.Entry<String, CachedObject> eldest) {
                    if (size() > MAX_ENTRIES) {
                        evictionCount.incrementAndGet();
                        return true;
                    }
                    return false;
                }
            }
        );
    }

    /**
     * Attempts to serve the request from cache.
     * Returns CacheHitResult if hit, null if miss.
     *
     * @param method        HTTP method
     * @param url           Full request URL
     * @param requestHeaders request headers (for Vary header matching)
     * @return CachedObject if cache hit, null if miss or expired
     */
    public CachedObject get(String method, String url, Map<String, String> requestHeaders) {
        if (!isCacheable(method)) return null;

        // We don't know Vary headers until we have a cached response to check
        // First lookup without Vary, then verify Vary headers match
        String baseKey = cacheKeyBuilder.build(method, url, Map.of());
        CachedObject cached = cacheStore.get(baseKey);

        if (cached == null) {
            // Try with common Vary header combinations
            String varyKey = buildVaryAwareKey(method, url, requestHeaders, cached);
            cached = cacheStore.get(varyKey);
        }

        if (cached == null) {
            missCount.incrementAndGet();
            return null;
        }

        // Check TTL expiry
        if (System.currentTimeMillis() / 1000L > cached.expiresAtEpoch()) {
            cacheStore.remove(baseKey);  // Evict expired entry
            missCount.incrementAndGet();
            return null;  // Return MISS so edge fetches fresh copy from shield/origin
        }

        hitCount.incrementAndGet();
        return cached;
    }

    /**
     * Stores a response in cache.
     * Determines TTL from response headers and content type.
     *
     * @param method          HTTP method
     * @param url             Request URL
     * @param responseStatus  HTTP response status code
     * @param responseHeaders Response headers from origin/shield
     * @param responseBody    Response body bytes
     * @param varyValues      Values of headers listed in Vary response header
     */
    public void put(String method, String url, int responseStatus,
                    Map<String, String> responseHeaders, byte[] responseBody,
                    Map<String, String> varyValues) {
        if (!isCacheable(method) || !isCacheableStatus(responseStatus)) return;

        int ttlSeconds = ttlPolicy.determineTtl(extractPath(url), responseHeaders, responseStatus);
        if (ttlSeconds == 0) return;  // Cache policy says do not cache

        String cacheKey = cacheKeyBuilder.build(method, url, varyValues);
        long now = System.currentTimeMillis() / 1000L;

        CachedObject cachedObject = new CachedObject(
            cacheKey,
            responseStatus,
            Map.copyOf(responseHeaders),
            responseBody,
            responseBody.length,
            now,
            now + ttlSeconds,
            responseHeaders.getOrDefault("ETag", null),
            responseHeaders.getOrDefault("Last-Modified", null),
            extractSurrogateKeys(responseHeaders)
        );

        cacheStore.put(cacheKey, cachedObject);
    }

    /**
     * Purges a specific cache entry by URL.
     * Called when CDN receives a purge instruction from control plane.
     */
    public boolean purgeByUrl(String method, String url) {
        String baseKey = cacheKeyBuilder.build(method, url, Map.of());
        boolean removed = cacheStore.remove(baseKey) != null;
        // Also try to remove any Vary-keyed variants (simplified: remove by prefix scan)
        cacheStore.entrySet().removeIf(entry -> entry.getValue().cacheKey().startsWith(baseKey));
        return removed;
    }

    /**
     * Purges all entries tagged with a given surrogate key.
     * More expensive O(N) scan — background operation only.
     */
    public int purgeBySurrogateKey(String surrogateKey) {
        int removedCount = 0;
        Iterator<Map.Entry<String, CachedObject>> iterator = cacheStore.entrySet().iterator();
        while (iterator.hasNext()) {
            CachedObject entry = iterator.next().getValue();
            if (entry.surrogateKeys().contains(surrogateKey)) {
                iterator.remove();
                removedCount++;
            }
        }
        return removedCount;
    }

    private boolean isCacheable(String method) {
        return "GET".equalsIgnoreCase(method) || "HEAD".equalsIgnoreCase(method);
    }

    private boolean isCacheableStatus(int status) {
        return status == 200 || status == 301 || status == 302
            || status == 304 || status == 404 || status == 410;
    }

    private String extractPath(String url) {
        int queryIndex = url.indexOf('?');
        String withoutQuery = queryIndex >= 0 ? url.substring(0, queryIndex) : url;
        int pathIndex = withoutQuery.indexOf('/', 8);  // skip "https://"
        return pathIndex >= 0 ? withoutQuery.substring(pathIndex) : "/";
    }

    private List<String> extractSurrogateKeys(Map<String, String> responseHeaders) {
        String surrogateKeyHeader = responseHeaders.get("Surrogate-Key");
        if (surrogateKeyHeader == null) return List.of();
        return Arrays.asList(surrogateKeyHeader.split("\\s+"));
    }

    private String buildVaryAwareKey(String method, String url,
                                      Map<String, String> requestHeaders,
                                      CachedObject existingEntry) {
        // If we have an existing entry, use its Vary headers to build the right key
        // Otherwise, try common Vary headers (Accept-Encoding first)
        Map<String, String> varyValues = new LinkedHashMap<>();
        String acceptEncoding = requestHeaders.get("Accept-Encoding");
        if (acceptEncoding != null) varyValues.put("Accept-Encoding", acceptEncoding);
        return cacheKeyBuilder.build(method, url, varyValues);
    }

    public double hitRate() {
        long total = hitCount.get() + missCount.get();
        return total == 0 ? 0.0 : (double) hitCount.get() / total;
    }

    public record CachedObject(
        String cacheKey,
        int status,
        Map<String, String> headers,
        byte[] body,
        long contentLength,
        long cachedAtEpoch,
        long expiresAtEpoch,
        String etag,
        String lastModified,
        List<String> surrogateKeys
    ) {}
}

📚Advanced CDN Patterns

Edge-Side Includes (ESI) and Edge Compute

Modern CDNs like Cloudflare Workers and AWS Lambda@Edge allow executing code at the edge PoP — inside the CDN, before the response reaches the user. This enables patterns beyond simple caching:

  • A/B testing at the edge: edge function reads experiment assignment cookie, rewrites the URL to the appropriate variant backend without a round-trip to origin. Zero latency overhead for experiment routing.
  • Personalization at the edge: edge function injects user's country or language segment into the cache key, serving country-specific content (currency, language, promotions) from the correct cached variant.
  • Authentication offload: edge function validates JWT or session cookie. Unauthorized requests are rejected at the PoP — origin never receives unauthenticated traffic. Same pattern as API gateway auth but at the CDN layer for static+dynamic hybrid apps.
  • Request coalescing: multiple concurrent requests for the same uncached URL are "coalesced" — the first request fetches from origin, subsequent ones wait and receive the same response. This is the edge node implementing the same thundering herd protection that origin shield provides at the regional level, but now at the individual PoP level.

Video Delivery: HLS/DASH Streaming Architecture

Video is the highest-traffic use case for CDNs (Netflix, YouTube together generate ~25% of all internet traffic). The adaptive bitrate streaming architecture (HLS/DASH) is designed to work exceptionally well with CDNs:

// HLS (HTTP Live Streaming) URL structure:
//
// Master playlist (changes rarely — list of quality variants):
// https://cdn.netflix.com/video_123/master.m3u8
// TTL: 60 seconds (can change as new quality levels are added)
//
// Variant playlist (changes during live, static for VOD):
// https://cdn.netflix.com/video_123/1080p/playlist.m3u8
// TTL: VOD: 1 year (immutable). Live: 2-5 seconds (constantly updated).
//
// Video segments (immutable, content-addressed):
// https://cdn.netflix.com/video_123/1080p/seg_001.ts
// https://cdn.netflix.com/video_123/1080p/seg_002.ts
// TTL: Forever (1 year + immutable). Segment content never changes.
//
// CDN cache behavior:
// 1. Player requests master.m3u8 → likely cached (60s TTL)
// 2. Player requests 1080p/playlist.m3u8 → cached for TTL, then refresh
// 3. Player requests seg_001.ts → cache HIT on first playback by any user in this PoP
//    All subsequent viewers at this PoP serve from cache — origin offload: 99%+
//
// The key insight: video segments are perfect for CDN caching because:
// a. They are large (2-10MB each) → fewer cache entries needed
// b. They are immutable (content hash in filename)
// c. Multiple users watch the same content → excellent cache hit rate
// d. Sequential access pattern is predictable → CDN can prefetch next segments

CDN Security: WAF (Web Application Firewall) Integration

Beyond DDoS mitigation, CDNs integrate WAF rules that inspect Layer 7 (HTTP) traffic:

  • OWASP Top 10 protection: SQL injection, XSS, CSRF, path traversal patterns detected in URL and POST body before reaching origin. Cloudflare and AWS WAF maintain rule sets updated against new attack patterns.
  • Bot management: distinguish legitimate bots (Googlebot, Bingbot) from malicious scrapers using TLS fingerprinting (JA3), HTTP/2 fingerprinting (GREASE, header order), and behavioral analysis (too-regular request intervals, no-JS execution).
  • Rate limiting at WAF: challenge or block IPs exceeding request rate thresholds. Challenge (CAPTCHA) rather than block when origin could be legitimate (shared NAT with many users behind same IP).
  • Credential stuffing detection: login endpoint: detect automated credential testing (many failed logins from distributed IPs, common password dictionaries). Rate limit + CAPTCHA at CDN edge before requests hit your auth service.

Cache Warming Strategy for Major Events

When a major event drives sudden traffic spikes (product launch, sports final, news event), cold CDN caches result in a thundering herd hitting origin simultaneously. Proactive cache warming:

  • Pre-populate before event: send synthetic requests to all PoPs 30-60 minutes before the expected traffic spike. The CDN fetches from origin, populates the cache. Event traffic hits warm cache.
  • Staggered warm-up: warm PoPs closest to expected traffic first. US event: warm US PoPs first, then global PoPs as traffic spreads.
  • Reduced TTL before purge: for content that changes at event start (product page revealing new price), set TTL to 30 seconds in the 5 minutes before launch. After launch, purge stale content and set normal TTL. This bounds the "flash of wrong content" window.
