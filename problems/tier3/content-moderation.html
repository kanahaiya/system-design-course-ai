Tier 3 — Expert 60 minML Systems

Design Content Moderation System

Content moderation at scale (500M posts/day) cannot be human-only — ML classifiers make the first decision. But ML has errors. A three-stage pipeline: automated ML → high-confidence auto-action or human review queue → human decision + feedback loop.

🏢 Meta, YouTube, Twitter
⏱️ 60 min interview
🛡️ Trust & Safety

❓R — Requirements3–5 min

Functional Requirements

  • Automatically detect and remove policy-violating content (hate speech, violence, CSAM, spam)
  • Route ambiguous content to human reviewers
  • Users can appeal moderation decisions
  • Support text, images, and video content types
  • Hash-based exact matching for known harmful content (PhotoDNA for CSAM)

Non-Functional Requirements

  • Scale: 500M posts/day across modalities
  • Precision vs recall: Configurable per violation category (CSAM: 100% recall, some false positives OK; hate speech: higher precision, lower recall)
  • Latency: ML scoring: <500ms; human review queue: SLA varies by severity (CSAM: <1hr; hate speech: <24hr)

🔢E — Estimation3–5 min

  • 500M posts/day = 5,800/sec → ML classifier must handle 10K/sec (with spike headroom)
  • ML accuracy 95% → 25M posts/day flagged for human review out of 500M
  • Humans review ~300 items/day → need ~83K human reviewers at full load (batched + prioritized)
  • Hash matching: image fingerprints ~100 bytes × 1B known hashes = 100GB hash index → fits in Redis or in-memory

🏗️H — High-level Design10 min

  • Ingestion: Content upload → Kafka → Moderation Pipeline fan-out (text classifier, image classifier, hash matcher in parallel).
  • Hash Matcher: Compute perceptual hash (pHash for images, SimHash for text). Look up in known-harmful hash index (Redis). Exact match → auto-remove immediately, no ML needed.
  • ML Classifiers: Text: fine-tuned BERT/RoBERTa. Image: CNN (ResNet/EfficientNet). Video: frame sampling + image classifier. Returns confidence score 0–1.
  • Decision Logic: Score > 0.95 → auto-remove. Score 0.6–0.95 → human review queue. Score < 0.6 → approve.
  • Human Review Queue: Redis priority queue. Reviewers pull from queue by priority. Decisions feed back into ML training data.
  • Feedback Loop: Human reviewer decisions (especially overturns of auto-actions) are sampled for model retraining weekly.
  • Appeals: User appeals → re-routes to senior reviewer. Overturn → restore content + adjust threshold for that user's account.

🔬D — Deep Dive: Multi-Stage Pipeline + Threshold Tuning10 min

Stage 1 — Hash matching (deterministic, <1ms): PhotoDNA (perceptual hashing for images). SimHash for near-duplicate text spam. Any exact/near match to known-harmful content = auto-remove. No ML latency, no errors on known content.

Stage 2 — ML scoring (probabilistic, 50–500ms):

  • ML score represents confidence: 0.99 = very likely violation. 0.51 = borderline.
  • Threshold tuning: different thresholds per category. CSAM: auto-remove at 0.80 (high recall, some false positives accepted). Hate speech: auto-remove at 0.95 (high precision, avoid censoring legitimate speech).

Stage 3 — Human review: Ambiguous items (0.60–threshold). Humans provide ground truth. Senior reviewers handle appeals.

Feedback loop quality: Track reviewer agreement rate. If two reviewers consistently disagree on a category → the category's ML training data has label noise → flag for policy clarification.

✅E — Evaluate3 min

  • Adversarial evasion: Bad actors modify text/images slightly to evade classifiers. Mitigation: adversarial training (include perturbed examples in training), ensemble models, hash-based detection for known variants.
  • False positive impact: Removing legitimate content harms free expression. Track false positive rate; alert when it spikes. For high-stakes categories (political speech), require human review instead of auto-remove.

🚀D — Deliver2 min

We designed a content moderation system handling 500M posts/day. Key decisions: hash matching for known content (zero ML latency), ML classifiers with configurable thresholds per category, Redis priority queue for human reviewers, and weekly feedback loops to improve model accuracy.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
ML action thresholdConfigurable per categorySingle global thresholdDifferent categories have different risk profiles. CSAM: maximize recall. Hate speech: balance precision/recall. A single threshold compromises both.
Review queue prioritizationPriority by severity (CSAM=100, spam=10)FIFO queueCSAM must be reviewed within 1hr (legal requirement). Spam can wait 24hr. Priority ensures SLAs are met even under queue backlog.
Hash matchingPerceptual hash (pHash)Cryptographic hash (SHA)SHA only matches identical bytes — one pixel change evades it. pHash is tolerant of compression/resizing artifacts. Near-duplicate detection required for re-uploaded known content.

☕Java Implementation

/**
 * ModerationPipeline — orchestrates hash matching, ML scoring, and routing decisions.
 * Processes one content item through all stages and returns the moderation action.
 */
public class ModerationPipeline {

    private static final float AUTO_REMOVE_THRESHOLD = 0.95f;
    private static final float HUMAN_REVIEW_THRESHOLD = 0.60f;

    private final HashMatcher hashMatcher;
    private final MlClassifier mlClassifier;
    private final ReviewQueuePublisher reviewQueuePublisher;
    private final ModerationDecisionStore decisionStore;

    public ModerationPipeline(HashMatcher hashMatcher, MlClassifier mlClassifier,
                               ReviewQueuePublisher reviewQueuePublisher,
                               ModerationDecisionStore decisionStore) {
        this.hashMatcher = hashMatcher;
        this.mlClassifier = mlClassifier;
        this.reviewQueuePublisher = reviewQueuePublisher;
        this.decisionStore = decisionStore;
    }

    /**
     * Runs content through all moderation stages and persists the decision.
     *
     * @param contentItem  content metadata and URL
     * @return ModerationAction indicating what happened to the content
     */
    public ModerationAction moderate(ContentItem contentItem) {
        // Stage 1: Hash matching — fast, deterministic, handles known-bad content
        if (hashMatcher.isKnownHarmful(contentItem)) {
            ModerationDecision decision = ModerationDecision.autoRemove(
                contentItem.getContentId(), "hash_match", 1.0f
            );
            decisionStore.persist(decision);
            return ModerationAction.REMOVE;
        }

        // Stage 2: ML classification
        ClassificationResult mlResult = mlClassifier.classify(contentItem);

        if (mlResult.getScore() >= AUTO_REMOVE_THRESHOLD) {
            // High-confidence violation — auto-remove
            ModerationDecision decision = ModerationDecision.autoRemove(
                contentItem.getContentId(), mlResult.getLabel(), mlResult.getScore()
            );
            decisionStore.persist(decision);
            return ModerationAction.REMOVE;
        }

        if (mlResult.getScore() >= HUMAN_REVIEW_THRESHOLD) {
            // Ambiguous — route to human reviewers with priority based on category
            int reviewPriority = calculateReviewPriority(mlResult.getLabel(), mlResult.getScore());
            reviewQueuePublisher.enqueue(contentItem.getContentId(), mlResult.getLabel(), reviewPriority);
            ModerationDecision decision = ModerationDecision.pendingReview(
                contentItem.getContentId(), mlResult.getLabel(), mlResult.getScore()
            );
            decisionStore.persist(decision);
            return ModerationAction.PENDING_REVIEW; // content stays up until reviewed
        }

        // Low confidence — approve
        ModerationDecision decision = ModerationDecision.approved(
            contentItem.getContentId(), mlResult.getScore()
        );
        decisionStore.persist(decision);
        return ModerationAction.APPROVE;
    }

    /**
     * Higher priority items reviewed first.
     * CSAM (child safety) always gets maximum priority regardless of score.
     */
    private int calculateReviewPriority(String violationLabel, float score) {
        int basePriority = switch (violationLabel) {
            case "csam"        -> 100;
            case "violence"    -> 80;
            case "hate_speech" -> 60;
            case "spam"        -> 20;
            default            -> 40;
        };
        // Higher ML score within a category = slightly higher priority
        return (int) (basePriority + score * 10);
    }
}
