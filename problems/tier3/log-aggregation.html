Design Distributed Log Aggregation (ELK Stack)

Log aggregation has a paradox: the time you most need logs (during an outage) is when the system is most stressed. The solution: decouple log generation from processing via Kafka, and use lightweight local agents that will not block application threads.

🏢 Elasticsearch, Splunk, Datadog Logs
⏱️ 60 min interview

❓R — Requirements3–5 min

Functional Requirements

  • Collect logs from distributed services (structured JSON logs preferred)
  • Full-text search: find all logs with a specific error message or trace ID
  • Tail logs in real-time for a specific service
  • Retention: searchable for 30 days, archived for 1 year
  • Alerting: notify on error rate spike or specific error patterns

Non-Functional Requirements

  • Scale: 1M log lines/sec from 10K services
  • Latency: Logs searchable within 30 seconds of generation
  • Durability: Never lose logs even during Elasticsearch downtime
  • Zero impact: Log shipping must not block application threads

🔢E — Estimation3–5 min

  • 1M logs/sec × avg 500 bytes = 500MB/sec = 43TB/day raw
  • Elasticsearch indexing overhead (~2x raw): 86TB/day → 2.6PB/month without tiering
  • With hot/warm/cold: SSD (7 days) → HDD (30 days) → S3 (1 year) → delete
  • Compressed S3 archive: 43TB/day × 0.1 (gzip) × 365 = 1.6PB/year

🗄️S — Schema3–5 min

// Log entries (Elasticsearch index per day)
// Index: logs-{service}-{YYYY-MM-DD}
log_entry:
    "@timestamp"  ISO8601 datetime
    level         enum: DEBUG INFO WARN ERROR FATAL
    service       string: "auth-service"
    trace_id      string: for correlation with distributed traces
    span_id       string
    message       text (full-text indexed)
    exception     text (stack trace)
    fields        object: {userId, requestId, ...}

// Hot storage: SSD-backed Elasticsearch (last 7 days, fast search)
// Warm storage: HDD-backed Elasticsearch (7-30 days, slower search)
// Cold storage: S3 Parquet (30-365 days, batch queries only)

🏗️H — High-level Design10 min

  • Log agents (Fluentd/Filebeat): Sidecar or DaemonSet in each pod. Tails log files (stdout/stderr). Parses and enriches (add service name, Kubernetes labels). Batches to Kafka. Async — never blocks application.
  • Kafka buffer: Absorbs log bursts during spikes. Decouples agent from Logstash. If Logstash is slow, Kafka queues the backlog without losing data. Retention: 7 days.
  • Logstash / Kafka consumer: Parses log format (regex/grok for unstructured, direct JSON for structured). Enriches (GeoIP, user lookup). Writes to Elasticsearch index.
  • Elasticsearch cluster: Hot nodes (SSD, last 7 days). Warm nodes (HDD, 7-30 days). Index Lifecycle Management (ILM) auto-migrates from hot to warm to cold.
  • Kibana: Query UI, saved searches, dashboards, alerting on log patterns.

// Alert rule management
POST /api/v1/alerts/rules  { condition: "error_rate > 10 per minute", notify: "pagerduty" }

🔬D — Deep Dive10 min

Why Kafka between agents and Elasticsearch?

  • Elasticsearch has variable throughput -- slow during shard rebalancing or GC pauses. Without Kafka, a slow Elasticsearch would back-pressure to agents, which would back-pressure to applications, blocking log writes and potentially impacting application performance.
  • Kafka provides durable buffering: if Elasticsearch is down for 4 hours, logs queue in Kafka. When Elasticsearch recovers, it replays from the Kafka offset.
  • Multiple consumers: Kafka enables consuming the same log stream for different purposes -- Elasticsearch for search, ClickHouse for metrics, S3 for archival.

Structured logging (JSON):

JSON logs: {"level":"ERROR","msg":"DB timeout","trace_id":"abc123","latency_ms":5001}

Benefits: no parsing needed in Logstash, fields are directly indexed, easy to search by structured fields. Switch from string-based log parsing to direct JSON ingestion reduces Logstash CPU by ~60%.

Log sampling for high-volume services: A high-throughput service might emit 1M DEBUG logs/sec. Sample DEBUG/INFO at 1%; always store WARN/ERROR/FATAL. Reduces storage 10-100x while preserving the actionable logs.

✅E — Evaluate3 min

  • Log loss risk: Agents buffer logs locally on disk before sending to Kafka (persistent queue). If the pod dies, the local buffer is lost. For critical logs: use application-level async logging to Kafka directly (no agent intermediary).
  • Elasticsearch mapping explosion: Dynamic field mapping: every new JSON field becomes a new Elasticsearch field. 10M distinct field names = mapping explosion leading to OOM. Mitigation: explicit index mapping, reject unknown fields, or use Elasticsearch dynamic mapping limits.

🚀D — Deliver2 min

Log aggregation = App to log agent to Kafka to Logstash to Elasticsearch to Kibana. Kafka is the critical buffer. Hot/warm/cold tiering reduces cost 10-50x. Structured JSON logs eliminate Logstash parsing overhead. Always sample DEBUG/INFO; never sample ERROR/FATAL.

⚖️Trade-offs

DecisionOption AOption B
Log formatStructured JSON: no parsing, direct field indexing, searchable fieldsUnstructured text: human-readable, requires grok parsing, slower
Kafka usageWith Kafka: durable buffer, survives ES downtimeDirect to ES: simpler, log loss during ES issues
SamplingSample DEBUG 1%, INFO 10%, always keep ERRORNo sampling: 100% capture, 100x storage cost
RetentionTiered (SSD/HDD/S3): 10-50x cost reductionAll on SSD: fast queries, very expensive

☕Java Implementation

/**
 * LogIngestionPipeline -- parses incoming log batches and publishes to Kafka asynchronously.
 * Never blocks the calling thread; failures are logged internally.
 */
public class LogIngestionPipeline {

    private static final String LOG_TOPIC = "app-logs";

    private final KafkaProducer<String, String> kafkaProducer;
    private final ObjectMapper objectMapper = new ObjectMapper();

    public LogIngestionPipeline(KafkaProducer<String, String> kafkaProducer) {
        this.kafkaProducer = kafkaProducer;
    }

    /**
     * Ingests a raw log line, parses it to structured JSON, and publishes to Kafka.
     * Runs on a virtual thread -- never blocks the application.
     */
    public void ingestLog(String rawLogLine, String serviceName) {
        Thread.ofVirtual().start(() -> {
            try {
                StructuredLogEntry entry = parseLogLine(rawLogLine, serviceName);
                if (shouldSample(entry.getLevel())) {
                    String serialized = objectMapper.writeValueAsString(entry);
                    kafkaProducer.send(
                        new ProducerRecord<>(LOG_TOPIC, serviceName, serialized),
                        (metadata, sendException) -> {
                            if (sendException != null) {
                                System.err.println("[LogIngestionPipeline] Kafka send failed: "
                                                   + sendException.getMessage());
                            }
                        }
                    );
                }
            } catch (Exception parseException) {
                System.err.println("[LogIngestionPipeline] Parse error: " + parseException.getMessage());
            }
        });
    }

    /**
     * Sampling policy: always store WARN/ERROR/FATAL; sample DEBUG/INFO.
     * Reduces storage 10-100x while preserving actionable logs.
     */
    private boolean shouldSample(String logLevel) {
        return switch (logLevel.toUpperCase()) {
            case "WARN", "ERROR", "FATAL" -> true;       // Always keep
            case "INFO"  -> Math.random() < 0.10;        // 10% of INFO
            case "DEBUG" -> Math.random() < 0.01;        // 1% of DEBUG
            default      -> true;
        };
    }

    private StructuredLogEntry parseLogLine(String rawLogLine, String serviceName) {
        try {
            StructuredLogEntry entry = objectMapper.readValue(rawLogLine, StructuredLogEntry.class);
            if (entry.getService() == null) { entry.setService(serviceName); }
            return entry;
        } catch (JsonProcessingException parseException) {
            // Fallback: unstructured log -- wrap in structured format
            return new StructuredLogEntry(
                Instant.now().toString(), "INFO", serviceName, rawLogLine, null, null
            );
        }
    }
}
