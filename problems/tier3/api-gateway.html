Design an API Gateway

An API gateway is a reverse proxy with a plugin/middleware pipeline: auth, rate limit, request transform, route, load balance, circuit break, response transform, cache. Each plugin is a single concern. Understanding this pipeline and when to put logic in the gateway vs the service is the interview signal.

🏢 Kong, AWS API Gateway, Nginx
⏱️ 60 min interview

❓R — Requirements3–5 min

Functional Requirements

  • Route requests to appropriate backend services based on path and method
  • Authentication and authorization (JWT validation, API key verification)
  • Rate limiting per client or API key
  • Request and response transformation (add headers, strip sensitive fields)
  • SSL termination, load balancing, circuit breaking
  • API composition: aggregate multiple service responses into one

Non-Functional Requirements

  • Scale: 1M requests/sec across all services
  • Latency overhead: <5ms added by gateway
  • Availability: 99.999% — gateway is in the hot path of every request

🔢E — Estimation3–5 min

  • 1M req/sec → multiple stateless gateway instances behind load balancer
  • Rate limiting state (sliding window counters): 10M API keys × 16 bytes = 160MB → Redis Cluster
  • Circuit breaker state: O(services) in-memory per gateway instance — trivial

🗄️S — Schema3–5 min

// Route registry (loaded at gateway startup, refreshed every 60s)
routes: path_pattern, method, backend_service_url, auth_required, rate_limit_tier

// Rate limit counters (Redis - sliding window)
// Key: rate:{api_key}:{window_minute}  TTL: 2 minutes
// INCR + EXPIRE on each request

// Circuit breaker state (in-memory per gateway instance)
circuit_states: service_id -> {state: CLOSED|OPEN|HALF_OPEN, failure_count, last_failure}

🏗️H — High-level Design10 min

  • Request pipeline (chain of responsibility): Auth → Rate Limit → Request Transform → Route Lookup → Load Balance → Circuit Breaker → Backend Call → Response Transform → Cache.
  • Auth: JWT validation (offline -- verify signature with public key, no DB call). API key validation (Redis lookup). OAuth 2.0 token introspection (external call -- cache results).
  • Rate limiting: Sliding window counter per (api_key, minute). Redis INCR + TTL. Reject with 429 if over limit.
  • Circuit breaker: Track failure rate per backend service. CLOSED → OPEN at 50% failure rate. OPEN → reject immediately with 503. HALF_OPEN → try one request, close if succeeds.
  • API composition: Fan out to multiple services in parallel, merge responses. Useful for BFF (Backend For Frontend) pattern.

🔬D — Deep Dive10 min

Chain of Responsibility pattern for middleware:

Each plugin implements: void handle(Request req, Response res, Runnable next). Calling next.run() passes control to the next plugin. Not calling next short-circuits (e.g., auth plugin rejects with 401).

This is the same pattern as Express.js middleware, Servlet filters in Java, and Django middleware.

Why put auth in the gateway vs each service?

  • Gateway: single enforcement point. Services receive pre-validated user context. Services trust the gateway (internal network -- accept X-User-Id header).
  • Each service: defense in depth. Services do not trust the gateway. Higher latency (each service validates independently).
  • Compromise: gateway validates JWT signature (fast, offline). Services check authorization (does this user have permission to this resource).

Circuit breaker states:

  • CLOSED: normal operation. Track failure rate.
  • OPEN: failure rate exceeded threshold. Reject all requests immediately. Start timer.
  • HALF-OPEN: timer expired. Allow one request through. If succeeds: CLOSED. If fails: back to OPEN.

✅E — Evaluate3 min

  • Gateway as SPOF: Multiple gateway instances behind a load balancer. Stateless design (rate limit state in Redis, circuit state local per instance). Horizontal scaling: add instances as traffic grows.
  • Gateway vs service mesh: Gateway handles north-south (client → service) traffic. Service mesh (Istio/Linkerd) handles east-west (service → service) traffic. Do not duplicate both -- use gateway for external, service mesh for internal.

🚀D — Deliver2 min

API gateway = chain-of-responsibility middleware pipeline (auth, rate limit, circuit break) + stateless instances + Redis for shared rate limit state. Key insight: JWT validation is offline (no network call), making auth latency negligible.

⚖️Trade-offs

DecisionGateway AuthPer-Service Auth
EnforcementSingle point: simpler, but gateway misconfiguration = security holeDefense in depth: each service validates independently
LatencyJWT: offline verify, <1ms. API key: one Redis read.Each service makes auth call: 1-5ms per service
Rate limitingGateway: aggregated across all services for a clientPer-service: each service limits independently (no global view)

☕Java Implementation

/**
 * ApiGatewayPipeline -- executes a pluggable middleware chain for each request.
 * Each plugin handles one concern (auth, rate limit, routing, circuit breaking).
 */
public class ApiGatewayPipeline {

    private final List<GatewayPlugin> plugins;

    public ApiGatewayPipeline(List<GatewayPlugin> plugins) {
        this.plugins = List.copyOf(plugins);
    }

    public GatewayResponse process(GatewayRequest request) {
        PluginChain chain = new PluginChain(plugins, 0);
        GatewayResponse response = new GatewayResponse();
        chain.handle(request, response);
        return response;
    }

    public interface GatewayPlugin {
        void handle(GatewayRequest request, GatewayResponse response, Runnable next);
    }

    private static class PluginChain {
        private final List<GatewayPlugin> plugins;
        private int index;

        PluginChain(List<GatewayPlugin> plugins, int index) { this.plugins = plugins; this.index = index; }

        void handle(GatewayRequest request, GatewayResponse response) {
            if (index >= plugins.size()) return;
            GatewayPlugin current = plugins.get(index++);
            PluginChain next = new PluginChain(plugins, index);
            current.handle(request, response, () -> next.handle(request, response));
        }
    }

    // JWT Auth plugin -- validates offline (no network call)
    public static class JwtAuthPlugin implements GatewayPlugin {
        private final JwtValidator jwtValidator;
        public JwtAuthPlugin(JwtValidator jwtValidator) { this.jwtValidator = jwtValidator; }

        @Override
        public void handle(GatewayRequest request, GatewayResponse response, Runnable next) {
            String authHeader = request.getHeader("Authorization");
            if (authHeader == null || !authHeader.startsWith("Bearer ")) {
                response.setStatus(401);
                response.setBody("{\"error\":\"Missing or invalid Authorization header\"}");
                return; // Short-circuit -- do NOT call next
            }
            JwtClaims claims = jwtValidator.validate(authHeader.substring(7));
            if (claims == null) {
                response.setStatus(401);
                response.setBody("{\"error\":\"Invalid or expired JWT\"}");
                return;
            }
            request.setAttribute("userId", claims.getSubject());
            next.run(); // Continue to next plugin
        }
    }

    // Rate limit plugin -- Redis sliding window counter
    public static class RateLimitPlugin implements GatewayPlugin {
        private final JedisPool jedisPool;
        private final int requestsPerMinute;

        public RateLimitPlugin(JedisPool jedisPool, int requestsPerMinute) {
            this.jedisPool = jedisPool;
            this.requestsPerMinute = requestsPerMinute;
        }

        @Override
        public void handle(GatewayRequest request, GatewayResponse response, Runnable next) {
            String apiKey = request.getHeader("X-Api-Key");
            if (apiKey == null) { next.run(); return; }
            long currentMinute = System.currentTimeMillis() / 60_000;
            String rateLimitKey = "rate:" + apiKey + ":" + currentMinute;
            try (Jedis jedis = jedisPool.getResource()) {
                long requestCount = jedis.incr(rateLimitKey);
                jedis.expire(rateLimitKey, 120);
                if (requestCount > requestsPerMinute) {
                    response.setStatus(429);
                    response.setBody("{\"error\":\"Rate limit exceeded\"}");
                    return;
                }
            }
            next.run();
        }
    }
}
