Tier 1 — Must Know 45 min Trie + Pipeline

Design Search Autocomplete / Typeahead

Every keystroke fires a request. The interview is about two things: the trie data structure with pre-computed top-K at each node, and the background aggregation pipeline that keeps suggestion popularity fresh.

🏢 Google, Amazon, Meta
⏱️ 45 min interview
⌨️ 5,800 QPS

❓ R — Requirements 3–5 min

Functional Requirements

  • As the user types each character, return top 5 matching suggestions
  • Suggestions sorted by search frequency (most searched first)
  • Support prefix matching (type "app" → "apple", "application", "app store")

Non-Functional Requirements

  • Latency: < 100ms response per keystroke (including network round-trip)
  • Scale: 10M DAU × 10 searches/day × ~5 keystrokes/search = 500M autocomplete requests/day ≈ 5,800 QPS
  • Freshness: Suggestions can be up to 1 hour stale (eventual consistency OK)
  • Availability: 99.9% — degrade gracefully (empty suggestions better than 500 error)
Key clarification to make: "Should suggestions reflect trends in near real-time (last hour), or can we rebuild daily?" This determines whether you need a streaming aggregation pipeline vs a nightly batch job.

🔢 E — Estimation 5 min

  • Autocomplete QPS: 10M × 10 × 5 / 86,400 ≈ 5,800 QPS
  • Unique queries: ~500M distinct search terms (long tail) → only top 1M are commonly searched
  • Trie size: 1M × avg 15 chars per query = 15M trie nodes × ~50 bytes each = ~750MB — fits in Redis
  • Top-K storage per node: 5 suggestions × 30 bytes = 150 bytes per prefix node → 15M × 150 = 2.25GB — borderline, needs partitioning
  • Client-side debounce: Users typically type 5 chars/sec. With 300ms debounce, effective QPS drops to ~1,200 — well within capacity

🏗️ H — High-level Design 10 min

Query Path (Real-time, per keystroke)

  1. User types "app" (after 300ms debounce)
  2. Client → Autocomplete Service → Redis lookup: GET autocomplete:app
  3. Return top 5 suggestions (pre-computed — O(1) Redis lookup)
  4. Total latency: ~5ms Redis + ~10ms network = well under 100ms

Update Path (Background, hourly)

  1. Every search query → logged to Kafka (topic: search-events)
  2. Aggregator Service (Flink/Spark Streaming) counts queries over rolling 1-hour window
  3. Updated counts written to Cassandra (search_counts table)
  4. Every hour, Trie Builder reads top queries from Cassandra → rebuilds trie → writes pre-computed top-5 per prefix to Redis
Why separate query and update paths? The query path is latency-critical and can serve stale data (1hr is fine). The update path is throughput-critical and can run slower (batch rebuild). Mixing them would slow down queries.

🔬 D — Deep Dive: Trie with Pre-computed Top-K 10 min

A naive trie lookup for "app" would traverse to the "app" node, then DFS all descendants to find the top 5 by frequency. For a trie with millions of nodes, this DFS is O(n) and too slow for 100ms SLA.

Optimization: Store Top-K at Each Node

During trie build, each node stores the top 5 results for that prefix — not just the strings below it. Building is O(n log K) (maintain a min-heap of size K while inserting). Querying is O(prefix_length) — just navigate to the prefix node and read the cached top-5.

Scale: Partition Trie by First Character

26 letter shards + digits + special chars = ~40 Redis shards. Each shard handles ~1/40 of the prefix space. Adding a shard adds capacity linearly — consistent hash ring for prefix routing by first character.

Trie Update Strategy

Instead of updating the live trie on every search (complex, hot path), maintain a secondary trie. Every hour, the Trie Builder writes the new trie to Redis with keys prefixed autocomplete_v2:. Atomically swap the active version. Zero-downtime update.

⚖️ E — Evaluate 5 min

  • Redis cache miss (prefix not in cache): Fall back to in-memory trie traversal on autocomplete service instances. Slower (20–50ms) but functional. Cache miss rate should be <1% after warm-up.
  • Trending queries (sudden spike): The 1-hour update cycle means a new trend takes up to 1 hour to appear in suggestions. Acceptable per requirements. For real-time trends, add a separate trending endpoint.
  • Cold start (Redis empty): Autocomplete service loads trie from Cassandra on startup. Falls back to in-memory serving until Redis is warm.
  • Special characters/Unicode: Normalize to lowercase ASCII before insertion and lookup. This covers the 95% case. Unicode support requires a more complex key encoding.

🚀 D — Deliver 2 min

"The query path is a single O(1) Redis lookup per prefix — we pre-compute top-5 suggestions at each trie node during an hourly background rebuild. The update path uses Kafka → Flink aggregation → Cassandra count store → Trie Builder → Redis. The trie is partitioned by first character across Redis shards. Client-side debounce (300ms) reduces QPS by 5×. Suggestions are eventually consistent — up to 1 hour stale, which meets requirements."

/**
 * TrieNode — represents one character in the prefix trie.
 * Each node caches the top-K suggestions for its prefix for O(1) lookup.
 */
public class TrieNode {
    private static final int TOP_K_SIZE = 5;

    private final Map childrenByChar = new HashMap<>();
    private boolean isCompleteWord = false;
    private long wordFrequency = 0;

    // Pre-computed top-K suggestions for this prefix, sorted by frequency descending
    private final List topKSuggestions = new ArrayList<>(TOP_K_SIZE);
    private final List topKFrequencies = new ArrayList<>(TOP_K_SIZE);

    public TrieNode getOrCreateChild(char character) {
        return childrenByChar.computeIfAbsent(character, key -> new TrieNode());
    }

    public TrieNode getChild(char character) {
        return childrenByChar.get(character);
    }

    public boolean hasChild(char character) {
        return childrenByChar.containsKey(character);
    }

    public void markAsCompleteWord(long frequency) {
        this.isCompleteWord = true;
        this.wordFrequency = frequency;
    }

    /**
     * Updates this node's top-K list with a candidate suggestion.
     * Called bottom-up during trie construction after all children are built.
     *
     * @param suggestion The query string
     * @param frequency  Its search frequency count
     */
    public void updateTopK(String suggestion, long frequency) {
        // Find insertion point (descending order by frequency)
        int insertPosition = topKSuggestions.size();
        for (int index = 0; index < topKSuggestions.size(); index++) {
            if (frequency > topKFrequencies.get(index)) {
                insertPosition = index;
                break;
            }
        }

        if (insertPosition >= TOP_K_SIZE) {
            return; // This suggestion doesn't make the top-K
        }

        topKSuggestions.add(insertPosition, suggestion);
        topKFrequencies.add(insertPosition, frequency);

        // Keep list at max TOP_K_SIZE
        if (topKSuggestions.size() > TOP_K_SIZE) {
            topKSuggestions.remove(TOP_K_SIZE);
            topKFrequencies.remove(TOP_K_SIZE);
        }
    }

    public List getTopKSuggestions() {
        return Collections.unmodifiableList(topKSuggestions);
    }

    public boolean isCompleteWord() { return isCompleteWord; }
    public long getWordFrequency() { return wordFrequency; }
}

/**
 * AutocompleteTrie — builds and queries a prefix trie with pre-computed top-K at each node.
 */
public class AutocompleteTrie {
    private final TrieNode rootNode = new TrieNode();

    /**
     * Builds the trie from a list of (query, frequency) pairs.
     * After insertion, calls buildTopK() to propagate top-K bottom-up.
     *
     * @param queryFrequencyPairs List of query strings with their search counts
     */
    public void buildFromFrequencies(List queryFrequencyPairs) {
        for (QueryFrequency queryFrequency : queryFrequencyPairs) {
            insertQuery(queryFrequency.getQuery().toLowerCase(), queryFrequency.getFrequency());
        }
        buildTopKBottomUp(rootNode);
    }

    private void insertQuery(String query, long frequency) {
        TrieNode currentNode = rootNode;
        for (char character : query.toCharArray()) {
            currentNode = currentNode.getOrCreateChild(character);
        }
        currentNode.markAsCompleteWord(frequency);
    }

    /**
     * Propagates top-K suggestions bottom-up after all words are inserted.
     * Each parent node merges its children's top-K lists into its own.
     * This is the key optimization: O(K log K) per node instead of O(subtree_size) at query time.
     *
     * @param node The node to process (recursive, DFS post-order)
     * @return The top-K suggestions collected from this subtree
     */
    private List buildTopKBottomUp(TrieNode node) {
        List subtreeSuggestions = new ArrayList<>();

        // Recurse into children first (post-order traversal)
        for (Map.Entry childEntry : getChildEntries(node)) {
            List childSuggestions = buildTopKBottomUp(childEntry.getValue());
            subtreeSuggestions.addAll(childSuggestions);
        }

        // Add this node's word if it's a complete word
        if (node.isCompleteWord()) {
            subtreeSuggestions.add(new QueryFrequency(
                    getCurrentPrefix(node), node.getWordFrequency()));
        }

        // Sort by frequency descending and keep top-K
        subtreeSuggestions.sort((a, b) -> Long.compare(b.getFrequency(), a.getFrequency()));
        List topK = subtreeSuggestions.stream()
                .limit(5)
                .collect(Collectors.toList());

        // Store in this node
        for (QueryFrequency suggestion : topK) {
            node.updateTopK(suggestion.getQuery(), suggestion.getFrequency());
        }

        return topK;
    }

    /**
     * Returns top-5 suggestions for a given prefix.
     * O(prefix_length) — just navigate to the prefix node and return cached top-K.
     *
     * @param prefix The search prefix to look up
     * @return List of suggestion strings, sorted by frequency, max 5
     */
    public List getSuggestions(String prefix) {
        TrieNode currentNode = rootNode;
        for (char character : prefix.toLowerCase().toCharArray()) {
            if (!currentNode.hasChild(character)) {
                return Collections.emptyList(); // No matching prefix in trie
            }
            currentNode = currentNode.getChild(character);
        }
        return currentNode.getTopKSuggestions();
    }

    private List> getChildEntries(TrieNode node) {
        // Access via reflection-like approach in production; simplified here
        return new ArrayList<>(); // Placeholder — real impl accesses node.childrenByChar.entrySet()
    }

    private String getCurrentPrefix(TrieNode node) {
        // In production, track prefix during traversal; simplified here
        return ""; // Placeholder
    }
}

/**
 * AutocompleteService — serves autocomplete requests from Redis cache.
 * Falls back to in-memory trie on cache miss.
 */
public class AutocompleteService {
    private static final String CACHE_KEY_PREFIX = "autocomplete:";
    private static final int MAX_SUGGESTIONS = 5;

    private final RedisClient redisClient;
    private final AutocompleteTrie inMemoryTrie; // Fallback trie loaded from Cassandra at startup

    public AutocompleteService(RedisClient redisClient, AutocompleteTrie inMemoryTrie) {
        this.redisClient = redisClient;
        this.inMemoryTrie = inMemoryTrie;
    }

    /**
     * Returns top suggestions for a prefix.
     * Fast path: Redis O(1) lookup. Fallback: in-memory trie traversal.
     *
     * @param prefix The user's current search prefix
     * @return Up to MAX_SUGGESTIONS query strings sorted by popularity
     */
    public List getSuggestions(String prefix) {
        if (prefix == null || prefix.isBlank()) {
            return Collections.emptyList();
        }

        String normalizedPrefix = prefix.toLowerCase().trim();
        String cacheKey = CACHE_KEY_PREFIX + normalizedPrefix;

        try {
            List cachedSuggestions = redisClient.lrange(cacheKey, 0, MAX_SUGGESTIONS - 1);
            if (!cachedSuggestions.isEmpty()) {
                return cachedSuggestions;
            }
        } catch (RedisException redisException) {
            System.err.println("[AutocompleteService] Redis unavailable, using trie fallback: "
                    + redisException.getMessage());
        }

        // Fallback to in-memory trie
        return inMemoryTrie.getSuggestions(normalizedPrefix);
    }
}

/** Simple value holder for a query + frequency pair. */
public final class QueryFrequency {
    private final String query;
    private final long frequency;

    public QueryFrequency(String query, long frequency) {
        this.query = query;
        this.frequency = frequency;
    }

    public String getQuery() { return query; }
    public long getFrequency() { return frequency; }
}
