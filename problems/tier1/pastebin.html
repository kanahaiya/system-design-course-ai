Tier 1 — Must Know 45 min

Design Pastebin

Design a text sharing service with short URL generation, optional expiry and password protection, 10:1 read/write ratio, content stored in S3 with hot paste caching in Redis, 99.9% availability.

🏢 Pastebin, GitHub Gist, CodeShare, Hastebin
⏱️ 45 min

R — Requirements

Functional Requirements

  • Create a paste (text or code) and receive a unique short URL (8-character alphanumeric)
  • Retrieve paste by short URL
  • Optional: expiry time (1 hour, 1 day, 1 week, never)
  • Optional: password protection (only those with password can read)
  • View count per paste

Non-Functional Requirements

  • Scale: 5M pastes/day (writes), 50M reads/day (10:1 ratio)
  • Read QPS: 579 QPS (50M ÷ 86,400)
  • Write QPS: 58 QPS (5M ÷ 86,400)
  • Paste size: up to 10MB per paste
  • Storage: 5M × avg 10KB = 50GB/day new content
  • Availability: 99.9%
Key insight: This is a read-heavy system (10:1). The design should optimize for fast reads. The interesting decision is where to store the paste content — DB or object storage? Answer: large variable-length blobs belong in S3.

579 QPS for reads is manageable for a single MySQL replica. With caching (Redis), 90% of reads can be served from cache. The unique ID space: 8 chars × base-62 = 62^8 ≈ 218 trillion unique IDs — no collision concern for millions of years.

S — Schema

-- MySQL: metadata only (NOT the content itself)
CREATE TABLE pastes (
    paste_id      CHAR(8) PRIMARY KEY,          -- base-62 short ID
    title         VARCHAR(200),
    content_url   VARCHAR(512) NOT NULL,         -- S3 key: pastes/{paste_id}
    syntax        VARCHAR(50),                   -- 'java', 'python', 'plain', etc.
    password_hash VARCHAR(60),                   -- bcrypt, NULL = no password
    expires_at    TIMESTAMP,                     -- NULL = never expires
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    view_count    BIGINT DEFAULT 0,
    INDEX idx_expires (expires_at)               -- for cleanup job
);

-- S3: actual content
-- Key pattern: pastes/{paste_id}
-- Content-Type: text/plain
-- Max size: 10MB enforced at API layer

-- Redis: cache hot pastes
-- Key: paste:{paste_id}
-- Value: { title, content, syntax, expires_at }  (JSON, full content)
-- TTL: min(paste expires_at, 24h default cache TTL)
Why content in S3, not MySQL? MySQL TEXT/BLOB columns up to 10MB would work, but: (1) bloats the DB buffer pool with huge blobs, evicting useful index data; (2) backup/restore becomes unwieldy; (3) S3 is designed for arbitrary-size objects and costs ~10x less per GB than RDS storage.

Figure: Pastebin — POST generates Base62 ID, uploads to S3, writes metadata to MySQL, warms Redis; GET hits CDN → Redis → MySQL+S3 on miss

Write path: Generate 8-char base-62 ID → upload content to S3 at key pastes/{id} → INSERT metadata row in MySQL → SET Redis cache with TTL → return short URL to client.

Read path: Check Redis for paste:{id} → cache hit: return content + increment view_count async → cache miss: read metadata from MySQL → fetch content from S3 → populate cache → return to client.

Expiry cleanup: A background cron job runs hourly and runs DELETE FROM pastes WHERE expires_at < NOW(), then deletes corresponding S3 objects and Redis keys.

D — Deep Dive: ID Generation

We need globally unique 8-character IDs that are URL-safe. Options:

Random base-62: Generate 8 random chars from [a-zA-Z0-9]. 62^8 = 218 trillion combinations. At 5M/day it takes 119 years to exhaust. Collision probability at 5M/day: ~(5M)^2 / (2 × 218T) ≈ 0.006% per day — acceptable, but check for collision on INSERT and retry.

Counter-based (preferred): Use a distributed counter (Redis INCR or a dedicated ID service). Convert the integer to base-62 string. Guarantees uniqueness, no collision check needed. Trade-off: predictable/enumerable IDs (attacker can iterate through pastes).

View count increment: Do NOT do a synchronous UPDATE on every read. At 579 QPS, this creates write contention on the pastes table. Instead: batch increments in Redis (INCR paste_views:{id}), flush to MySQL every 5 minutes via a background job. Accepts minor inaccuracy for huge performance gain.

E — Evaluate

  • Cache hit ratio: Pastebin traffic follows a power-law distribution. Top 1% of pastes receive 99% of views. Redis cache with 1GB RAM can hold ~100K pastes. That covers the "hot" pastes; cold pastes fall back to S3 which is still fast (<100ms).
  • Password-protected pastes: Store bcrypt(password) in MySQL. On GET, require X-Paste-Password header, verify with bcrypt.check(). Do NOT cache password-protected pastes in Redis (shared cache would expose content to other users).
  • Paste too large for Redis: If paste content > 1MB, skip Redis caching and serve directly from S3. 1MB threshold prevents large pastes from evicting many small hot pastes.
  • S3 costs: At 50GB/day, S3 Standard costs ~$1.15/day. After 30 days, migrate to S3 Infrequent Access; after 90 days, Glacier. Use S3 Lifecycle rules.

D — Deliver

Pastebin is a great example of separating concerns by data type: structured metadata (small, indexed, relational) lives in MySQL; unstructured blobs (large, no queries needed) live in S3. This pattern appears in almost every large-scale system — never put blobs in a relational DB.

The read path (Redis → S3 → client) can be further optimized with a CDN in front of S3 for public pastes, reducing S3 GET costs and improving global read latency to <50ms.

Trade-off Table

DecisionOption AOption BChosenWhy
Content storage MySQL TEXT column S3 object storage S3 10MB blobs in MySQL bloat the buffer pool and hurt index performance. S3 is built for blob storage, cheaper, and infinitely scalable.
ID generation Random base-62 (with collision check) Counter → base-62 (no collision) Counter Counter guarantees uniqueness without DB round-trip for collision check. Downside: sequential IDs are enumerable. Mitigate by adding a random offset to the counter.
Expiry enforcement Redis TTL on cache keys Background cleanup cron job Both Redis TTL removes from cache automatically. Cron job deletes from MySQL and S3. Need both — Redis TTL alone doesn't clean up S3 objects.
View count updates Synchronous DB UPDATE on each read Async batching via Redis → periodic flush Async 579 QPS of write contention on the same row causes lock waits. Batching accepts small inaccuracy (±5 min lag) for dramatically better read performance.

Java Implementation

/**
 * PasteService
 * Core business logic for creating and retrieving pastes.
 * Orchestrates S3, MySQL, and Redis cache layers.
 */
public class PasteService {

    private static final int PASTE_ID_LENGTH = 8;
    private static final String BASE62_CHARS = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789";
    private static final int MAX_CACHEABLE_CONTENT_BYTES = 1_048_576; // 1MB
    private static final int DEFAULT_CACHE_TTL_SECONDS = 86_400;       // 24 hours

    private final S3Client s3Client;
    private final PasteRepository pasteRepository;
    private final RedisClient redisClient;
    private final IdGenerator idGenerator;

    public PasteService(S3Client s3Client, PasteRepository pasteRepository,
                        RedisClient redisClient, IdGenerator idGenerator) {
        this.s3Client = s3Client;
        this.pasteRepository = pasteRepository;
        this.redisClient = redisClient;
        this.idGenerator = idGenerator;
    }

    /**
     * Creates a new paste: generates ID, uploads to S3, saves metadata to MySQL,
     * caches in Redis for fast reads.
     *
     * @param createRequest the paste creation request from the API layer
     * @return the created paste metadata including the short URL
     */
    public PasteMetadata createPaste(CreatePasteRequest createRequest) {
        String pasteId = generateUniqueId();
        String storageKey = "pastes/" + pasteId;

        uploadContentToS3(storageKey, createRequest.content(), createRequest.syntax());

        PasteRecord pasteRecord = new PasteRecord(
            pasteId,
            createRequest.title(),
            storageKey,
            createRequest.syntax(),
            hashPasswordIfPresent(createRequest.password()),
            calculateExpiryTimestamp(createRequest.expiresInSeconds())
        );
        pasteRepository.insert(pasteRecord);

        if (createRequest.content().length() <= MAX_CACHEABLE_CONTENT_BYTES
                && createRequest.password() == null) {
            cachePaste(pasteId, pasteRecord, createRequest.content());
        }

        return new PasteMetadata(pasteId, pasteRecord.expiresAt());
    }

    /**
     * Retrieves paste content. Cache-first; falls back to S3 on miss.
     * Does NOT cache password-protected pastes (security: shared cache).
     *
     * @param pasteId  the 8-character paste identifier
     * @param password the submitted password, or null if none
     * @return paste content and metadata, or empty if not found/expired
     */
    public Optional<PasteContent> getPaste(String pasteId, String password) {
        Optional<CachedPaste> cachedPaste = redisClient.get("paste:" + pasteId, CachedPaste.class);

        if (cachedPaste.isPresent()) {
            incrementViewCountAsync(pasteId);
            return Optional.of(new PasteContent(cachedPaste.get().content(), cachedPaste.get().metadata()));
        }

        Optional<PasteRecord> pasteRecord = pasteRepository.findById(pasteId);
        if (pasteRecord.isEmpty()) {
            return Optional.empty();
        }

        PasteRecord record = pasteRecord.get();

        if (isPasteExpired(record)) {
            pasteRepository.delete(pasteId);
            return Optional.empty();
        }

        if (!verifyPassword(password, record.passwordHash())) {
            throw new PasteAccessDeniedException("Incorrect password for paste " + pasteId);
        }

        String content = s3Client.getObjectAsString(record.storageKey());

        if (record.passwordHash() == null && content.length() <= MAX_CACHEABLE_CONTENT_BYTES) {
            cachePaste(pasteId, record, content);
        }

        incrementViewCountAsync(pasteId);
        return Optional.of(new PasteContent(content, record));
    }

    private String generateUniqueId() {
        long counter = idGenerator.nextId();
        return encodeBase62(counter, PASTE_ID_LENGTH);
    }

    private String encodeBase62(long number, int targetLength) {
        StringBuilder encodedId = new StringBuilder();
        while (number > 0 || encodedId.length() < targetLength) {
            encodedId.append(BASE62_CHARS.charAt((int) (number % 62)));
            number /= 62;
        }
        return encodedId.reverse().toString();
    }

    private void uploadContentToS3(String storageKey, String content, String syntax) {
        String contentType = "java".equals(syntax) || "python".equals(syntax)
            ? "text/x-" + syntax
            : "text/plain";
        s3Client.putObject(storageKey, content.getBytes(StandardCharsets.UTF_8), contentType);
    }

    private void cachePaste(String pasteId, PasteRecord record, String content) {
        int cacheTtlSeconds = record.expiresAt() != null
            ? (int) Math.min(DEFAULT_CACHE_TTL_SECONDS,
                Duration.between(Instant.now(), record.expiresAt().toInstant()).getSeconds())
            : DEFAULT_CACHE_TTL_SECONDS;

        if (cacheTtlSeconds > 0) {
            redisClient.setWithTtl("paste:" + pasteId,
                new CachedPaste(content, record), cacheTtlSeconds);
        }
    }

    private void incrementViewCountAsync(String pasteId) {
        // INCR paste_views:{pasteId} — flushed to MySQL every 5 minutes by background job
        redisClient.increment("paste_views:" + pasteId);
    }

    private boolean isPasteExpired(PasteRecord record) {
        return record.expiresAt() != null && record.expiresAt().before(new Date());
    }

    private boolean verifyPassword(String submittedPassword, String storedHash) {
        if (storedHash == null) {
            return true; // no password required
        }
        if (submittedPassword == null) {
            return false; // password required but not provided
        }
        return BCrypt.checkpw(submittedPassword, storedHash);
    }

    private String hashPasswordIfPresent(String password) {
        return password != null ? BCrypt.hashpw(password, BCrypt.gensalt()) : null;
    }

    private Timestamp calculateExpiryTimestamp(Long expiresInSeconds) {
        if (expiresInSeconds == null) {
            return null;
        }
        return Timestamp.from(Instant.now().plusSeconds(expiresInSeconds));
    }

    public record CreatePasteRequest(String title, String content, String syntax,
                                     String password, Long expiresInSeconds) {}
    public record PasteMetadata(String pasteId, Timestamp expiresAt) {}
    public record PasteContent(String content, PasteRecord metadata) {}
    public record CachedPaste(String content, PasteRecord metadata) {}
}
