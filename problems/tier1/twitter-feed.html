Tier 1 — Must Know 45 min Celebrity Problem

Design Twitter/X News Feed

The classic feed design problem. The real challenge is the "celebrity problem" — when Cristiano Ronaldo tweets, you cannot push to 600M followers synchronously. Hybrid fanout is the answer interviewers want to hear.

🏢 Meta, Twitter, LinkedIn
⏱️ 45 min interview
📈 300M DAU

❓ R — Requirements 3–5 min

Functional Requirements

  • Post a tweet (text up to 280 chars + optional media)
  • View home feed: reverse-chronological tweets from followed users
  • Follow / unfollow users
  • Like a tweet, retweet a tweet
  • Search tweets (out of scope for this interview — redirect)

Non-Functional Requirements

  • Scale: 300M DAU, 500M tweets per day
  • Feed read QPS: ~17,000 QPS (300M × 5 reads/day / 86,400)
  • Tweet write QPS: ~175 QPS (300M × 0.05 writes/day / 86,400)
  • Feed latency: < 200ms p99 to load home feed
  • Eventual consistency OK: seeing a tweet 1–2 seconds after posting is acceptable
Key question to ask: "What's the follower ceiling? Should we treat celebrity accounts (100M+ followers) differently?" This signals you already know about the celebrity problem.

🔢 E — Estimation 5 min

  • Tweets/day: 300M × 0.05 (5% of users tweet daily) = 15M tweets/day
  • Tweet storage: 15M × 500B = 7.5GB/day → ~2.7TB/year (manageable)
  • Feed cache size: 300M users × 20 tweet IDs × 8 bytes = ~48GB per shard
  • Fan-out writes: Average 200 followers × 175 tweet QPS = 35,000 fan-out writes/sec — must be async via Kafka
  • Celebrity fan-out blocker: 175M followers × 175 QPS = would require 30 billion writes/sec synchronously — impossible, confirms need for hybrid approach

🏗️ H — High-level Design 10 min

Figure: Fan-out on Write (left) vs Fan-out on Read (right) — Hybrid approach for celebrity accounts

Write Path (Post Tweet)

  1. Client → Tweet Service → persist to Cassandra (tweets table)
  2. Publish tweet event to Kafka (topic: tweet-created)
  3. Fan-out Worker consumes from Kafka:
    • Fetch follower list from follows table
    • For non-celebrity (< 1M followers): push tweet_id to each follower's Redis sorted set
    • For celebrity: skip fan-out; followers pull at read time

Read Path (Load Home Feed)

  1. Client → Feed Service
  2. Fetch tweet IDs from Redis sorted set feed:{user_id} (sorted by timestamp)
  3. Merge with celebrity tweets: fetch IDs from followed celebrities' Cassandra rows
  4. Sort merged list by timestamp → take top 20
  5. Hydrate tweet IDs → full tweet objects (tweet metadata cache or Cassandra)
  6. Return paginated feed to client

🔬 D — Deep Dive: The Celebrity Fanout Problem 10 min

When Elon Musk posts a tweet (175M followers), writing to 175M Redis sorted sets synchronously is impossible — it would take hours and block everything.

Hybrid Fanout Strategy

  • Push model (normal users, < 1M followers): Fan-out asynchronously via Kafka worker. Followers see tweets pre-computed in their Redis feed. Read is O(1).
  • Pull model (celebrities, ≥ 1M followers): Do NOT fan-out. At read time, for each celebrity the user follows, fetch their last 20 tweets from Cassandra and merge with the pre-computed feed.

Merge at Read Time

The feed service maintains two sorted streams:

  1. Pre-computed stream from Redis (non-celebrity follows)
  2. On-demand celebrity tweets fetched from Cassandra at read time

Merge with a k-way merge algorithm (min-heap), take top 20 by timestamp. The celebrity query results are cached per-celebrity (not per-follower), so 175M followers all share the same celebrity cache entry.

⚖️ E — Evaluate 5 min

Failure Scenarios

  • Fan-out worker lag: Kafka consumer group lag monitoring. Scale consumers horizontally. Tweets appear with slight delay — acceptable per requirements.
  • Redis OOM: Cap feed cache at 200 tweet IDs per user. Evict oldest. If user hasn't read feed in 30 days, expire the key entirely.
  • New follower not seeing old tweets: On follow, backfill last 20 tweets from followee into follower's Redis feed.

Consistency

Eventual consistency is explicitly acceptable. A tweet may take 1–5 seconds to appear in followers' feeds (Kafka propagation delay). This matches real Twitter behaviour.

🚀 D — Deliver 2 min

"We use a hybrid fanout approach — push for normal users via Kafka workers into Redis sorted sets, pull for celebrities at read time from Cassandra. Feeds merge at read time using a min-heap. The design handles 300M DAU with eventual consistency and sub-200ms feed loads because 95% of the feed comes pre-computed from Redis."

⚖️ Key Trade-offs

DecisionOption AOption BWinner
Fanout Strategy Fanout on write (push to all) Fanout on read (pull always) Hybrid — push for normal, pull for celebrities
Feed Storage Redis sorted set (pre-computed) Rebuild from DB on every read Redis — 17K QPS impossible from DB alone
Consistency Strong (synchronous fanout) Eventual (async Kafka) Eventual — strong consistency blocks writes at celebrity scale
Tweet Storage MySQL (relational) Cassandra (wide-column) Cassandra — append-heavy, time-series access pattern

☕ Java Implementation 

/**
 * FanoutService — pushes a new tweet to follower feeds asynchronously.
 * Normal users (< CELEBRITY_THRESHOLD followers): push to Redis sorted sets.
 * Celebrity users: skip fanout; followers pull at read time.
 */
public class FanoutService {
    private static final int CELEBRITY_FOLLOWER_THRESHOLD = 1_000_000;
    private static final int MAX_FEED_SIZE = 200;
    private static final String FEED_KEY_PREFIX = "feed:";
    private static final int FEED_TTL_DAYS = 30;

    private final FollowRepository followRepository;
    private final RedisClient redisClient;
    private final UserRepository userRepository;

    public FanoutService(FollowRepository followRepository,
                         RedisClient redisClient,
                         UserRepository userRepository) {
        this.followRepository = followRepository;
        this.redisClient = redisClient;
        this.userRepository = userRepository;
    }

    /**
     * Fans out a tweet to all eligible follower feeds.
     * Called by a Kafka consumer — one message per tweet creation event.
     *
     * @param tweetEvent The Kafka event containing tweetId, authorId, and timestamp
     */
    public void fanoutTweet(TweetCreatedEvent tweetEvent) {
        User author = userRepository.findById(tweetEvent.getAuthorId())
                .orElseThrow(() -> new IllegalStateException("Author not found: " + tweetEvent.getAuthorId()));

        if (author.getFollowerCount() >= CELEBRITY_FOLLOWER_THRESHOLD) {
            // Celebrity: do not fan out; followers pull at read time
            return;
        }

        List followerIds = followRepository.getFollowerIds(tweetEvent.getAuthorId());

        for (Long followerId : followerIds) {
            pushTweetToFeed(followerId, tweetEvent.getTweetId(), tweetEvent.getTimestampMs());
        }
    }

    private void pushTweetToFeed(long userId, long tweetId, long timestampMs) {
        String feedKey = FEED_KEY_PREFIX + userId;

        // ZADD feed:{userId} timestamp tweetId
        redisClient.zadd(feedKey, timestampMs, String.valueOf(tweetId));

        // Trim to MAX_FEED_SIZE, keeping highest scores (newest tweets)
        long feedSize = redisClient.zcard(feedKey);
        if (feedSize > MAX_FEED_SIZE) {
            redisClient.zremrangeByRank(feedKey, 0, feedSize - MAX_FEED_SIZE - 1);
        }

        // Refresh TTL on every write to keep active users' caches alive
        redisClient.expire(feedKey, FEED_TTL_DAYS * 86_400);
    }
}

/**
 * FeedService — reads and assembles a user's home feed.
 * Merges pre-computed Redis feed with on-demand celebrity tweets.
 */
public class FeedService {
    private static final int CELEBRITY_FOLLOWER_THRESHOLD = 1_000_000;
    private static final int PAGE_SIZE = 20;

    private final RedisClient redisClient;
    private final TweetRepository tweetRepository;
    private final FollowRepository followRepository;
    private final UserRepository userRepository;

    public FeedService(RedisClient redisClient,
                       TweetRepository tweetRepository,
                       FollowRepository followRepository,
                       UserRepository userRepository) {
        this.redisClient = redisClient;
        this.tweetRepository = tweetRepository;
        this.followRepository = followRepository;
        this.userRepository = userRepository;
    }

    /**
     * Returns the home feed for the given user, paginated by cursor.
     *
     * @param userId         The requesting user's ID
     * @param cursorTweetId  The last tweet ID from the previous page (null for first page)
     * @return Up to PAGE_SIZE hydrated Tweet objects, newest first
     */
    public List getHomeFeed(long userId, Long cursorTweetId) {
        // Step 1: Get pre-computed tweet IDs from Redis (non-celebrity follows)
        List precomputedTweetIds = getPrecomputedFeedIds(userId, cursorTweetId);

        // Step 2: Get celebrity tweet IDs via pull model
        List celebrityTweetIds = getCelebrityTweetIds(userId, cursorTweetId);

        // Step 3: Merge both lists by timestamp using a priority queue
        List mergedTweetIds = mergeSortedByRecency(precomputedTweetIds, celebrityTweetIds);

        // Step 4: Take top PAGE_SIZE
        List pageIds = mergedTweetIds.stream()
                .limit(PAGE_SIZE)
                .collect(Collectors.toList());

        // Step 5: Hydrate tweet IDs → full tweet objects
        return tweetRepository.findAllByIds(pageIds);
    }

    private List getPrecomputedFeedIds(long userId, Long cursorTweetId) {
        String feedKey = "feed:" + userId;
        double maxScore = cursorTweetId != null
                ? tweetRepository.getTimestamp(cursorTweetId) - 1
                : Double.MAX_VALUE;

        // ZREVRANGEBYSCORE feed:{userId} maxScore -inf LIMIT 0 PAGE_SIZE
        return redisClient.zrevrangeByScore(feedKey, maxScore, 0, PAGE_SIZE)
                .stream()
                .map(Long::parseLong)
                .collect(Collectors.toList());
    }

    private List getCelebrityTweetIds(long userId, Long cursorTweetId) {
        List followedCelebrities = followRepository.getFollowedCelebrities(
                userId, CELEBRITY_FOLLOWER_THRESHOLD);

        if (followedCelebrities.isEmpty()) {
            return Collections.emptyList();
        }

        List allCelebrityTweetIds = new ArrayList<>();
        for (Long celebrityId : followedCelebrities) {
            // Each celebrity's recent tweets are cached in Redis too
            // (shared across all followers — key: celeb_tweets:{celebrityId})
            List recentTweets = tweetRepository.getRecentTweetIds(celebrityId, PAGE_SIZE);
            allCelebrityTweetIds.addAll(recentTweets);
        }
        return allCelebrityTweetIds;
    }

    /**
     * Merges two lists of tweet IDs by recency.
     * Uses a PriorityQueue (max-heap by timestamp) for O(n log k) merge.
     */
    private List mergeSortedByRecency(List listA, List listB) {
        PriorityQueue maxHeap = new PriorityQueue<>((a, b) -> {
            long timestampA = tweetRepository.getTimestamp(a);
            long timestampB = tweetRepository.getTimestamp(b);
            return Long.compare(timestampB, timestampA); // descending
        });

        maxHeap.addAll(listA);
        maxHeap.addAll(listB);

        List merged = new ArrayList<>();
        while (!maxHeap.isEmpty() && merged.size() < PAGE_SIZE * 2) {
            merged.add(maxHeap.poll());
        }
        return merged;
    }
}
