Tier 1 — Must Know 45 min

Design Social Media News Feed (Facebook-style)

Design a ranked news feed for 500M DAU with hybrid fanout (write for regular users, read for celebrities), ML-based ranking, Redis feed cache, and efficient pagination at 6000 QPS.

🏢 Facebook, Instagram, Twitter/X, LinkedIn, TikTok
⏱️ 45 min

R — Requirements

Functional Requirements

  • Users see a ranked feed of posts from people/pages they follow
  • Feed is ranked by relevance (not just chronological)
  • Support text, images, videos in posts
  • Paginated infinite scroll (20 posts per page)
  • Near real-time: new posts appear in feed within ~30 seconds

Non-Functional Requirements

  • Scale: 500M DAU, 50M posts/day, 500M feed reads/day
  • Feed read QPS: 500M ÷ 86,400 ≈ 5,787 QPS (peak ~3x = 17K)
  • Celebrity problem: A user with 100M followers posts → must fanout to 100M feeds
  • Feed freshness: < 30s from post to visible in followers' feeds
  • Availability: 99.99% (social feeds are user-facing)
The celebrity problem is the crux of this question. If Beyoncé posts and has 100M followers, naive fanout-on-write would write 100M Redis entries. That takes minutes. The interviewer is testing whether you know the hybrid approach.

E — Estimation

Feed reads/second
5,787 QPS

~80 GB

50M posts ÷ 86,400

~57,800

The feed cache at 80GB fits across a Redis cluster. We store only post IDs (8 bytes each), not full post content — post content is fetched separately. This keeps the feed cache small and fast.

Hybrid fanout: Regular users (≤ 1M followers): fanout on write — their posts are pushed to followers' feed caches. Celebrity users (> 1M followers): fanout on read — their posts are stored separately and merged into the feed at read time. This prevents writing 100M Redis entries for a single post.

D — Deep Dive: Feed Ranking

A purely chronological feed shows the most recent posts first. Facebook/Instagram's algorithmic feed ranks posts by predicted engagement, showing users what they're most likely to interact with.

Simple scoring model (good enough for interview):

score = w1 × recency_score
      + w2 × like_rate        (likes ÷ impressions)
      + w3 × comment_rate     (comments ÷ impressions)
      + w4 × relationship_strength  (close friends = 1.0, weak follow = 0.1)

where w1 + w2 + w3 + w4 = 1.0 (weights tunable via A/B testing).

Recency score: Use exponential decay — recency = e^(-λ × age_in_hours). This makes a 1-hour-old post score 0.97 and a 24-hour-old post score ~0.28 (for λ=0.05).

Online vs pre-computed ranking: Pre-computing scores at write time and storing in the sorted set score is fast at read time but stale (a post that gets 10K likes 6 hours later should rank higher than when first written). Online ranking (at read time) is fresh but adds latency. Facebook uses a tiered approach: pre-compute for old posts, re-rank recent posts online.

E — Evaluate

  • Celebrity posts in active users' feeds: A user who follows 100 celebrities and 500 regular users gets a feed that's 100 celebrity posts merged with the pre-computed feed at read time. Merge is O(k log k) where k ≤ 1000 — fast.
  • User with 0 followers creates post: No fanout needed — feed will never show this post to others. Fanout service checks follower count before queuing work.
  • Feed invalidation on unfollow: When user A unfollows user B, remove all of B's post IDs from A's feed cache. Scan is O(feed_size) — acceptable as unfollows are rare.
  • A/B testing ranking weights: Assign each user to a bucket (hash(user_id) % 100). Bucket 0-49 gets weights [0.4, 0.3, 0.2, 0.1]; bucket 50-99 gets [0.3, 0.35, 0.25, 0.1]. Compare engagement metrics per bucket after 1 week.

D — Deliver

The news feed system's key architectural insight is the hybrid fanout strategy: regular users get pre-computed feed caches (fast reads), celebrities get their posts fetched and merged at read time (avoids write amplification). This asymmetry is the correct trade-off because celebrity write events are rare but have enormous fanout, while regular user posts have manageable fanout that benefits from pre-computation.

Ranking adds a layer of complexity on top of raw feed assembly. The Redis sorted set score field doubles as the rank score, keeping the feed pre-sorted. Re-ranking happens asynchronously when engagement signals change significantly.

Trade-off Table

DecisionOption AOption BChosenWhy
Feed generation Fanout on write (push) Fanout on read (pull) Hybrid Pure write: celebrity with 100M followers writes → 100M Redis writes (minutes of lag). Pure read: 500M users each recompute feed on every load (too slow). Hybrid: write for <1M followers, read for celebrities.
Feed ordering Chronological (timestamp as score) Algorithmic (rank score) Algorithmic Chronological is simpler but shows stale content from infrequent posters above breaking news. Algorithmic increases engagement 30-40% (industry data). Trade-off: harder to implement and less transparent to users.
Ranking timing Pre-computed at write time Online at read time Tiered Pre-computed is fast but scores go stale. Online is fresh but adds 50-100ms latency. Tiered: pre-compute for posts > 1 hour old; re-rank recent posts online using current engagement signals.
Feed cache storage Redis sorted set (post IDs only) Redis hash (full post content) IDs only Full content: 500M users × 20 posts × ~1KB = 10TB Redis — cost-prohibitive. IDs: 500M × 20 × 8B = 80GB — fits in Redis. Fetch content from MySQL/S3 in a separate hydration step.

Java Implementation

/**
 * FeedRankingService
 * Scores and ranks feed items using a weighted multi-signal model.
 * Weights are tunable via A/B testing without code changes.
 */
public class FeedRankingService {

    // Default weights — tuned by A/B testing
    private static final double RECENCY_WEIGHT = 0.35;
    private static final double LIKE_RATE_WEIGHT = 0.25;
    private static final double COMMENT_RATE_WEIGHT = 0.25;
    private static final double RELATIONSHIP_WEIGHT = 0.15;

    // Exponential decay constant: score halves every ~14 hours
    private static final double DECAY_CONSTANT = 0.05;

    /**
     * Ranks a list of feed items using weighted scoring.
     * Items are returned sorted descending by score (best first).
     *
     * @param candidateItems  raw feed items (from cache + celebrity posts)
     * @param viewerId        the user viewing the feed (for relationship signals)
     * @param rankingWeights  optional custom weights for A/B testing
     * @return ranked list of feed items with scores attached
     */
    public List<RankedFeedItem> rankFeedItems(
            List<FeedItem> candidateItems,
            long viewerId,
            RankingWeights rankingWeights) {

        RankingWeights weights = rankingWeights != null ? rankingWeights
            : new RankingWeights(RECENCY_WEIGHT, LIKE_RATE_WEIGHT,
                                 COMMENT_RATE_WEIGHT, RELATIONSHIP_WEIGHT);

        return candidateItems.stream()
            .map(item -> new RankedFeedItem(item, computeScore(item, viewerId, weights)))
            .sorted(Comparator.comparingDouble(RankedFeedItem::score).reversed())
            .toList();
    }

    /**
     * Computes a composite ranking score for a single feed item.
     * All sub-scores are normalized to [0, 1] before weighting.
     *
     * @param item     the feed item to score
     * @param viewerId the viewer (used for relationship strength lookup)
     * @param weights  the weight configuration for this A/B test bucket
     * @return composite score in range [0, 1]
     */
    private double computeScore(FeedItem item, long viewerId, RankingWeights weights) {
        double recencyScore = computeRecencyScore(item.createdAtEpochSeconds());
        double likeRateScore = computeEngagementRate(item.likeCount(), item.impressionCount());
        double commentRateScore = computeEngagementRate(item.commentCount(), item.impressionCount());
        double relationshipScore = computeRelationshipStrength(viewerId, item.authorId());

        return weights.recency() * recencyScore
            + weights.likeRate() * likeRateScore
            + weights.commentRate() * commentRateScore
            + weights.relationship() * relationshipScore;
    }

    /**
     * Exponential decay: recent posts score near 1.0, old posts near 0.0.
     * Half-life: ln(2) / DECAY_CONSTANT ≈ 14 hours.
     */
    private double computeRecencyScore(long createdAtEpochSeconds) {
        long currentEpochSeconds = System.currentTimeMillis() / 1000;
        double ageInHours = (currentEpochSeconds - createdAtEpochSeconds) / 3600.0;
        return Math.exp(-DECAY_CONSTANT * ageInHours);
    }

    /**
     * Engagement rate: interactions ÷ impressions, capped at 1.0.
     * Small smoothing term prevents division by zero for new posts.
     */
    private double computeEngagementRate(long interactionCount, long impressionCount) {
        if (impressionCount == 0) {
            return 0.1; // prior for brand-new posts with no impressions yet
        }
        double rawRate = (double) interactionCount / impressionCount;
        return Math.min(rawRate * 10.0, 1.0); // scale: 10% engagement rate = 1.0 score
    }

    /**
     * Relationship strength: close friends = 1.0, casual follow = 0.1.
     * In production this queries a Graph Service or feature store.
     * Factors: mutual follows, DM frequency, comment history, tag history.
     */
    private double computeRelationshipStrength(long viewerId, long authorId) {
        // Simplified: real system queries pre-computed edge weights from Graph DB
        // Returned as a value in [0.0, 1.0]
        return 0.5; // placeholder — production uses GraphQL/feature store lookup
    }

    public record FeedItem(long postId, long authorId, long createdAtEpochSeconds,
                           long likeCount, long commentCount, long impressionCount) {}
    public record RankedFeedItem(FeedItem item, double score) {}
    public record RankingWeights(double recency, double likeRate,
                                  double commentRate, double relationship) {}
}

/**
 * FeedAssemblyService
 * Assembles and returns a user's feed by combining pre-computed cache
 * with real-time celebrity posts, then ranking the merged result.
 */
public class FeedAssemblyService {

    private static final int CELEBRITY_FOLLOWER_THRESHOLD = 1_000_000;
    private static final int FEED_PAGE_SIZE = 20;
    private static final int CELEBRITY_POSTS_LOOKBACK_HOURS = 24;

    private final RedisClient redisClient;
    private final FeedRankingService rankingService;
    private final PostRepository postRepository;
    private final FollowRepository followRepository;

    public FeedAssemblyService(RedisClient redisClient, FeedRankingService rankingService,
                                PostRepository postRepository, FollowRepository followRepository) {
        this.redisClient = redisClient;
        this.rankingService = rankingService;
        this.postRepository = postRepository;
        this.followRepository = followRepository;
    }

    /**
     * Assembles the ranked news feed for a user.
     * Merges pre-computed feed cache (regular users) with celebrity posts (fetched on read).
     *
     * @param viewerId the user requesting their feed
     * @param pageNumber zero-based page index for pagination
     * @return ranked, paginated list of post IDs
     */
    public List<Long> assembleNewsFeed(long viewerId, int pageNumber) {
        List<Long> cachedPostIds = fetchFromFeedCache(viewerId);
        List<Long> celebrityPostIds = fetchCelebrityPostsForUser(viewerId);

        List<Long> allPostIds = new ArrayList<>(cachedPostIds);
        allPostIds.addAll(celebrityPostIds);

        List<FeedRankingService.FeedItem> feedItems = hydratePostMetadata(allPostIds);
        List<FeedRankingService.RankedFeedItem> rankedItems =
            rankingService.rankFeedItems(feedItems, viewerId, null);

        int startIndex = pageNumber * FEED_PAGE_SIZE;
        int endIndex = Math.min(startIndex + FEED_PAGE_SIZE, rankedItems.size());

        return rankedItems.subList(startIndex, endIndex).stream()
            .map(ranked -> ranked.item().postId())
            .toList();
    }

    private List<Long> fetchFromFeedCache(long userId) {
        // ZREVRANGE feed:{userId} 0 199  — top 200 candidates before ranking
        return redisClient.zrevrange("feed:" + userId, 0, 199);
    }

    private List<Long> fetchCelebrityPostsForUser(long viewerId) {
        List<Long> followedCelebrityIds = followRepository.getCelebrityFollowees(
            viewerId, CELEBRITY_FOLLOWER_THRESHOLD
        );

        return followedCelebrityIds.stream()
            .flatMap(celebrityId ->
                redisClient.zrevrange("celebrity_posts:" + celebrityId, 0, 9).stream()
            )
            .toList();
    }

    private List<FeedRankingService.FeedItem> hydratePostMetadata(List<Long> postIds) {
        return postRepository.findByIds(postIds).stream()
            .map(post -> new FeedRankingService.FeedItem(
                post.postId(), post.userId(), post.createdAt().getTime() / 1000,
                post.likeCount(), post.commentCount(), post.impressionCount()
            ))
            .toList();
    }
}
