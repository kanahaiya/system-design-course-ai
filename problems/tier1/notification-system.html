Tier 1 — Must Know 45 min Event-driven

Design a Push Notification System

10 million notifications per minute on a breaking news event. The challenge is fanout at that scale, absorbing bursts with Kafka, and reliably calling third-party gateways (APNs, FCM) that have their own rate limits and failure modes.

🏢 Meta, Amazon, Netflix, Apple
⏱️ 45 min interview
📱 10M/min peak

❓ R — Requirements 3–5 min

Functional Requirements

  • Send push notification via multiple channels: iOS (APNs), Android (FCM), email (SendGrid), SMS (Twilio)
  • Support three trigger types:
    • Triggered: individual event (user got a like)
    • Scheduled: send at specific time (daily digest)
    • Broadcast: send to a user segment (all iOS users in US)
  • Track delivery status per notification per user
  • Deduplicate — user should never receive the same notification twice

Non-Functional Requirements

  • Peak throughput: 10M notifications/minute (~167K/sec)
  • Delivery latency: < 5 seconds from trigger to device delivery
  • Reliability: At-least-once delivery (guaranteed, not exactly-once)
  • Deduplication: Handle retries gracefully — don't show duplicate pushes

🔢 E — Estimation 5 min

  • Peak QPS: 10M/min = 167K notifications/second
  • Bandwidth: 167K × 1KB = 167MB/second peak write throughput
  • Kafka partitions needed: At 10K msgs/sec per partition = 167,000 / 10,000 = 17 partitions minimum (use 64 for headroom)
  • Device tokens storage: 2B users × 2 devices avg × 200 bytes per token = 800GB → partition in Cassandra
  • Notification history storage: 10M/min × 60 × 24 = 14.4B notifications/day × 200 bytes = ~2.9TB/day (prune after 30 days)
Critical to call out: 10M/min is a burst, not steady-state. Kafka is the buffer that absorbs the burst. Downstream workers can process at their natural rate without the upstream API being blocked.

🏗️ H — High-level Design 10 min

Figure: Notification fan-out pipeline — event triggers Notification Service → Kafka topics → parallel workers delivering to APNs/FCM (push), SendGrid (email), Twilio (SMS)

Triggered Notification Flow

  1. Event source (social service, payment service, etc.) calls Notification API
  2. Notification API deduplicates (Redis check) → persist to Cassandra (PENDING) → publish to Kafka (channel-specific topic)
  3. Channel Worker (iOS/Android/Email/SMS) consumes from Kafka → calls third-party gateway (APNs/FCM/SendGrid/Twilio)
  4. Gateway responds → Worker updates Cassandra status (SENT/FAILED)
  5. On FAILED: retry with exponential backoff (up to 3 attempts)

Broadcast Notification Flow (e.g., breaking news to 100M users)

  1. Admin triggers broadcast via Notification API with segment filter (e.g., "all active iOS users in US")
  2. Fanout Service queries device_tokens table in batches of 10,000 users
  3. Each batch published to Kafka as individual messages → workers process in parallel
  4. Total time: 100M / (64 partitions × 10K/sec per worker) ≈ 156 seconds to deliver to all

🔬 D — Deep Dive: Broadcast Fanout at 10M/min 10 min

You cannot loop through 100M device tokens synchronously in the API handler — it would take hours and block the request thread.

Segment-Based Batch Fanout

  1. The Fanout Service queries device_tokens in pages of 10,000
  2. Each page is dispatched as a batch Kafka message containing 10,000 (userId, token) pairs
  3. 10,000 page workers consume pages from Kafka and call the respective gateway APIs in parallel using async HTTP
  4. At 10,000 tokens per batch and 10,000 concurrent batches processed = 100M tokens in ~10 seconds at peak (with enough workers)

Third-Party Gateway Constraints

  • APNs: Batch up to 1,000 device tokens per HTTP/2 request. Rate limited to ~500K/min per certificate.
  • FCM: Up to 500 tokens per batch request. Rate limit per project.
  • Workers respect gateway rate limits using a token bucket per gateway. If rate limited (429), back off and retry — never drop.

Invalid Token Cleanup

APNs and FCM return error codes for invalid/unregistered tokens. Workers process these errors and mark tokens as active=false in the device_tokens table — prevents wasting gateway calls on dead tokens.

⚖️ E — Evaluate 5 min

  • Worker crash mid-batch: Kafka consumer group ensures the batch is re-consumed by another worker. Messages are not lost (Kafka retains until consumer ACK). Idempotency key prevents duplicate delivery to user.
  • Gateway rate limit hit: Workers implement exponential backoff. Kafka offset not committed until successful — retried automatically.
  • Deduplication: Redis check on idempotencyKey before publish. TTL = 24 hours. If Redis is down, dedup fails open (allow the notification) — better to send twice than not at all.
  • Scheduled notifications: Store in a scheduled_notifications table with scheduled_at timestamp. A cron job (running every minute) fetches due notifications and publishes them to Kafka.

🚀 D — Deliver 2 min

"The Notification API accepts events, deduplicates via Redis, persists to Cassandra, and publishes to channel-specific Kafka topics. Channel workers consume and call gateway APIs with retry and exponential backoff. Broadcasts use a Fanout Service that pages through device tokens in batches of 10K and dispatches parallel Kafka messages, achieving 100M notifications in under 3 minutes with 64 Kafka partitions. Idempotency keys guarantee at-most-once delivery at the user level despite at-least-once Kafka semantics."

⚖️ Key Trade-offs

DecisionOption AOption BWinner
Message Durability At-least-once (Kafka default) Exactly-once (Kafka transactions) At-least-once + idempotency key — exactly-once adds 3× overhead; dedup handles duplicates
Topic Structure Single topic, consumers filter by channel Per-channel topics (push/email/SMS) Per-channel topics — independent scaling, iOS vs SMS workers differ dramatically
Broadcast Fanout Synchronous DB scan + send Async batch Kafka fanout Async batch — synchronous would block for minutes; async scales to 100M in <3 min
Gateway Retry Fixed 3 retries, 1s apart Exponential backoff (1s, 2s, 4s, 8s) Exponential backoff — gateway rate limits recover over time; fixed retry thundering-herds

☕ Java Implementation 

/**
 * NotificationFanoutService — pages through device tokens and dispatches
 * broadcast notifications to Kafka in parallel batches.
 */
public class NotificationFanoutService {
    private static final int BATCH_SIZE = 10_000;
    private static final String PUSH_TOPIC = "notifications-push";

    private final DeviceTokenRepository deviceTokenRepository;
    private final KafkaProducer kafkaProducer;

    public NotificationFanoutService(DeviceTokenRepository deviceTokenRepository,
                                     KafkaProducer kafkaProducer) {
        this.deviceTokenRepository = deviceTokenRepository;
        this.kafkaProducer = kafkaProducer;
    }

    /**
     * Fans out a broadcast notification to all users matching the segment.
     * Pages through device_tokens in batches and publishes each batch to Kafka.
     * The API call returns immediately — fanout continues asynchronously.
     *
     * @param broadcastRequest The broadcast request with segment filter and payload
     * @return The broadcastId for status tracking
     */
    public String fanoutBroadcast(BroadcastRequest broadcastRequest) {
        String broadcastId = UUID.randomUUID().toString();

        // Run fanout asynchronously — do not block the API request thread
        CompletableFuture.runAsync(() ->
                executeFanout(broadcastId, broadcastRequest));

        return broadcastId;
    }

    private void executeFanout(String broadcastId, BroadcastRequest broadcastRequest) {
        String lastSeenUserId = null;
        int totalDispatched = 0;

        while (true) {
            List tokenBatch = deviceTokenRepository.findActiveTokensBySegment(
                    broadcastRequest.getSegment(), lastSeenUserId, BATCH_SIZE);

            if (tokenBatch.isEmpty()) {
                break; // All tokens processed
            }

            publishBatchToKafka(broadcastId, tokenBatch, broadcastRequest.getPayload());
            totalDispatched += tokenBatch.size();
            lastSeenUserId = tokenBatch.get(tokenBatch.size() - 1).getUserIdAsString();

            if (tokenBatch.size() < BATCH_SIZE) {
                break; // Last page
            }
        }

        System.out.println("[NotificationFanoutService] Broadcast " + broadcastId
                + " dispatched to " + totalDispatched + " devices");
    }

    private void publishBatchToKafka(String broadcastId,
                                     List tokenBatch,
                                     NotificationPayload payload) {
        NotificationBatch batch = new NotificationBatch(broadcastId, tokenBatch, payload);
        // Partition by first token's userId so related users may land on same partition
        String partitionKey = tokenBatch.get(0).getUserIdAsString();

        ProducerRecord kafkaRecord =
                new ProducerRecord<>(PUSH_TOPIC, partitionKey, batch);

        kafkaProducer.send(kafkaRecord, (recordMetadata, exception) -> {
            if (exception != null) {
                System.err.println("[NotificationFanoutService] Kafka publish failed: "
                        + exception.getMessage());
                // In production: retry with backoff or send to dead-letter queue
            }
        });
    }
}

/**
 * PushNotificationWorker — Kafka consumer that sends batches to APNs/FCM.
 * Implements exponential backoff retry on gateway failures.
 */
public class PushNotificationWorker {
    private static final int MAX_RETRY_ATTEMPTS = 4;
    private static final long BASE_BACKOFF_MS = 1_000L;
    private static final int APNS_BATCH_SIZE = 1_000;
    private static final int FCM_BATCH_SIZE = 500;

    private final ApnsClient apnsClient;
    private final FcmClient fcmClient;
    private final NotificationRepository notificationRepository;
    private final DeviceTokenRepository deviceTokenRepository;

    public PushNotificationWorker(ApnsClient apnsClient,
                                  FcmClient fcmClient,
                                  NotificationRepository notificationRepository,
                                  DeviceTokenRepository deviceTokenRepository) {
        this.apnsClient = apnsClient;
        this.fcmClient = fcmClient;
        this.notificationRepository = notificationRepository;
        this.deviceTokenRepository = deviceTokenRepository;
    }

    /**
     * Processes a batch of notifications from Kafka.
     * Groups by platform, sends to appropriate gateway, handles errors.
     *
     * @param batch The batch of (userId, deviceToken, payload) from Kafka
     */
    public void processBatch(NotificationBatch batch) {
        Map> tokensByPlatform = batch.getTokens().stream()
                .collect(Collectors.groupingBy(token -> token.getPlatform().name()));

        List iosTokens = tokensByPlatform.getOrDefault("IOS", List.of());
        List androidTokens = tokensByPlatform.getOrDefault("ANDROID", List.of());

        sendToApnsInBatches(iosTokens, batch.getPayload(), batch.getBroadcastId());
        sendToFcmInBatches(androidTokens, batch.getPayload(), batch.getBroadcastId());
    }

    private void sendToApnsInBatches(List tokens,
                                     NotificationPayload payload,
                                     String broadcastId) {
        for (int startIndex = 0; startIndex < tokens.size(); startIndex += APNS_BATCH_SIZE) {
            int endIndex = Math.min(startIndex + APNS_BATCH_SIZE, tokens.size());
            List apnsBatch = tokens.subList(startIndex, endIndex);
            sendToApnsWithRetry(apnsBatch, payload, broadcastId, 0);
        }
    }

    private void sendToApnsWithRetry(List tokens,
                                     NotificationPayload payload,
                                     String broadcastId,
                                     int attemptNumber) {
        try {
            ApnsResponse apnsResponse = apnsClient.sendBatch(
                    tokens.stream().map(DeviceToken::getToken).collect(Collectors.toList()),
                    payload);

            handleApnsResponse(apnsResponse, tokens);

        } catch (ApnsRateLimitException rateLimitException) {
            if (attemptNumber < MAX_RETRY_ATTEMPTS) {
                long backoffMs = BASE_BACKOFF_MS * (long) Math.pow(2, attemptNumber);
                System.out.println("[PushNotificationWorker] APNs rate limited, retrying in "
                        + backoffMs + "ms (attempt " + (attemptNumber + 1) + ")");
                sleepQuietly(backoffMs);
                sendToApnsWithRetry(tokens, payload, broadcastId, attemptNumber + 1);
            } else {
                System.err.println("[PushNotificationWorker] APNs retry exhausted for broadcastId: "
                        + broadcastId);
                markTokensAsFailed(tokens);
            }
        } catch (ApnsException apnsException) {
            System.err.println("[PushNotificationWorker] APNs error: " + apnsException.getMessage());
            markTokensAsFailed(tokens);
        }
    }

    private void handleApnsResponse(ApnsResponse response, List tokens) {
        for (ApnsTokenResult result : response.getResults()) {
            if (result.isSuccess()) {
                notificationRepository.updateStatus(result.getNotificationId(),
                        NotificationStatus.SENT);
            } else if (result.getErrorCode().equals("BadDeviceToken")
                    || result.getErrorCode().equals("Unregistered")) {
                // Device token is invalid — deactivate it to avoid future waste
                deviceTokenRepository.deactivateToken(result.getDeviceToken());
            }
        }
    }

    private void sendToFcmInBatches(List tokens,
                                    NotificationPayload payload,
                                    String broadcastId) {
        for (int startIndex = 0; startIndex < tokens.size(); startIndex += FCM_BATCH_SIZE) {
            int endIndex = Math.min(startIndex + FCM_BATCH_SIZE, tokens.size());
            List fcmBatch = tokens.subList(startIndex, endIndex);
            sendToFcmWithRetry(fcmBatch, payload, 0);
        }
    }

    private void sendToFcmWithRetry(List tokens,
                                    NotificationPayload payload,
                                    int attemptNumber) {
        try {
            fcmClient.sendMulticast(
                    tokens.stream().map(DeviceToken::getToken).collect(Collectors.toList()),
                    payload);
        } catch (FcmException fcmException) {
            if (attemptNumber < MAX_RETRY_ATTEMPTS) {
                long backoffMs = BASE_BACKOFF_MS * (long) Math.pow(2, attemptNumber);
                sleepQuietly(backoffMs);
                sendToFcmWithRetry(tokens, payload, attemptNumber + 1);
            } else {
                System.err.println("[PushNotificationWorker] FCM retry exhausted");
                markTokensAsFailed(tokens);
            }
        }
    }

    private void markTokensAsFailed(List tokens) {
        tokens.forEach(token ->
                notificationRepository.updateStatusByToken(token.getToken(),
                        NotificationStatus.FAILED));
    }

    private void sleepQuietly(long durationMs) {
        try {
            Thread.sleep(durationMs);
        } catch (InterruptedException interruptedException) {
            Thread.currentThread().interrupt();
        }
    }
}
