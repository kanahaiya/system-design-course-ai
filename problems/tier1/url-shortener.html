Tier 1 — Must Know 45 min Classic

Design a URL Shortener (like bit.ly)

A deceptively simple problem. The real challenge is generating globally unique short codes at 1,200 writes/second without collisions, then serving 115,000 redirects/second with sub-10ms latency.

🏢 Amazon, Google, Meta
⏱️ 45 min interview
📈 Read-heavy (100:1)

❓ R — Requirements 3–5 min

Always clarify before designing. State functional requirements (what the system does), then non-functional (how well it does it).

Functional Requirements

  • Given a long URL, generate a short 7-character code (e.g., bit.ly/abc1234)
  • Redirect short URL → original URL with minimal latency
  • Optional: custom aliases (bit.ly/my-brand)
  • Optional: expiry dates on short URLs
  • Optional: click analytics (count, geography, timestamp)

Non-Functional Requirements

  • Scale: 100M new URLs shortened per day; 10B redirects per day
  • Availability: 99.9% uptime (redirect service is revenue-critical)
  • Latency: Redirect must complete in < 10ms p99
  • Durability: Short URLs must never be lost or reused after deletion
  • Uniqueness: No two long URLs map to the same short code; no two short codes map to the same slot
Interviewer signal: Asking "should 301 or 302 redirect be used?" shows you understand caching vs analytics trade-offs. Bring this up here — not at the end.

🔢 E — Estimation 5 min

Traffic

  • Write QPS: 100M / 86,400 ≈ 1,200 writes/sec
  • Read QPS: 10B / 86,400 ≈ 115,000 reads/sec
  • Read:Write ratio ≈ 100:1 → heavily read-optimised design

Storage

  • Each URL record ≈ 500 bytes (short_code + long URL + metadata)
  • 100M writes/day × 365 days × 5 years = 182.5B records
  • 182.5B × 500B ≈ ~91 TB over 5 years
  • Fits in a sharded Cassandra cluster (3–5 nodes initially)

Cache

  • 80/20 rule: 20% of URLs generate 80% of traffic
  • Cache the hot 20%: 100M active URLs × 20% × 500B ≈ 10GB RAM — easily fits in Redis
Key insight: The read:write ratio of 100:1 immediately tells you to optimise the read path aggressively. Redis cache is non-negotiable, not optional.

🗄️ S — Schema 5 min 

// urls table (Cassandra — sharded by short_code)
CREATE TABLE urls (
    short_code   VARCHAR(7)  PRIMARY KEY,   -- e.g. "abc1234"
    original_url TEXT        NOT NULL,
    user_id      BIGINT,                    -- nullable for anonymous
    created_at   TIMESTAMP   NOT NULL,
    expires_at   TIMESTAMP,                 -- null = never expires
    is_active    BOOLEAN     DEFAULT TRUE
);

// analytics table (Cassandra — time-series optimised)
CREATE TABLE url_analytics (
    short_code   VARCHAR(7),
    date         DATE,
    click_count  BIGINT,
    PRIMARY KEY ((short_code), date)        -- partition by code, cluster by date
);

// Redis key pattern:
// GET url:{short_code}  →  original_url (string, TTL = 24 hours)

Why Cassandra? The primary access pattern is lookup by short_code — a perfect Cassandra partition key. Cassandra handles 100k+ reads/sec per node and horizontal sharding is built in.

🏗️ H — High-level Design 10 min

Write Path (Shorten URL)

  1. Client → API Gateway → URL Service
  2. URL Service calls ID Generator Service (Snowflake) → gets unique 64-bit ID
  3. Base62-encode the ID → 7-character short code
  4. Write to Cassandra (durable storage)
  5. Write to Redis (cache warm-up with 24hr TTL)
  6. Return short URL to client

Read Path (Redirect)

  1. Client requests short.ly/abc1234
  2. CDN edge node checks its cache → HIT: 302 redirect immediately (fastest path)
  3. CDN MISS → Redirect Service checks Redis
  4. Redis HIT (80% of traffic): return original_url
  5. Redis MISS: query Cassandra → populate Redis → return original_url
  6. HTTP 302 redirect to original_url
301 vs 302: Use 302 Found. A 301 (permanent) is cached by the browser — the redirect never hits your servers again, so analytics break. A 302 (temporary) always comes back to your server, enabling click counting.

🔬 D — Deep Dive: Unique ID Generation 10 min

This is the hard problem in URL shortening. Three approaches:

Option A: Random + Check

Generate 7 random base62 characters, check DB if taken. Problem: at high scale, collisions become frequent (birthday paradox). Requires DB round-trip per write. Reject.

Option B: Counter + Base62

Use a single auto-increment counter in DB. Base62-encode it. Problem: single counter is a bottleneck and SPOF. Range partitioning helps but adds complexity.

Option C: Snowflake ID → Base62 (Chosen)

Twitter's Snowflake algorithm produces a 64-bit ID = 41-bit timestamp (milliseconds) + 10-bit machine ID + 12-bit sequence. No coordination between nodes. No DB round-trip. Guarantee: 4,096 unique IDs per millisecond per machine.

Base62 encode the 64-bit ID using characters [0-9A-Za-z]. A 64-bit number encodes to at most 11 base62 characters. We take the last 7 (still unique within our ID space for practical URL volumes).

⚖️ E — Evaluate 5 min

Failure Modes

  • ID Generator SPOF: Run multiple Snowflake nodes, each with a unique machine ID (10-bit = up to 1,024 machines)
  • Redis failure: Fail open — fall through to Cassandra. Rate of miss increases but service stays up
  • Cassandra node down: Replication factor 3 with quorum reads/writes ensures availability with 1 node down

Cache Eviction

Use LRU eviction in Redis. Hot URLs (top 20%) stay warm naturally. Set TTL = 24 hours for cold URLs. URLs with expires_at set a matching Redis TTL.

Expiry Cleanup

Redis handles its own TTL cleanup. For Cassandra, run a background Spark job daily to tombstone expired rows (do not delete immediately — Cassandra deletes are expensive).

🚀 D — Deliver 2 min

Summary Statement for Interviewer

"We use a Snowflake ID generator to produce collision-free short codes without coordination. The read path is CDN → Redis → Cassandra, with an expected 80% Redis hit rate keeping p99 redirect latency under 10ms. We use 302 redirects to preserve analytics. The system scales horizontally — add more Redirect Service instances behind the load balancer, add Cassandra nodes for storage, and the ID generator scales by adding machines with unique machine IDs."

What to Mention if Time Allows

  • Analytics pipeline: click events → Kafka → Flink aggregation → analytics DB
  • Abuse prevention: rate limit URL creation per API key
  • Multi-region: deploy in US/EU/APAC, use GeoDNS to route users to nearest region

⚖️ Key Trade-offs

Decision Option A Option B Winner
ID Generation Random + collision check Snowflake → Base62 Snowflake — no coordination, no collision
Primary Storage PostgreSQL (relational) Cassandra (NoSQL) Cassandra — key-value lookups at 100k+ QPS
Redirect Type 301 Permanent (browser caches) 302 Temporary (server sees each) 302 — analytics require every hit to touch server
Cache Layer No cache (DB only) Redis in front of DB Redis — 10ms requirement impossible without cache
Redirect Serving App server only CDN + App server fallback CDN — geographically distributed, sub-5ms for hot URLs

☕ Java Implementation 

/**
 * Snowflake ID Generator — produces unique 64-bit IDs across distributed nodes.
 * Structure: 41-bit timestamp | 10-bit machineId | 12-bit sequence
 */
public class SnowflakeIdGenerator {
    private static final long EPOCH = 1700000000000L;      // Custom epoch (Nov 2023)
    private static final long MACHINE_ID_BITS = 10L;
    private static final long SEQUENCE_BITS = 12L;
    private static final long MAX_MACHINE_ID = ~(-1L << MACHINE_ID_BITS); // 1023
    private static final long MAX_SEQUENCE = ~(-1L << SEQUENCE_BITS);     // 4095
    private static final long MACHINE_ID_SHIFT = SEQUENCE_BITS;           // 12
    private static final long TIMESTAMP_SHIFT = MACHINE_ID_BITS + SEQUENCE_BITS; // 22

    private final long machineId;
    private long lastTimestampMs = -1L;
    private long sequence = 0L;

    public SnowflakeIdGenerator(long machineId) {
        if (machineId < 0 || machineId > MAX_MACHINE_ID) {
            throw new IllegalArgumentException("machineId must be 0–" + MAX_MACHINE_ID);
        }
        this.machineId = machineId;
    }

    public synchronized long nextId() {
        long currentTimestampMs = System.currentTimeMillis() - EPOCH;

        if (currentTimestampMs == lastTimestampMs) {
            sequence = (sequence + 1) & MAX_SEQUENCE;
            if (sequence == 0) {
                // Sequence exhausted — spin until next millisecond
                currentTimestampMs = waitForNextMillisecond(lastTimestampMs);
            }
        } else {
            sequence = 0L;
        }

        if (currentTimestampMs < lastTimestampMs) {
            throw new IllegalStateException("Clock moved backwards — refusing to generate ID");
        }

        lastTimestampMs = currentTimestampMs;

        return (currentTimestampMs << TIMESTAMP_SHIFT)
             | (machineId << MACHINE_ID_SHIFT)
             | sequence;
    }

    private long waitForNextMillisecond(long lastTimestampMs) {
        long timestamp = System.currentTimeMillis() - EPOCH;
        while (timestamp <= lastTimestampMs) {
            timestamp = System.currentTimeMillis() - EPOCH;
        }
        return timestamp;
    }
}

/**
 * Base62 encoder — converts a long ID to a 7-character short code.
 * Alphabet: 0-9, A-Z, a-z (62 characters)
 */
public class Base62Encoder {
    private static final String ALPHABET = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz";
    private static final int BASE = 62;
    private static final int SHORT_CODE_LENGTH = 7;

    public static String encode(long id) {
        if (id < 0) throw new IllegalArgumentException("ID must be non-negative");

        char[] shortCode = new char[SHORT_CODE_LENGTH];
        for (int index = SHORT_CODE_LENGTH - 1; index >= 0; index--) {
            shortCode[index] = ALPHABET.charAt((int)(id % BASE));
            id /= BASE;
        }
        return new String(shortCode);
    }

    public static long decode(String shortCode) {
        long id = 0;
        for (char character : shortCode.toCharArray()) {
            int digitValue = ALPHABET.indexOf(character);
            if (digitValue == -1) {
                throw new IllegalArgumentException("Invalid character in short code: " + character);
            }
            id = id * BASE + digitValue;
        }
        return id;
    }
}

/**
 * URL Shortener Service — orchestrates ID generation, caching, and persistence.
 */
public class UrlShortenerService {
    private static final int CACHE_TTL_SECONDS = 86_400; // 24 hours
    private static final String CACHE_KEY_PREFIX = "url:";
    private static final String BASE_URL = "https://short.ly/";

    private final SnowflakeIdGenerator idGenerator;
    private final RedisClient redisClient;
    private final UrlRepository urlRepository;

    public UrlShortenerService(SnowflakeIdGenerator idGenerator,
                               RedisClient redisClient,
                               UrlRepository urlRepository) {
        this.idGenerator = idGenerator;
        this.redisClient = redisClient;
        this.urlRepository = urlRepository;
    }

    /**
     * Creates a short URL for the given original URL.
     * @param originalUrl The URL to shorten (must be valid HTTP/HTTPS)
     * @param userId      The authenticated user, or null for anonymous
     * @param expiresAt   Optional expiry instant, or null for permanent
     * @return The complete short URL string
     */
    public String shortenUrl(String originalUrl, Long userId, Instant expiresAt) {
        validateUrl(originalUrl);

        long snowflakeId = idGenerator.nextId();
        String shortCode = Base62Encoder.encode(snowflakeId);

        UrlRecord record = new UrlRecord(shortCode, originalUrl, userId,
                                         Instant.now(), expiresAt, true);
        urlRepository.save(record);

        // Warm the cache immediately — avoids cold-start miss on first redirect
        String cacheKey = CACHE_KEY_PREFIX + shortCode;
        int ttlSeconds = expiresAt != null
            ? (int) Duration.between(Instant.now(), expiresAt).getSeconds()
            : CACHE_TTL_SECONDS;
        redisClient.setex(cacheKey, ttlSeconds, originalUrl);

        return BASE_URL + shortCode;
    }

    /**
     * Resolves a short code to the original URL.
     * Read path: Redis cache → Cassandra fallback.
     * @param shortCode The 7-character short code
     * @return The original URL, or empty if not found/expired
     */
    public Optional resolveShortCode(String shortCode) {
        String cacheKey = CACHE_KEY_PREFIX + shortCode;

        // Fast path: Redis cache
        String cachedUrl = redisClient.get(cacheKey);
        if (cachedUrl != null) {
            recordClickAsync(shortCode);
            return Optional.of(cachedUrl);
        }

        // Slow path: Cassandra lookup
        Optional record = urlRepository.findByShortCode(shortCode);
        if (record.isEmpty()) {
            return Optional.empty();
        }

        UrlRecord urlRecord = record.get();
        if (!urlRecord.isActive() || isExpired(urlRecord)) {
            return Optional.empty();
        }

        // Repopulate cache on miss
        int remainingTtl = urlRecord.getExpiresAt() != null
            ? (int) Duration.between(Instant.now(), urlRecord.getExpiresAt()).getSeconds()
            : CACHE_TTL_SECONDS;
        if (remainingTtl > 0) {
            redisClient.setex(cacheKey, remainingTtl, urlRecord.getOriginalUrl());
        }

        recordClickAsync(shortCode);
        return Optional.of(urlRecord.getOriginalUrl());
    }

    private void validateUrl(String url) {
        if (url == null || url.isBlank()) {
            throw new IllegalArgumentException("URL must not be blank");
        }
        if (!url.startsWith("http://") && !url.startsWith("https://")) {
            throw new IllegalArgumentException("URL must start with http:// or https://");
        }
        if (url.length() > 2048) {
            throw new IllegalArgumentException("URL exceeds maximum length of 2048 characters");
        }
    }

    private boolean isExpired(UrlRecord record) {
        return record.getExpiresAt() != null && Instant.now().isAfter(record.getExpiresAt());
    }

    private void recordClickAsync(String shortCode) {
        // Fire-and-forget analytics — does not block redirect
        CompletableFuture.runAsync(() ->
            urlRepository.incrementClickCount(shortCode, LocalDate.now())
        );
    }
}
