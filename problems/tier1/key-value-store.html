Tier 1 — Must Know 45 min

Design a Key-Value Store (like DynamoDB)

Design a distributed key-value store handling 1M QPS with configurable consistency, consistent hashing for partitioning, quorum-based replication, vector clocks for conflict resolution, and LSM-tree storage engine.

🏢 Amazon (DynamoDB), Meta (Cassandra), LinkedIn (Voldemort)
⏱️ 45 min

R — Requirements

Functional Requirements

  • get(key) — retrieve the value for a key
  • put(key, value) — store or update a key-value pair
  • delete(key) — remove a key
  • Configurable consistency: eventual (higher availability) or strong (linearizable)

Non-Functional Requirements

  • Throughput: 1M QPS total (mix of reads/writes)
  • Data size: 10TB across the cluster
  • Durability: 99.999% (data survives disk failures)
  • Horizontal scaling: add nodes without downtime
  • Fault tolerance: cluster continues operating with up to N-1 node failures (where N is replication factor)
This is a CAP theorem question. The interviewer is probing: do you understand the partition tolerance tradeoff? Strong consistency (CP) vs high availability (AP). Amazon Dynamo chose AP with eventual consistency for shopping cart — data loss less damaging than unavailability.

30K QPS per node is achievable with a memory-mapped storage engine (RocksDB handles 100K+ QPS per node). The challenge is coordination — quorum writes to 3 nodes must complete before acknowledging the client, adding latency.

S — Schema

// Internal storage structure — NOT a relational schema

// Consistent hash ring — maps key hashes to nodes
// Ring has 360 × virtual_nodes_per_physical_node positions
// Virtual nodes improve load balance (avoids hot spots)

// SSTable (Sorted String Table) on each node:
// - Stored as immutable files sorted by key
// - Bloom filter per SSTable (fast miss detection)
// - Summary index: sparse key-offset pairs for binary search

// Write-Ahead Log (WAL): append-only file for durability
// Format: [timestamp][key_len][key][value_len][value][checksum]

// MemTable: in-memory sorted structure (Red-Black tree or skip list)
// When MemTable reaches threshold (~64MB), flush to new SSTable

// Vector clock for each key: { node_id: logical_clock }
// Tracks causal history of writes across replicas

// Metadata stored per entry:
// key, value, vector_clock, tombstone_flag, created_at, version
Why LSM-tree (Log-Structured Merge-tree)? Writes go to an in-memory MemTable first (extremely fast). Periodic flushes to disk are sequential (fast for SSDs and HDDs). Reads check MemTable → SSTables → use Bloom filters to skip SSTables that don't contain the key. Write-optimized at the cost of slightly slower reads (compaction keeps read overhead bounded).

Figure: Key-value store — key "foo" maps to N1 (primary), replicated clockwise to N2 (sync) and N3 (async); W=2 write quorum + R=2 read quorum guarantees consistency (W+R > N)

Consistent hash ring: Keys are mapped to a position on a 0–2^32 ring via MD5 or MurmurHash. Each physical node owns multiple positions (virtual nodes). A key goes to the first N nodes clockwise on the ring.

Quorum protocol: N=3 replicas, W=2 write quorum, R=2 read quorum. W+R=4 > N=3, so every read will see at least one node with the latest write → strong consistency. For eventual consistency, use R=1, W=1.

Write path: Client → any coordinator node → hash key → identify 3 replica nodes → send write to all 3 in parallel → wait for W=2 ACKs → respond OK to client. Third replica receives async.

Read path: Coordinator sends read to R=2 replicas → if they agree, return value → if they disagree, resolve conflict (vector clock or last-write-wins) → return winner, trigger read-repair on stale replica.

D — Deep Dive: Vector Clocks & Conflict Resolution

When two clients write to the same key concurrently on different replicas (possible under eventual consistency), both writes are valid from their perspective. Vector clocks track causality to determine if one write supersedes another or if they are truly concurrent.

A vector clock is a map of {nodeId → logicalClock}. When node A writes, it increments its own clock: {A:1, B:0}. If node B receives this write then makes its own write, B's clock becomes {A:1, B:1}. We can prove B's write happened after A's.

If two writes have clocks {A:2, B:1} and {A:1, B:2}, neither dominates — they are concurrent and we have a conflict. Resolution options: (1) application-level merge (shopping cart can union both), (2) last-write-wins using wall clock timestamp (simpler, loses one write).

Last-Write-Wins (LWW) tradeoff: Simpler to implement and reason about. Requires synchronized clocks (NTP drift can cause incorrect ordering). Amazon Dynamo uses LWW by default but exposes conflicting versions to the application for custom resolution.

E — Evaluate

  • Node failure mid-write: If a node goes down after coordinator sends write but before ACK, coordinator counts it as failed. If W=2 is still met with remaining nodes, write succeeds. Failed node catches up via Hinted Handoff (coordinator stores the write with a hint, delivers when node recovers).
  • Network partition: Under AP mode (W=1, R=1), both sides continue serving. Reads may return stale data. After partition heals, anti-entropy gossip protocol synchronizes replicas using Merkle trees to find diverged key ranges.
  • Hot key (celebrity problem): One key gets 100K writes/sec. Consistent hashing puts it on 3 nodes — those 3 nodes are overloaded. Solution: add random suffixes to create N logical sub-keys, read all N and merge. DynamoDB's adaptive capacity also detects and reroutes hot partitions.
  • Compaction: SSTables accumulate on disk. Periodic compaction merges SSTables, removes deleted keys (tombstones), and reduces read amplification. During compaction, disk I/O spikes — schedule during low-traffic windows.

D — Deliver

The architecture follows Amazon Dynamo's design: consistent hashing for partitioning, quorum for consistency, vector clocks for conflict detection, gossip protocol for membership, and anti-entropy for replica repair.

CAP summary: With W=2, R=2, N=3 → CP (consistent, partition-tolerant, sacrifices some availability). With W=1, R=1 → AP (available, partition-tolerant, eventual consistency). The system is configurable per-request — different use cases in the same cluster can have different consistency requirements.

Trade-off Table

DecisionOption AOption BChosenWhy
Conflict resolution Vector clocks (application-level merge) Last-write-wins (LWW) Configurable Shopping cart needs merge; user profile can afford to lose one write. Expose both modes. Default to LWW for simplicity; let application opt into vector clocks.
Storage engine LSM-tree (write-optimized) B-tree (read-optimized) LSM-tree KV stores are typically write-heavy. LSM-tree converts random writes to sequential I/O (10x faster on HDD, 5x on SSD). Read overhead is bounded by compaction keeping SSTable count small.
Consistency level Strong (W+R > N) Eventual (W=1, R=1) Configurable per-request Different use cases need different consistency. Expose as a parameter so low-latency use cases (session cache) can use eventual while financial data uses strong.

Java Implementation

/**
 * VectorClock
 * Tracks causal ordering of writes across distributed nodes.
 * Used to detect concurrent writes (conflicts) vs causal writes (no conflict).
 */
public class VectorClock {

    // nodeId -> logical clock counter for that node
    private final Map<String, Long> clockValues;

    public VectorClock() {
        this.clockValues = new HashMap<>();
    }

    public VectorClock(Map<String, Long> initialValues) {
        this.clockValues = new HashMap<>(initialValues);
    }

    /**
     * Increments this node's clock when it performs a write.
     * Must be called before each local write operation.
     *
     * @param nodeId the node performing the write
     * @return new VectorClock with incremented value for this node
     */
    public VectorClock increment(String nodeId) {
        Map<String, Long> newValues = new HashMap<>(clockValues);
        newValues.merge(nodeId, 1L, Long::sum);
        return new VectorClock(newValues);
    }

    /**
     * Merges two clocks by taking the max of each component.
     * Used when a node receives a message from another node.
     *
     * @param other the clock from the received message
     * @return merged VectorClock
     */
    public VectorClock merge(VectorClock other) {
        Map<String, Long> mergedValues = new HashMap<>(clockValues);
        other.clockValues.forEach((nodeId, clockValue) ->
            mergedValues.merge(nodeId, clockValue, Math::max)
        );
        return new VectorClock(mergedValues);
    }

    /**
     * Determines the causal relationship between this clock and another.
     *
     * @param other the clock to compare against
     * @return BEFORE, AFTER, CONCURRENT, or EQUAL
     */
    public CausalRelation compareTo(VectorClock other) {
        boolean thisIsLarger = false;
        boolean otherIsLarger = false;

        Set<String> allNodes = new HashSet<>(clockValues.keySet());
        allNodes.addAll(other.clockValues.keySet());

        for (String nodeId : allNodes) {
            long thisValue = clockValues.getOrDefault(nodeId, 0L);
            long otherValue = other.clockValues.getOrDefault(nodeId, 0L);

            if (thisValue > otherValue) {
                thisIsLarger = true;
            } else if (thisValue < otherValue) {
                otherIsLarger = true;
            }
        }

        if (!thisIsLarger && !otherIsLarger) return CausalRelation.EQUAL;
        if (thisIsLarger && !otherIsLarger)  return CausalRelation.AFTER;   // this happened after other
        if (!thisIsLarger && otherIsLarger)  return CausalRelation.BEFORE;  // this happened before other
        return CausalRelation.CONCURRENT; // conflict: neither dominates
    }

    public enum CausalRelation { BEFORE, AFTER, EQUAL, CONCURRENT }

    public Map<String, Long> getValues() { return Collections.unmodifiableMap(clockValues); }
}

/**
 * QuorumCoordinator
 * Manages quorum-based reads and writes across replica nodes.
 * Implements the coordinator role in the consistent hashing cluster.
 */
public class QuorumCoordinator {

    private final int replicationFactor;    // N
    private final int writeQuorum;          // W: min nodes to ACK before write success
    private final int readQuorum;           // R: min nodes to read from

    private final ConsistentHashRing hashRing;
    private final ReplicaNodeClient replicaClient;

    public QuorumCoordinator(int replicationFactor, int writeQuorum, int readQuorum,
                              ConsistentHashRing hashRing, ReplicaNodeClient replicaClient) {
        if (writeQuorum + readQuorum <= replicationFactor) {
            throw new IllegalArgumentException(
                "W+R must be > N for strong consistency. Got W=" + writeQuorum
                + " R=" + readQuorum + " N=" + replicationFactor
            );
        }
        this.replicationFactor = replicationFactor;
        this.writeQuorum = writeQuorum;
        this.readQuorum = readQuorum;
        this.hashRing = hashRing;
        this.replicaClient = replicaClient;
    }

    /**
     * Writes a value to N replicas, waiting for W acknowledgements.
     * Returns after W ACKs — remaining replicas replicate asynchronously.
     *
     * @param key   the key to write
     * @param value the value bytes
     * @throws QuorumException if fewer than W replicas acknowledge within timeout
     */
    public void put(String key, byte[] value) {
        List<String> replicaNodeIds = hashRing.getReplicaNodes(key, replicationFactor);
        VectorClock newClock = replicaClient.getCurrentClock(key, replicaNodeIds.get(0))
            .increment(getCurrentNodeId());

        List<CompletableFuture<Boolean>> writeFutures = replicaNodeIds.stream()
            .map(nodeId -> replicaClient.replicateWriteAsync(nodeId, key, value, newClock))
            .toList();

        long successfulAcknowledgements = writeFutures.stream()
            .map(future -> {
                try {
                    return future.get(200, TimeUnit.MILLISECONDS);
                } catch (Exception writeException) {
                    return false;
                }
            })
            .filter(Boolean::booleanValue)
            .count();

        if (successfulAcknowledgements < writeQuorum) {
            throw new QuorumException("Write quorum not met: got "
                + successfulAcknowledgements + " of required " + writeQuorum);
        }
    }

    /**
     * Reads from R replicas and resolves conflicts if replicas disagree.
     * Triggers read-repair on any stale replica found.
     */
    public Optional<byte[]> get(String key) {
        List<String> replicaNodeIds = hashRing.getReplicaNodes(key, replicationFactor);

        List<ReplicaResponse> responses = replicaNodeIds.stream()
            .limit(readQuorum)
            .map(nodeId -> replicaClient.read(nodeId, key))
            .filter(Optional::isPresent)
            .map(Optional::get)
            .toList();

        if (responses.isEmpty()) {
            return Optional.empty();
        }

        ReplicaResponse latestResponse = resolveConflicts(responses);
        triggerReadRepairIfNeeded(key, responses, latestResponse, replicaNodeIds);
        return Optional.of(latestResponse.value());
    }

    private ReplicaResponse resolveConflicts(List<ReplicaResponse> responses) {
        // Last-write-wins: return response with highest timestamp
        return responses.stream()
            .max(Comparator.comparingLong(ReplicaResponse::writeTimestampMs))
            .orElseThrow();
    }

    private void triggerReadRepairIfNeeded(String key, List<ReplicaResponse> responses,
            ReplicaResponse latestResponse, List<String> allReplicaNodeIds) {
        boolean hasStaleReplica = responses.stream()
            .anyMatch(response -> response.writeTimestampMs() < latestResponse.writeTimestampMs());

        if (hasStaleReplica) {
            // Async: update stale replicas with the latest value
            allReplicaNodeIds.forEach(nodeId ->
                replicaClient.replicateWriteAsync(nodeId, key,
                    latestResponse.value(), latestResponse.vectorClock())
            );
        }
    }

    private String getCurrentNodeId() {
        return hashRing.getCurrentNodeId();
    }

    public record ReplicaResponse(byte[] value, VectorClock vectorClock, long writeTimestampMs) {}
}
