Tier 1 — Must Know 45 min Real-time

Design WhatsApp / Chat Messaging

100 billion messages per day. The hard parts: maintaining persistent WebSocket connections at scale across stateful servers, and routing messages when sender and recipient are on different servers.

🏢 Meta, Apple, Google
⏱️ 45 min interview
💬 2B users

❓ R — Requirements 3–5 min

Functional Requirements

  • 1:1 messaging between users
  • Group chat (up to 1,000 members)
  • Message delivery receipts: single tick (sent), double tick (delivered), blue tick (read)
  • Media sharing (images, video, documents)
  • Online presence indicator (last seen)

Non-Functional Requirements

  • Scale: 2B users, 100B messages/day
  • Delivery guarantee: Messages must be delivered even if recipient is offline for up to 7 days
  • Latency: < 100ms message delivery when both users are online
  • Encryption: End-to-end encrypted (E2EE) — server cannot read message content
  • Ordering: Messages within a conversation appear in sent order

🔢 E — Estimation 5 min

  • Message QPS: 100B / 86,400 ≈ 1.16M messages/sec
  • Write throughput: 1.16M × 100 bytes avg = 116 MB/s sustained write
  • Offline storage (7-day): 100B msgs/day × 7 days × 100B = 70TB
  • Concurrent WebSocket connections: 2B users × 60% online at peak = 1.2B connections → distributed across thousands of chat servers (each handling ~100K connections)
  • Presence heartbeats: 1.2B users × 1 heartbeat/30s = 40M heartbeat writes/sec → Redis only (in-memory TTL, no persistence needed)

🏗️ H — High-level Design 10 min

Message Send (Both Users Online)

  1. Alice sends message via WebSocket to her Chat Server (CS-A)
  2. CS-A persists message to Cassandra with status=SENT
  3. CS-A looks up Bob's chat server in Redis (ws_session:bob_id)
  4. CS-A publishes message to Redis pub/sub channel user:{bob_id}
  5. CS-B (Bob's server) is subscribed to user:{bob_id} → receives message → pushes over WebSocket to Bob
  6. Bob's client ACKs → CS-B updates status to DELIVERED in Cassandra

Message Send (Recipient Offline)

  1. CS-A checks Redis → Bob has no active WebSocket session
  2. CS-A saves message to Cassandra (status=SENT)
  3. CS-A triggers Push Notification Service (APNs/FCM)
  4. When Bob comes online, his client sends last-seen message_id → server fetches all newer messages from Cassandra → delivers in order

🔬 D — Deep Dive: WebSocket Routing at Scale 10 min

The fundamental problem: WebSocket connections are stateful and pinned to a specific server. If Alice is on CS-A and Bob is on CS-B, how does CS-A deliver a message to Bob?

Solution: Redis Pub/Sub for Cross-Server Routing

  1. Every chat server subscribes to a Redis pub/sub channel for each connected user: SUBSCRIBE user:{user_id}
  2. When CS-A needs to send to Bob, it publishes to PUBLISH user:{bob_id} <message>
  3. Redis fan-outs to all subscribers — CS-B receives it and pushes to Bob's WebSocket

Why Not Just Route HTTP Between Chat Servers?

It works but requires CS-A to know Bob's specific server IP (stored in Redis anyway) and make an HTTP call. Pub/sub decouples this — CS-A doesn't need to know which server Bob is on. Also handles the case where Bob has multiple devices.

Group Messages

For a group with 1,000 members, the sending server publishes to each member's pub/sub channel. 1,000 PUBLISH calls per group message. For very large groups, use a dedicated group fanout service that shards members across workers.

⚖️ E — Evaluate 5 min

  • Chat Server failure: Clients detect WebSocket disconnection and reconnect to any available server (via load balancer). On reconnect, client sends its last seen message_id and server delivers missed messages.
  • Redis pub/sub failure: Messages fail to route in real-time. Fall back to push notifications for delivery guarantee. Messages are in Cassandra — none are lost.
  • Message ordering: Cassandra rows sorted by Snowflake message_id (time-ordered). Client uses this as display order. No server-side sorting needed.
  • Duplicate messages: Client includes clientMessageId (UUID). Server deduplicates on Cassandra insert using IF NOT EXISTS.

🚀 D — Deliver 2 min

"Clients maintain persistent WebSocket connections to stateful chat servers. Cross-server message routing uses Redis pub/sub — each user has a channel, and their connected server subscribes on their behalf. Messages are durably stored in Cassandra before routing, ensuring no loss on server failure. Offline users receive push notifications and gap-fill on reconnect. Delivery receipts flow back via the same WebSocket channel."

⚖️ Key Trade-offs

DecisionOption AOption BWinner
Real-time Protocol Long polling (HTTP) WebSocket (persistent TCP) WebSocket — <100ms latency requirement; long polling adds 1–5s
Cross-server Routing Direct HTTP between servers Redis pub/sub Redis pub/sub — decoupled; sender doesn't need to track recipient's server
Offline Delivery Push notification only Push notification + Cassandra gap-fill Both — push wakes app; gap-fill delivers all missed messages in order
Message Storage MySQL with conversation sharding Cassandra partitioned by conversation_id Cassandra — 1.16M QPS write throughput; append-only time-series

☕ Java Implementation 

/**
 * ChatServer — handles WebSocket connections and routes messages via Redis pub/sub.
 * One instance handles ~100K concurrent WebSocket connections.
 */
public class ChatServer {
    private static final String SESSION_KEY_PREFIX = "ws_session:";
    private static final String PUBSUB_CHANNEL_PREFIX = "user:";
    private static final int SESSION_TTL_SECONDS = 60;

    private final Map activeSessionsByUserId = new ConcurrentHashMap<>();
    private final MessageRepository messageRepository;
    private final RedisClient redisClient;
    private final RedisPubSubClient redisPubSubClient;
    private final String serverIpAddress;

    public ChatServer(MessageRepository messageRepository,
                      RedisClient redisClient,
                      RedisPubSubClient redisPubSubClient,
                      String serverIpAddress) {
        this.messageRepository = messageRepository;
        this.redisClient = redisClient;
        this.redisPubSubClient = redisPubSubClient;
        this.serverIpAddress = serverIpAddress;
    }

    /**
     * Called when a client establishes a WebSocket connection.
     * Registers session in Redis and subscribes to pub/sub for message routing.
     */
    public void onClientConnected(long userId, WebSocketSession session) {
        activeSessionsByUserId.put(userId, session);

        // Register this user → this server in Redis
        redisClient.setex(SESSION_KEY_PREFIX + userId, SESSION_TTL_SECONDS, serverIpAddress);

        // Subscribe to Redis pub/sub channel for this user
        // When another server publishes to "user:{userId}", this server receives it
        redisPubSubClient.subscribe(PUBSUB_CHANNEL_PREFIX + userId,
                (channel, messagePayload) -> deliverMessageToClient(userId, messagePayload));
    }

    /**
     * Called when a client disconnects (WebSocket closed).
     */
    public void onClientDisconnected(long userId) {
        activeSessionsByUserId.remove(userId);
        redisClient.delete(SESSION_KEY_PREFIX + userId);
        redisPubSubClient.unsubscribe(PUBSUB_CHANNEL_PREFIX + userId);
    }

    /**
     * Processes an incoming SEND message from a connected client.
     * Persists to Cassandra, then routes to recipient.
     *
     * @param sendEvent The parsed message send request from the WebSocket frame
     */
    public void handleSendMessage(MessageSendEvent sendEvent) {
        // Persist first — durability before delivery
        Message persistedMessage = messageRepository.saveMessage(
                sendEvent.getConversationId(),
                sendEvent.getSenderId(),
                sendEvent.getRecipientId(),
                sendEvent.getContentBytes(),
                sendEvent.getClientMessageId()
        );

        // Route to recipient via Redis pub/sub
        // CS-B (recipient's server) is subscribed to "user:{recipientId}"
        String channelName = PUBSUB_CHANNEL_PREFIX + sendEvent.getRecipientId();
        String serializedMessage = serializeForDelivery(persistedMessage);
        redisPubSubClient.publish(channelName, serializedMessage);

        // Acknowledge to sender with the server-assigned message ID
        sendAckToSender(sendEvent.getSenderId(), persistedMessage.getMessageId());
    }

    /**
     * Delivers a message received from Redis pub/sub to the connected client.
     * Called on the pub/sub callback thread.
     */
    private void deliverMessageToClient(long userId, String messagePayload) {
        WebSocketSession recipientSession = activeSessionsByUserId.get(userId);

        if (recipientSession == null || !recipientSession.isOpen()) {
            // Client disconnected between pub/sub subscribe and delivery
            // Message is in Cassandra — client will gap-fill on next reconnect
            return;
        }

        try {
            recipientSession.sendText(messagePayload);
        } catch (IOException ioException) {
            // Log and let gap-fill handle it — do not lose the message
            System.err.println("[ChatServer.deliverMessageToClient] Send failed for user "
                    + userId + ": " + ioException.getMessage());
        }
    }

    /**
     * Gap-fill: delivers all messages missed since lastSeenMessageId.
     * Called when a client reconnects and sends its last seen message ID.
     */
    public void deliverMissedMessages(long userId, long conversationId, long lastSeenMessageId) {
        WebSocketSession session = activeSessionsByUserId.get(userId);
        if (session == null || !session.isOpen()) {
            return;
        }

        List missedMessages = messageRepository.fetchMessagesSince(
                conversationId, lastSeenMessageId);

        for (Message message : missedMessages) {
            try {
                session.sendText(serializeForDelivery(message));
            } catch (IOException ioException) {
                System.err.println("[ChatServer.deliverMissedMessages] Failed: " + ioException.getMessage());
                break; // Stop on error — client will retry on next reconnect
            }
        }
    }

    /**
     * Handles delivery ACK from client — updates message status to DELIVERED.
     */
    public void handleDeliveryAck(long userId, long messageId) {
        messageRepository.updateMessageStatus(messageId, userId, MessageStatus.DELIVERED);

        // Notify original sender of delivery receipt via pub/sub
        Message message = messageRepository.findById(messageId);
        if (message != null) {
            String receiptPayload = buildDeliveryReceiptJson(messageId, MessageStatus.DELIVERED);
            redisPubSubClient.publish(PUBSUB_CHANNEL_PREFIX + message.getSenderId(), receiptPayload);
        }
    }

    private void sendAckToSender(long senderId, long serverMessageId) {
        WebSocketSession senderSession = activeSessionsByUserId.get(senderId);
        if (senderSession != null && senderSession.isOpen()) {
            try {
                senderSession.sendText("{\"type\":\"SENT_ACK\",\"messageId\":" + serverMessageId + "}");
            } catch (IOException ioException) {
                System.err.println("[ChatServer.sendAckToSender] Failed: " + ioException.getMessage());
            }
        }
    }

    private String serializeForDelivery(Message message) {
        return "{\"type\":\"DELIVER\""
                + ",\"messageId\":" + message.getMessageId()
                + ",\"conversationId\":" + message.getConversationId()
                + ",\"senderId\":" + message.getSenderId()
                + ",\"contentBytes\":\"" + message.getContentBytesBase64() + "\""
                + ",\"timestamp\":" + message.getCreatedAtMs()
                + "}";
    }

    private String buildDeliveryReceiptJson(long messageId, MessageStatus status) {
        return "{\"type\":\"RECEIPT\",\"messageId\":" + messageId
                + ",\"status\":\"" + status.name() + "\"}";
    }
}
