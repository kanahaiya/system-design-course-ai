Tier 2 — Should Know 45 min Security-critical

Design Online Code Judge (LeetCode)

The central challenge is security: you're executing arbitrary user code on your servers. A malicious submission could delete your database, exfiltrate secrets, or fork-bomb the host. Sandboxing is non-negotiable — Docker containers with hard resource limits.

🏢 LeetCode, HackerRank, Google
⏱️ 45 min interview
🔒 Untrusted code execution

❓R — Requirements3–5 min

Functional Requirements

  • Submit code in multiple languages (Java, Python, C++, Go)
  • Run code against hidden test cases; return pass/fail per test
  • Show: runtime (ms), memory usage (MB), output diff on failure
  • Support custom test cases (run against user-provided input)
  • Problem management: create/edit problems with test cases

Non-Functional Requirements

  • Security: Submitted code must be fully isolated — no network, no filesystem, CPU/memory limited
  • Scale: 100K submissions/day = ~1,200/min peak; 5s max execution time
  • Fairness: Same code should produce consistent runtime measurements

🔢E — Estimation3–5 min

  • 100K submissions/day; each runs 50 test cases avg → 5M executions/day
  • Avg execution: 500ms → 5M × 0.5s = 2.5M execution-seconds/day → need ~30 executor cores running continuously
  • Container startup overhead: 200ms; reuse containers via warm pool to amortize
  • Code storage: 100K submissions × avg 2KB = 200MB/day; S3 for long-term

🗄️S — Schema3–5 min

// Problems (PostgreSQL)
problems: problem_id, title, description, difficulty (easy/medium/hard),
          time_limit_ms, memory_limit_mb, created_at

// Test cases (stored in S3, metadata in DB)
test_cases: test_case_id, problem_id, is_hidden, input_s3_key, expected_output_s3_key

// Submissions (PostgreSQL)
submissions:
    submission_id  UUID PRIMARY KEY,
    problem_id     UUID,
    user_id        UUID,
    language       VARCHAR(20),  -- java, python, cpp, go
    code_s3_key    VARCHAR(500),
    status         ENUM(queued, running, accepted, wrong_answer, time_limit, memory_limit, compile_error, runtime_error),
    runtime_ms     INT,
    memory_mb      INT,
    created_at     TIMESTAMP

🏗️H — High-level Design10 min

  • Submission API: Validates and stores code in S3. Creates submission row (status=queued). Publishes job to Kafka. Returns submission_id immediately (async).
  • Job Queue (Kafka): Submission jobs buffered. Executor workers consume from Kafka.
  • Executor Pool: Isolated VMs (or Kubernetes pods) with Docker daemon. Each worker pulls a job, spins up a container, executes code, compares output, updates DB, produces result to Kafka.
  • Result Service: Client polls GET /submissions/{id} for status, or uses WebSocket for real-time result push.
  • Container Pool: Pre-warm containers per language to avoid cold-start latency. Reuse containers between submissions (reset state between runs).

🔌A — APIs5 min

POST /v1/submissions
  Body: { problemId, language, code }
  Returns: { submissionId, status: "queued" }   // immediate async response

GET  /v1/submissions/{submissionId}
  Returns: { status, runtimeMs, memoryMb, testResults: [{passed, input, output, expected}] }

POST /v1/submissions/run          // run against custom input (no test cases)
  Body: { language, code, stdin }
  Returns: { stdout, stderr, runtimeMs }

GET  /v1/problems/{problemId}
GET  /v1/problems/{problemId}/submissions?userId={}&limit=20

🔬D — Deep Dive: Secure Code Execution10 min

Never run untrusted code on the host OS. Use Docker containers with strict constraints:

  • CPU limit: --cpus=1 — prevents fork bombs from consuming all cores
  • Memory limit: --memory=256m --memory-swap=256m — kills OOM attempts
  • Network disabled: --network=none — prevents data exfiltration
  • Read-only filesystem: --read-only with a tmpfs for /tmp
  • No privilege escalation: --security-opt=no-new-privileges
  • Timeout: Kill container after time_limit_ms + 1s buffer via docker run --timeout
  • No root: Run as non-root user inside container

Language-specific containers: One Docker image per language (openjdk:17-slim, python:3.11-slim, gcc:12). Images are pre-pulled and cached on executor nodes.

Compile step: For compiled languages (Java, C++), compile first in a separate container run, check for compile errors, then run the binary in a second container run for each test case.

✅E — Evaluate3 min

  • Runtime fairness: Container overhead varies. Measure wall-clock time inside the container using language-native timing, not externally. Run on dedicated hardware (no noisy neighbors).
  • Test case isolation: Each test case runs in a fresh container state — stateful code between test cases is not allowed. Reset container or use new container per test case.
  • Escape vulnerability: Container escapes are rare but possible. Use gVisor (user-space kernel) as an additional isolation layer for untrusted code.

🚀D — Deliver2 min

We designed a code judge handling 100K submissions/day with full sandboxing. Key decisions: Docker containers with CPU/memory/network limits for security, Kafka job queue for async execution, pre-warmed container pool to minimize latency, per-language Docker images, and WebSocket for real-time result delivery.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
IsolationDocker + resource limitsVM per submissionDocker: faster startup (200ms vs 5s for VM), lower overhead. VM stronger isolation. For MAANG interviews Docker is acceptable answer.
Execution modelAsync queue (Kafka)Synchronous HTTPExecution can take up to 5s; synchronous HTTP would hold connections, limit concurrency, and fail on timeout. Queue handles bursts gracefully.
Result deliveryWebSocket pushClient pollingWebSocket delivers result immediately on completion (~1–5s); polling adds 1–2s average latency and wasteful requests
Container reusePre-warm pool, reset between runsNew container per submissionContainer startup adds 200ms. Pre-warm pool reduces this to near-zero. Reset (remove output files, kill stray processes) is fast.

☕Java Implementation

/**
 * SandboxedExecutor — runs user-submitted code in an isolated Docker container.
 * Enforces CPU, memory, network, and time limits. Never executes code on the host OS.
 */
public class SandboxedExecutor {

    private static final int TIME_LIMIT_BUFFER_MS = 1000; // extra buffer beyond problem's limit
    private static final String EXECUTOR_IMAGE_JAVA  = "openjdk:17-slim";
    private static final String EXECUTOR_IMAGE_PYTHON = "python:3.11-slim";

    /**
     * Executes compiled code in a sandboxed container against one test case.
     *
     * @param language       "java", "python", "cpp"
     * @param codeFilePath   path to compiled binary or source on executor host
     * @param stdinInput     test case input
     * @param timeLimitMs    problem's time limit in milliseconds
     * @param memoryLimitMb  problem's memory limit in megabytes
     * @return ExecutionResult with stdout, stderr, runtime, status
     */
    public ExecutionResult execute(String language, String codeFilePath,
                                   String stdinInput, int timeLimitMs, int memoryLimitMb) {
        String dockerImage = resolveDockerImage(language);
        int timeoutSeconds = (timeLimitMs + TIME_LIMIT_BUFFER_MS) / 1000;

        // Build the Docker run command with all security constraints
        List<String> dockerCommand = buildDockerCommand(
            dockerImage, codeFilePath, memoryLimitMb, timeoutSeconds, language
        );

        try {
            ProcessBuilder processBuilder = new ProcessBuilder(dockerCommand);
            processBuilder.redirectErrorStream(false);
            Process dockerProcess = processBuilder.start();

            // Write stdin to the container
            try (OutputStream stdinStream = dockerProcess.getOutputStream()) {
                stdinStream.write(stdinInput.getBytes());
            }

            long executionStartMs = System.currentTimeMillis();
            boolean completedInTime = dockerProcess.waitFor(timeoutSeconds + 1, TimeUnit.SECONDS);
            long runtimeMs = System.currentTimeMillis() - executionStartMs;

            if (!completedInTime) {
                dockerProcess.destroyForcibly();
                return ExecutionResult.timeLimitExceeded(runtimeMs);
            }

            String stdout = readStream(dockerProcess.getInputStream());
            String stderr = readStream(dockerProcess.getErrorStream());
            int exitCode = dockerProcess.exitValue();

            return buildExecutionResult(exitCode, stdout, stderr, runtimeMs, timeLimitMs);

        } catch (IOException ioException) {
            throw new RuntimeException("[SandboxedExecutor.execute] Docker invocation failed", ioException);
        } catch (InterruptedException interruptedException) {
            Thread.currentThread().interrupt();
            throw new RuntimeException("[SandboxedExecutor.execute] Interrupted", interruptedException);
        }
    }

    private List<String> buildDockerCommand(String image, String codeFilePath,
                                              int memoryLimitMb, int timeoutSeconds, String language) {
        return List.of(
            "docker", "run",
            "--rm",                                          // auto-remove container on exit
            "--network=none",                                // no network access
            "--cpus=1",                                      // one CPU core max
            "--memory=" + memoryLimitMb + "m",              // hard memory limit
            "--memory-swap=" + memoryLimitMb + "m",         // no swap (swap would allow memory bypass)
            "--read-only",                                   // read-only root filesystem
            "--tmpfs=/tmp:size=64m",                         // writable /tmp only
            "--security-opt=no-new-privileges",              // prevent privilege escalation
            "--user=1000:1000",                              // run as non-root
            "-v", codeFilePath + ":/code:ro",               // mount code read-only
            image,
            buildRunCommand(language)
        );
    }

    private String buildRunCommand(String language) {
        return switch (language) {
            case "python" -> "python3 /code/solution.py";
            case "java"   -> "java -cp /code Main";
            case "cpp"    -> "/code/solution";
            default -> throw new IllegalArgumentException("Unsupported language: " + language);
        };
    }

    private String resolveDockerImage(String language) {
        return switch (language) {
            case "java"   -> EXECUTOR_IMAGE_JAVA;
            case "python" -> EXECUTOR_IMAGE_PYTHON;
            default -> throw new IllegalArgumentException("Unsupported language: " + language);
        };
    }

    private ExecutionResult buildExecutionResult(int exitCode, String stdout,
                                                  String stderr, long runtimeMs, int timeLimitMs) {
        if (runtimeMs > timeLimitMs) return ExecutionResult.timeLimitExceeded(runtimeMs);
        if (exitCode != 0)           return ExecutionResult.runtimeError(stderr, runtimeMs);
        return ExecutionResult.success(stdout, runtimeMs);
    }

    private String readStream(InputStream inputStream) throws IOException {
        return new String(inputStream.readAllBytes());
    }
}
