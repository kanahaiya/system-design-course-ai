Tier 2 — Should Know 45 min Ultra-low latency

Design a Stock Exchange

A stock exchange has the strictest latency requirements of any system: order matching must complete in <1ms. The core data structure — the order book — is two priority queues. The matching engine processes orders sequentially (single-threaded) to ensure strict price-time priority.

🏢 Nasdaq, NYSE, Robinhood
⏱️ 45 min interview
⚡ <1ms matching

❓R — Requirements3–5 min

Functional Requirements

  • Place orders: limit orders (price specified) and market orders (execute at best available price)
  • Cancel orders
  • Match buy and sell orders when bid price ≥ ask price
  • Real-time market data feed: price, volume, order book depth
  • Trade history: list of executed trades per symbol

Non-Functional Requirements

  • Latency: Order matching <1ms p99 (hardware-level engineering required)
  • Throughput: 100K orders/sec per symbol at peak
  • Fairness: Price-time priority — first order at a price level executes first
  • Durability: No order loss; persist to WAL before acknowledging

🔢E — Estimation3–5 min

  • NYSE: ~20B shares/day, 3,000 symbols → avg 7M trades/day per symbol
  • Peak: 100K orders/sec for hot symbols (AAPL, TSLA)
  • Order book depth: typically 10–50 price levels → fits entirely in L1/L2 CPU cache for hot symbols
  • Market data fan-out: 100K subscribers × 100K updates/sec = 10B messages/sec → multicast or specialized market data infrastructure

🗄️S — Schema3–5 min

🏗️H — High-level Design10 min

  • Order Gateway: Accepts orders via FIX protocol (financial industry standard) or REST. Validates, writes to WAL, forwards to matching engine via ring buffer (LMAX Disruptor pattern).
  • Matching Engine: Single-threaded (no locks, no contention). Processes orders from ring buffer sequentially. Maintains in-memory order book per symbol. Emits trade events.
  • Market Data Publisher: Receives trade events. Distributes via multicast UDP or Kafka to market data consumers (trading terminals, algos).
  • Trade Store: Consumes trade events. Persists to append-only trade log (PostgreSQL or time-series DB).
  • Risk Engine: Pre-trade validation. Checks margin, position limits before order reaches matching engine. Runs on order arrival, <100μs latency requirement.

🔬D — Deep Dive: Order Book Data Structure10 min

The order book consists of two sorted collections:

  • Bids (buy orders): Max-heap by price. Best bid = highest price.
  • Asks (sell orders): Min-heap by price. Best ask = lowest price.

Matching logic: After inserting an order, check if best bid ≥ best ask. If yes: match. Trade executes at the resting order's price (the order already in the book). Repeat until no match.

Price-time priority within a price level: A simple heap doesn't give time priority at the same price. Use a TreeMap<Price, Queue<Order>> where orders at the same price are queued FIFO. This gives O(log N) price navigation and O(1) within a price level.

Why single-threaded? Any concurrent modification to the order book requires locks, adding latency and complexity. A single-threaded matching engine processes 500K+ orders/sec on modern hardware (ring buffer eliminates IPC overhead). Correctness is trivial; no race conditions possible.

✅E — Evaluate3 min

  • Partial fills: If a buy order for 100 shares matches a sell order for 60 shares: trade executes for 60, buy order becomes partially filled (40 remaining). The remainder stays in the book.
  • Disaster recovery: WAL (Write-Ahead Log) on NVMe SSD. On crash, replay WAL to rebuild in-memory order book. Target: <5 minute recovery time.
  • Hot backup: Primary matching engine streams state to a hot standby. Failover in <1s (sub-millisecond switchover for co-located primary/backup).

🚀D — Deliver2 min

We designed a stock exchange with <1ms order matching. Key decisions: single-threaded matching engine (no lock contention), TreeMap+FIFO queue order book for price-time priority, LMAX Disruptor ring buffer for zero-GC order delivery, WAL for durability, and UDP multicast for low-latency market data distribution.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Matching engine threadingSingle-threadedMulti-threaded with locksNo locking = no contention. Single-threaded easily achieves 500K orders/sec. Multi-threaded complexity for no benefit on this workload.
Order book structureTreeMap + FIFO queue per price levelSimple PriorityQueuePriorityQueue gives best price but no time-ordering within a level. TreeMap + Queue gives O(log N) price + O(1) FIFO within price level — required for price-time priority.
Market data distributionUDP multicastKafka to subscribersUDP multicast: one packet, delivered to all subscribers simultaneously, sub-microsecond additional latency. Kafka adds 5ms+ — unacceptable for HFT consumers.
IPC to matching engineLMAX Disruptor ring bufferConcurrentLinkedQueueDisruptor uses mechanical sympathy (cache-line friendly, no GC allocation) achieving 25M messages/sec. ConcurrentLinkedQueue uses CAS and heap allocation — orders of magnitude slower.

☕Java Implementation

/**
 * OrderBook — in-memory matching engine for one trading symbol.
 * Uses TreeMap<Price, Deque<Order>> for price-time priority matching.
 * Single-threaded: called only from the matching engine thread.
 */
public class OrderBook {

    private final String symbol;
    // Buy orders: sorted descending by price (highest bid first)
    private final TreeMap<Long, Deque<Order>> bids = new TreeMap<>(Comparator.reverseOrder());
    // Sell orders: sorted ascending by price (lowest ask first)
    private final TreeMap<Long, Deque<Order>> asks = new TreeMap<>();

    private final List<Trade> executedTrades = new ArrayList<>();

    public OrderBook(String symbol) {
        this.symbol = symbol;
    }

    /**
     * Adds a limit order to the book and immediately attempts matching.
     * Returns list of trades generated by this order.
     */
    public List<Trade> addLimitOrder(Order incomingOrder) {
        executedTrades.clear();

        if (incomingOrder.getSide() == Side.BUY) {
            matchBuyOrder(incomingOrder);
            if (incomingOrder.getRemainingQuantity() > 0) {
                addToBook(bids, incomingOrder.getPriceTicks(), incomingOrder);
            }
        } else {
            matchSellOrder(incomingOrder);
            if (incomingOrder.getRemainingQuantity() > 0) {
                addToBook(asks, incomingOrder.getPriceTicks(), incomingOrder);
            }
        }

        return List.copyOf(executedTrades);
    }

    /**
     * Matches an incoming buy order against resting asks.
     * Executes at the resting ask's price (price-improvement for the buyer).
     */
    private void matchBuyOrder(Order buyOrder) {
        while (buyOrder.getRemainingQuantity() > 0 && !asks.isEmpty()) {
            Map.Entry<Long, Deque<Order>> bestAskEntry = asks.firstEntry();
            long bestAskPrice = bestAskEntry.getKey();

            if (buyOrder.getPriceTicks() < bestAskPrice) {
                break; // No match: buyer's max price below best ask
            }

            Order restingSellOrder = bestAskEntry.getValue().peekFirst();
            long tradeQuantity = Math.min(buyOrder.getRemainingQuantity(), restingSellOrder.getRemainingQuantity());
            long tradePrice = restingSellOrder.getPriceTicks(); // resting order's price

            executedTrades.add(new Trade(symbol, buyOrder.getOrderId(), restingSellOrder.getOrderId(),
                                         tradePrice, tradeQuantity));

            buyOrder.fill(tradeQuantity);
            restingSellOrder.fill(tradeQuantity);

            if (restingSellOrder.getRemainingQuantity() == 0) {
                bestAskEntry.getValue().pollFirst();
                if (bestAskEntry.getValue().isEmpty()) {
                    asks.pollFirstEntry();
                }
            }
        }
    }

    private void matchSellOrder(Order sellOrder) {
        while (sellOrder.getRemainingQuantity() > 0 && !bids.isEmpty()) {
            Map.Entry<Long, Deque<Order>> bestBidEntry = bids.firstEntry();
            long bestBidPrice = bestBidEntry.getKey();

            if (sellOrder.getPriceTicks() > bestBidPrice) {
                break; // No match: seller's min price above best bid
            }

            Order restingBuyOrder = bestBidEntry.getValue().peekFirst();
            long tradeQuantity = Math.min(sellOrder.getRemainingQuantity(), restingBuyOrder.getRemainingQuantity());
            long tradePrice = restingBuyOrder.getPriceTicks();

            executedTrades.add(new Trade(symbol, restingBuyOrder.getOrderId(), sellOrder.getOrderId(),
                                         tradePrice, tradeQuantity));

            sellOrder.fill(tradeQuantity);
            restingBuyOrder.fill(tradeQuantity);

            if (restingBuyOrder.getRemainingQuantity() == 0) {
                bestBidEntry.getValue().pollFirst();
                if (bestBidEntry.getValue().isEmpty()) {
                    bids.pollFirstEntry();
                }
            }
        }
    }

    private void addToBook(TreeMap<Long, Deque<Order>> book, long priceTicks, Order order) {
        book.computeIfAbsent(priceTicks, priceKey -> new ArrayDeque<>()).addLast(order);
    }

    public int getBidLevels() { return bids.size(); }
    public int getAskLevels() { return asks.size(); }
}
