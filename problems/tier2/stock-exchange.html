Tier 2 — Should Know 45 min Ultra-low latency

Design a Stock Exchange

A stock exchange has the strictest latency requirements of any system: order matching must complete in <100 microseconds. The core data structure — the order book — is two priority queues. The matching engine processes orders sequentially (single-threaded) for strict price-time priority with no lock contention.

🏢 Nasdaq, NYSE, Robinhood
⏱️ 45 min interview
⚡ <100μs matching

❓R — Requirements3–5 min

Functional Requirements

  • Place orders: limit (price specified), market (fill at best price), stop-loss (trigger when price crosses threshold)
  • Cancel open orders
  • Match buy and sell orders when bid price ≥ ask price — price-time priority
  • Real-time market data feed: last trade price, bid/ask, volume, order book depth
  • Trade history: list of executed trades per symbol
  • Account management: portfolio positions, P&L, trade confirmations

Non-Functional Requirements

  • Latency: Order matching <100 microseconds p99 (hardware-level engineering required for HFT)
  • Throughput: 100K orders/sec per symbol at peak (AAPL, TSLA during market open)
  • Fairness: Price-time priority — first order at a price level executes first
  • Durability: No order loss; persist to WAL before acknowledging any order
  • Audit: Every order, trade, and cancel is immutably recorded for compliance (SEC requires 7-year retention)
L6 depth signal: Mention event sourcing proactively. "The order book state is derived from an event log — every order and trade is an immutable event. We can reconstruct the order book at any point in time by replaying the log. This is critical for compliance and crash recovery."

🔢E — Estimation3–5 min

  • NYSE: ~20B shares/day across 3,000 symbols → ~7M trades/day; peak 100K orders/sec for hot symbols
  • Order book depth: typically 10–50 price levels → entire book fits in L1/L2 CPU cache (64KB) for hot symbols — this is intentional
  • Market data fan-out: 100K updates/sec × 100K subscribers = 10B messages/sec → requires multicast UDP, not unicast
  • WAL writes: 100K orders/sec × 200 bytes/order = 20MB/sec → NVMe SSD absorbs this easily, with fsync batching
  • Settlement: T+2 means 2B shares × avg $100/share = $200B in-flight at DTCC daily

🏗️H — High-level Design10 min

  • Order Gateway: Accepts orders via FIX protocol (financial industry standard) or REST. Validates, writes to WAL (NVMe SSD, fsync), forwards to matching engine via LMAX Disruptor ring buffer (zero-GC, lock-free IPC).
  • Risk Engine (pre-trade): Runs on every incoming order. Checks: account has sufficient funds/shares, order size within limits, no wash trading. Target: <100μs. In the same JVM process as the matching engine to avoid network round-trip.
  • Matching Engine: Single-threaded (no locks, no contention). Processes orders from ring buffer sequentially. Maintains in-memory order book per symbol. Emits trade events to output ring buffer.
  • Market Data Publisher: Receives trade and order book delta events. Distributes via UDP multicast to subscribers (trading terminals, algos). One UDP packet → delivered to thousands of subscribers by network infrastructure simultaneously.
  • Trade Store: Consumes trade events from output ring buffer. Persists to append-only PostgreSQL trade log. Also feeds position updates to Account Service.
  • Settlement Service: Batches trades for T+2 settlement. Submits to DTCC (Depository Trust & Clearing Corporation). Handles stock and cash movements.
  • Circuit Breaker: Monitors price movement rate per symbol. If price moves >5% in 5 minutes → halt trading for that symbol for 5 minutes. Prevents "flash crash" cascades.

🔬D — Deep Dive: Order Book, Matching, and Latency10 min

Order Book Data Structure

Figure: Order book — bids sorted descending (highest buy price first), asks sorted ascending (lowest sell price first)

Order Types and Matching Logic

// LIMIT order: fill only at specified price or better
// Incoming BUY limit at $150.52: best ask = $150.52 → match at $150.52 (ask's price, price improvement for buyer)
// Incoming BUY limit at $150.51: best ask = $150.52 → no match (bid < ask) → rest in book

// MARKET order: fill immediately at best available price(s)
// Incoming BUY market: takes the best ask ($150.52, 300 shares)
//   If market order qty > 300: takes next ask ($150.53, 600 shares), then next, until filled
//   Risk: "market impact" — large market orders move the price adversely

// STOP-LOSS order: passive until trigger price crossed, then converts to market
// STOP-LOSS SELL at $150.40: sits dormant; if last trade price hits $150.40 or below,
//   it activates and immediately becomes a market sell order

// Price-time priority within a price level:
// Multiple sell orders at $150.52: $150.52 first FIFO (first posted = first matched)
// TreeMap key = price level; Deque value = FIFO queue of orders at that price
// O(log P) to find price level (P = number of distinct price levels, typically 10-50)
// O(1) to dequeue the front order at a price level

Matching Algorithm — Single-Threaded Design

// Why single-threaded? Any concurrent modification to the order book
// requires locks. Every lock acquisition = potential cache miss + OS scheduling.
// A single-threaded engine with a ring buffer achieves 500K+ orders/sec on modern
// hardware without any contention. Correctness is trivially guaranteed.

// LMAX Disruptor ring buffer: pre-allocated fixed-size array of event slots
// Producer (Order Gateway) writes to ring buffer: no allocation, no GC
// Consumer (Matching Engine) reads from ring buffer: cache-line friendly access
// Throughput: 25M events/sec vs 2M for ConcurrentLinkedQueue

public class MatchingEngine implements Runnable {
    private final Map<String, OrderBook> orderBooks = new HashMap<>();
    private final RingBuffer<OrderEvent> inputRingBuffer;  // from Order Gateway
    private final RingBuffer<TradeEvent> outputRingBuffer; // to Market Data Publisher

    @Override
    public void run() {
        // Pin this thread to a specific CPU core (CPU affinity)
        // Prevents OS from migrating thread = no cache invalidation on core switch
        while (true) {
            OrderEvent event = inputRingBuffer.poll(); // non-blocking, spins on empty
            if (event != null) {
                processOrder(event);
            }
        }
    }

    private void processOrder(OrderEvent event) {
        OrderBook book = orderBooks.computeIfAbsent(event.getSymbol(), OrderBook::new);
        List<Trade> trades = switch (event.getOrderType()) {
            case LIMIT  -> book.addLimitOrder(event.toOrder());
            case MARKET -> book.addMarketOrder(event.toOrder());
            case CANCEL -> book.cancelOrder(event.getOrderId());
        };
        // Emit trades and book deltas to market data output ring buffer
        for (Trade trade : trades) {
            outputRingBuffer.publish(TradeEvent.from(trade));
        }
    }
}

Event Sourcing for Compliance and Recovery

// Event sourcing: the order book is not stored — it is DERIVED from events
// Every incoming order is first written to the WAL (Write-Ahead Log)
// On crash: replay all WAL events to rebuild exact order book state

// WAL format (binary, NVMe SSD, fsync every batch)
// [8 bytes] event_id  [1 byte] type  [10 bytes] symbol
// [8 bytes] order_id  [1 byte] side  [8 bytes] price_ticks
// [8 bytes] quantity  [8 bytes] account_id  [8 bytes] timestamp_ns
// = 62 bytes per event, fits in one cache line (64 bytes)

// Recovery procedure on restart:
// 1. Open WAL file
// 2. For each event in order:
//    - ORDER_PLACED: add to order book
//    - ORDER_CANCELLED: remove from order book
//    - TRADE_EXECUTED: update fill quantities
// 3. Order book is now identical to pre-crash state
// 4. Resume processing new orders

// Compliance: SEC requires 7-year retention of all order activity
// WAL segments archived to S3 (Parquet format, queryable via Athena)

Circuit Breakers and Risk Controls

/**
 * Monitors price velocity per symbol.
 * Halts trading if price moves more than 5% in 5 minutes (flash crash prevention).
 */
public class CircuitBreaker {

    private static final double HALT_THRESHOLD_PERCENT = 5.0;
    private static final int MONITORING_WINDOW_MINUTES = 5;
    private static final int HALT_DURATION_MINUTES = 5;

    // Sliding window of trade prices per symbol
    private final Map<String, Deque<PriceSnapshot>> priceHistory = new ConcurrentHashMap<>();
    private final Map<String, Instant> haltedUntil = new ConcurrentHashMap<>();

    /**
     * Called on every trade execution. Returns true if trading should halt.
     */
    public boolean shouldHalt(String symbol, long tradePriceTicks) {
        Instant haltedUntilTime = haltedUntil.get(symbol);
        if (haltedUntilTime != null && Instant.now().isBefore(haltedUntilTime)) {
            return true; // still in halt period
        }

        Deque<PriceSnapshot> history = priceHistory.computeIfAbsent(
            symbol, s -> new ArrayDeque<>());

        history.addLast(new PriceSnapshot(tradePriceTicks, Instant.now()));

        // Remove snapshots older than 5 minutes
        Instant windowStart = Instant.now().minusSeconds(MONITORING_WINDOW_MINUTES * 60L);
        while (!history.isEmpty() && history.peekFirst().getTimestamp().isBefore(windowStart)) {
            history.pollFirst();
        }

        if (history.size() < 2) {
            return false; // not enough data
        }

        long firstPrice = history.peekFirst().getPriceTicks();
        double priceChangePct = Math.abs((double)(tradePriceTicks - firstPrice) / firstPrice * 100);

        if (priceChangePct >= HALT_THRESHOLD_PERCENT) {
            haltedUntil.put(symbol, Instant.now().plusSeconds(HALT_DURATION_MINUTES * 60L));
            return true; // halt this symbol
        }

        return false;
    }
}

// Pre-trade risk check (runs before every order reaches matching engine):
public class RiskEngine {
    public RiskCheckResult checkOrder(Order order, AccountPosition position) {
        // 1. Sufficient funds/shares
        if (order.getSide() == Side.BUY) {
            long requiredCash = order.getPriceTicks() * order.getQuantity();
            if (position.getCashBalance() < requiredCash) {
                return RiskCheckResult.reject("Insufficient funds");
            }
        } else {
            if (position.getSharesHeld(order.getSymbol()) < order.getQuantity()) {
                return RiskCheckResult.reject("Insufficient shares");
            }
        }
        // 2. Order size limits (prevent fat-finger errors)
        if (order.getQuantity() > 1_000_000) {
            return RiskCheckResult.reject("Order exceeds size limit");
        }
        // 3. No wash trading (buy and sell same symbol from same account)
        // (additional checks omitted for brevity)
        return RiskCheckResult.approved();
    }
}

Settlement — T+2

NYSE and NASDAQ use T+2 settlement (SEC regulation SHO): a trade executed today settles 2 business days later. This means:

  • Buyer has 2 days to deliver cash; seller has 2 days to deliver shares
  • DTCC (Depository Trust & Clearing Corporation) acts as central counterparty — nets all trades across all brokers to minimize actual cash and share movements
  • If a broker fails to deliver ("fails to deliver"), DTCC invokes buy-in procedures
  • In our system: trades are held in a settlement queue. A batch job at 5pm EST creates net obligations per broker and submits to DTCC API

✅E — Evaluate3 min

  • Partial fills: Buy 100 shares, best ask has 60 → trade executes for 60, buy order becomes partially filled (40 remaining). Remainder stays in book. Market order continues to consume next price levels until filled or book exhausted.
  • Disaster recovery: WAL on NVMe SSD with fsync batching. On crash, replay WAL to rebuild in-memory order book. Target <5 minute recovery. For faster recovery: weekly snapshot of order book state reduces WAL replay to events since last snapshot.
  • Hot backup (sub-second failover): Primary matching engine streams state changes to a hot standby on the same machine via shared memory. On primary failure, standby takes over in <1 second with all orders intact.
  • GC pauses: JVM GC can cause >100ms pauses — catastrophic for a <100μs latency target. Mitigation: use pre-allocated object pools (no heap allocation in hot path), or switch to off-heap memory (Unsafe), or use GraalVM native image (no JVM GC).

🚀D — Deliver2 min

We designed a stock exchange with <100μs order matching. Key decisions: single-threaded matching engine (no lock contention), TreeMap+FIFO Deque order book for price-time priority, LMAX Disruptor ring buffer for zero-GC IPC, WAL-based event sourcing for compliance and crash recovery, pre-trade risk checks preventing bad orders, circuit breakers halting trading on 5%+ price moves, and UDP multicast for sub-microsecond market data distribution to HFT subscribers.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Matching engine threading Single-threaded Multi-threaded with locks No locking = no contention, no cache invalidation, deterministic ordering. Single-threaded achieves 500K orders/sec. Multi-threading adds 5–50μs of lock overhead per order — unacceptable at <100μs target.
Order book structure TreeMap<Price, Deque<Order>> Simple PriorityQueue<Order> PriorityQueue gives best price but no time-ordering within a price level. TreeMap + FIFO Deque gives O(log P) price access + O(1) FIFO at each level. Required for price-time priority compliance.
Order book persistence Event sourcing (WAL replay) Snapshot order book to DB every N orders Event log is the compliance record anyway. Rebuilding from events is auditable and deterministic. Snapshots introduce complexity (snapshot consistency, incremental updates). Events are simpler and satisfy both recovery and compliance.
Market data distribution UDP multicast Kafka to HFT subscribers UDP multicast: one packet delivered simultaneously to all subscribers by network infrastructure, sub-microsecond additional latency. Kafka adds 5–50ms through broker polling — catastrophic for HFT algorithms.
IPC to matching engine LMAX Disruptor ring buffer ConcurrentLinkedQueue Disruptor: pre-allocated, cache-line optimized, lock-free with CAS, 25M events/sec. ConcurrentLinkedQueue: heap allocations (GC pressure), CAS contention, ~5M events/sec max.

☕Java Implementation

/**
 * @file OrderBook.java
 * @description In-memory matching engine for one trading symbol.
 *              Uses TreeMap<Long, Deque<Order>> for price-time priority matching.
 *              Single-threaded: called only from the matching engine thread.
 *
 * Public API:
 *   addLimitOrder(order) — insert limit order, attempt matching, return trades
 *   addMarketOrder(order) — execute against best available prices, return trades
 *   cancelOrder(orderId) — remove from book, return cancelled order
 */
public class OrderBook {

    private final String symbol;
    // Buy orders: sorted descending by price (highest bid first)
    private final TreeMap<Long, Deque<Order>> bids = new TreeMap<>(Comparator.reverseOrder());
    // Sell orders: sorted ascending by price (lowest ask first)
    private final TreeMap<Long, Deque<Order>> asks = new TreeMap<>();
    // For O(1) order lookup by orderId (for cancellation)
    private final Map<Long, Order> orderIndex = new HashMap<>();

    public OrderBook(String symbol) {
        this.symbol = symbol;
    }

    /**
     * Inserts a limit order and immediately attempts to match against resting orders.
     * Unfilled remainder is added to the book.
     *
     * @param incomingOrder the new limit order
     * @return list of trades generated (may be empty if no match)
     */
    public List<Trade> addLimitOrder(Order incomingOrder) {
        List<Trade> trades = new ArrayList<>();

        if (incomingOrder.getSide() == Side.BUY) {
            matchBuyAgainstAsks(incomingOrder, trades);
            if (incomingOrder.getRemainingQuantity() > 0) {
                addToBook(bids, incomingOrder);
            }
        } else {
            matchSellAgainstBids(incomingOrder, trades);
            if (incomingOrder.getRemainingQuantity() > 0) {
                addToBook(asks, incomingOrder);
            }
        }

        return trades;
    }

    /**
     * Executes a market order against all available resting orders.
     * Consumes as many price levels as needed until order is filled or book exhausted.
     */
    public List<Trade> addMarketOrder(Order marketOrder) {
        List<Trade> trades = new ArrayList<>();
        if (marketOrder.getSide() == Side.BUY) {
            matchBuyAgainstAsks(marketOrder, trades);
        } else {
            matchSellAgainstBids(marketOrder, trades);
        }
        // Market order never rests in book — filled or cancelled if insufficient liquidity
        return trades;
    }

    /**
     * Cancels an open order by removing it from its price level.
     */
    public Order cancelOrder(long orderId) {
        Order order = orderIndex.remove(orderId);
        if (order == null) {
            return null; // already filled or cancelled
        }
        TreeMap<Long, Deque<Order>> book = order.getSide() == Side.BUY ? bids : asks;
        Deque<Order> priceLevel = book.get(order.getPriceTicks());
        if (priceLevel != null) {
            priceLevel.remove(order);
            if (priceLevel.isEmpty()) {
                book.remove(order.getPriceTicks());
            }
        }
        return order;
    }

    /**
     * Matches an incoming buy order against resting asks.
     * Trade executes at the resting ask's price (price improvement for buyer).
     */
    private void matchBuyAgainstAsks(Order buyOrder, List<Trade> trades) {
        while (buyOrder.getRemainingQuantity() > 0 && !asks.isEmpty()) {
            Map.Entry<Long, Deque<Order>> bestAskEntry = asks.firstEntry();
            long bestAskPrice = bestAskEntry.getKey();

            // Limit order: only match if buyer's max price >= best ask
            if (buyOrder.getOrderType() == OrderType.LIMIT &&
                buyOrder.getPriceTicks() < bestAskPrice) {
                break;
            }

            Order restingSell = bestAskEntry.getValue().peekFirst();
            long tradeQty = Math.min(buyOrder.getRemainingQuantity(),
                                     restingSell.getRemainingQuantity());

            trades.add(buildTrade(buyOrder, restingSell, bestAskPrice, tradeQty));

            buyOrder.fill(tradeQty);
            restingSell.fill(tradeQty);

            if (restingSell.getRemainingQuantity() == 0) {
                bestAskEntry.getValue().pollFirst();
                orderIndex.remove(restingSell.getOrderId());
                if (bestAskEntry.getValue().isEmpty()) {
                    asks.pollFirstEntry();
                }
            }
        }
    }

    private void matchSellAgainstBids(Order sellOrder, List<Trade> trades) {
        while (sellOrder.getRemainingQuantity() > 0 && !bids.isEmpty()) {
            Map.Entry<Long, Deque<Order>> bestBidEntry = bids.firstEntry();
            long bestBidPrice = bestBidEntry.getKey();

            if (sellOrder.getOrderType() == OrderType.LIMIT &&
                sellOrder.getPriceTicks() > bestBidPrice) {
                break;
            }

            Order restingBuy = bestBidEntry.getValue().peekFirst();
            long tradeQty = Math.min(sellOrder.getRemainingQuantity(),
                                     restingBuy.getRemainingQuantity());

            trades.add(buildTrade(restingBuy, sellOrder, bestBidPrice, tradeQty));

            sellOrder.fill(tradeQty);
            restingBuy.fill(tradeQty);

            if (restingBuy.getRemainingQuantity() == 0) {
                bestBidEntry.getValue().pollFirst();
                orderIndex.remove(restingBuy.getOrderId());
                if (bestBidEntry.getValue().isEmpty()) {
                    bids.pollFirstEntry();
                }
            }
        }
    }

    private void addToBook(TreeMap<Long, Deque<Order>> book, Order order) {
        book.computeIfAbsent(order.getPriceTicks(), price -> new ArrayDeque<>())
            .addLast(order);  // FIFO within price level = time priority
        orderIndex.put(order.getOrderId(), order);
    }

    private Trade buildTrade(Order buyOrder, Order sellOrder, long priceTicks, long qty) {
        return new Trade(symbol, buyOrder.getOrderId(), sellOrder.getOrderId(),
                         priceTicks, qty, System.nanoTime());
    }

    public long getBestBidTicks() {
        return bids.isEmpty() ? 0L : bids.firstKey();
    }

    public long getBestAskTicks() {
        return asks.isEmpty() ? Long.MAX_VALUE : asks.firstKey();
    }

    public int getBidLevels() { return bids.size(); }
    public int getAskLevels() { return asks.size(); }
}
