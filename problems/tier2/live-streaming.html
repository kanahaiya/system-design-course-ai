Design Live Video Streaming (Twitch)

Live streaming differs from VOD in one key way: content is generated in real-time and must reach viewers within seconds. Standard HLS has 30s latency. Low-Latency HLS (LLHLS) cuts this to 2–3s using smaller segment sizes and push delivery.

🏢 Twitch, YouTube Live, Instagram
⏱️ 45 min interview
📡 <5s latency

❓R — Requirements3–5 min

Functional Requirements

  • Broadcaster streams live video via RTMP from OBS/mobile
  • Viewers watch the live stream at adaptive quality (720p/1080p/4K)
  • Live chat alongside the stream
  • Viewer count display (real-time)
  • Stream recording and VOD playback after stream ends

Non-Functional Requirements

  • Latency: <5s glass-to-glass (broadcaster camera → viewer screen)
  • Scale: 10M concurrent viewers, 100K concurrent streams
  • Availability: 99.99% — stream drops are catastrophic for viewer retention

🔢E — Estimation3–5 min

  • 100K streams × 4 Mbps ingest = 400 Gbps ingest bandwidth
  • 10M concurrent viewers × 2.5 Mbps avg = 25 Tbps egress → CDN essential
  • Transcoding: 100K streams × 3 quality tiers = 300K concurrent encode jobs → GPU cluster
  • Chat: 10M concurrent users in chat; avg 100 msg/min per channel → 1B msg/min at peak → Kafka fan-out essential

🗄️S — Schema3–5 min

streams: stream_id, user_id, title, is_live, viewer_count,
         rtmp_ingest_url, hls_playlist_url, started_at

// Segments stored in object storage (S3) with short TTL for live, long TTL for VOD
// Key: streams/{streamId}/{quality}/{segmentNumber}.ts
// Manifest: streams/{streamId}/{quality}/playlist.m3u8 (updated every 2s)

// Chat messages (Redis for live; Cassandra for history)
// Redis list per channel: LPUSH + LTRIM to keep last 100 messages
// Cassandra for full history with partition by stream_id

🏗️H — High-level Design10 min

  • RTMP Ingest Servers: Broadcaster connects via RTMP. Ingest server receives raw video stream. RTMP is TCP-based, reliable, <1s buffer.
  • Transcoding Farm: Ingest server sends raw stream to transcoding cluster. FFmpeg/GPU-based real-time encoding to 360p/720p/1080p simultaneously. Outputs HLS segments every 2s.
  • Segment Storage: Segments written to S3 as they complete. Manifest file (playlist.m3u8) updated every 2s with new segment URL.
  • CDN: Viewers fetch manifest + segments from CDN edge. Edge pulls from origin (S3) on first request, caches subsequent. Live segments have 5s TTL (just long enough to cache but not stale).
  • Chat: WebSocket connections to chat servers. Redis Pub/Sub for cross-server fan-out (same as Slack design). Messages persisted to Cassandra.
  • Viewer Count: Increment Redis counter on viewer connect; decrement on disconnect. Broadcast updated count via WebSocket every 5s.

🔌A — APIs5 min

POST /v1/streams/start              // broadcaster starts stream → returns RTMP ingest URL
POST /v1/streams/{streamId}/end     // end stream
GET  /v1/streams/{streamId}/watch   // returns HLS manifest URL + chat WebSocket URL
GET  /v1/streams/live?category={}&limit=20  // discover live streams
// WebSocket /ws/chat/{streamId}   // real-time chat

🔬D — Deep Dive: Low-Latency HLS (LLHLS)10 min

Standard HLS latency: 6 segments × 5s each = 30s latency from broadcast to viewer.

Low-Latency HLS (Apple LLHLS, RFC 8216 extension):

  • Segment size reduced to 2s (was 5–10s)
  • Partial segments: CDN pushes partial segment data as it's being written (every 200ms). Client can start playing before the full 2s segment is complete.
  • Playlist update push: CDN uses HTTP/2 server push or long-poll to notify client of new playlist version — no client polling delay.

Result: 2–3s glass-to-glass latency vs 30s for standard HLS.

Trade-off: Smaller segments = more S3 write operations (1 per 2s per quality = 1.5 writes/sec per stream × 3 qualities × 100K streams = 450K writes/sec on S3).

✅E — Evaluate3 min

  • Transcoding bottleneck: Real-time transcoding requires GPU acceleration. A GPU can transcode ~10 streams simultaneously at 1080p. 100K streams need 10K GPUs — expensive. Twitch uses custom ASIC encoders for cost efficiency.
  • CDN cache for live: Live segments have very short TTL (live content changes every 2s). CDN hit rate is lower for live vs VOD — many viewers will hit origin. Use CDN with push model (transcoder pushes segments to CDN proactively) rather than pull-on-miss.

🚀D — Deliver2 min

We designed a live streaming system handling 10M concurrent viewers. Key decisions: RTMP ingest → real-time GPU transcoding → LLHLS (2s segments) → CDN push model for low latency, Redis Pub/Sub for live chat routing, and Redis counters for real-time viewer counts.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Ingest protocolRTMPWebRTCRTMP: widely supported by broadcast software (OBS, XSplit), TCP-based (reliable). WebRTC: lower latency but complex, no broad OBS support.
Delivery protocolLLHLSWebRTCLLHLS: CDN-compatible, scales to millions via HTTP infrastructure. WebRTC: sub-second latency but requires SFU servers, doesn't scale as cheaply via CDN.
CDN modelPush (transcoder pushes to CDN)Pull (CDN fetches on miss)Live segments: cache miss on every new segment causes origin spike. Push pre-populates CDN before viewers request — smoother delivery.

☕Java Implementation

/**
 * StreamIngestionPipeline — receives transcoded HLS segments,
 * writes to S3, updates the live manifest, and pushes to CDN.
 */
public class StreamIngestionPipeline {
    private final S3Client s3Client;
    private final CdnPushClient cdnPushClient;
    private final String bucketName;
    private static final int MANIFEST_MAX_SEGMENTS = 6; // keep last 6 segments in live manifest

    public StreamIngestionPipeline(S3Client s3Client, CdnPushClient cdnPushClient, String bucketName) {
        this.s3Client = s3Client;
        this.cdnPushClient = cdnPushClient;
        this.bucketName = bucketName;
    }

    /**
     * Called by the transcoder when a new 2-second segment is ready.
     * Writes segment to S3, updates manifest, pushes both to CDN.
     *
     * @param streamId       unique stream identifier
     * @param qualityLabel   e.g. "1080p", "720p", "360p"
     * @param segmentNumber  monotonically increasing segment sequence number
     * @param segmentData    raw .ts segment bytes
     */
    public void ingestSegment(String streamId, String qualityLabel, int segmentNumber, byte[] segmentData) {
        String segmentKey = buildSegmentKey(streamId, qualityLabel, segmentNumber);
        uploadSegmentToS3(segmentKey, segmentData);

        String manifestContent = buildLiveManifest(streamId, qualityLabel, segmentNumber);
        String manifestKey = buildManifestKey(streamId, qualityLabel);
        uploadManifestToS3(manifestKey, manifestContent);

        // Push to CDN proactively (push model — don't wait for viewer request)
        cdnPushClient.pushFile(segmentKey, segmentData);
        cdnPushClient.pushFile(manifestKey, manifestContent.getBytes());
    }

    /**
     * Builds an HLS manifest listing the last MANIFEST_MAX_SEGMENTS segments.
     * Only recent segments are listed — older ones are removed from the live window.
     */
    private String buildLiveManifest(String streamId, String qualityLabel, int latestSegmentNumber) {
        StringBuilder manifest = new StringBuilder();
        manifest.append("#EXTM3U\n");
        manifest.append("#EXT-X-VERSION:3\n");
        manifest.append("#EXT-X-TARGETDURATION:2\n");
        manifest.append("#EXT-X-MEDIA-SEQUENCE:").append(Math.max(0, latestSegmentNumber - MANIFEST_MAX_SEGMENTS + 1)).append("\n");

        int startSegment = Math.max(0, latestSegmentNumber - MANIFEST_MAX_SEGMENTS + 1);
        for (int segIndex = startSegment; segIndex <= latestSegmentNumber; segIndex++) {
            manifest.append("#EXTINF:2.0,\n");
            manifest.append(buildSegmentKey(streamId, qualityLabel, segIndex)).append("\n");
        }
        return manifest.toString();
    }

    private String buildSegmentKey(String streamId, String qualityLabel, int segmentNumber) {
        return "streams/" + streamId + "/" + qualityLabel + "/" + segmentNumber + ".ts";
    }

    private String buildManifestKey(String streamId, String qualityLabel) {
        return "streams/" + streamId + "/" + qualityLabel + "/playlist.m3u8";
    }

    private void uploadSegmentToS3(String key, byte[] data) {
        s3Client.putObject(builder -> builder.bucket(bucketName).key(key).contentType("video/MP2T"),
                           RequestBody.fromBytes(data));
    }

    private void uploadManifestToS3(String key, String content) {
        s3Client.putObject(builder -> builder.bucket(bucketName).key(key)
                               .contentType("application/vnd.apple.mpegurl")
                               .cacheControl("max-age=2"),  // short TTL for live content
                           RequestBody.fromString(content));
    }
}
