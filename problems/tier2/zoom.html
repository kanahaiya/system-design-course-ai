Tier 2 — Should Know 45 min Real-time Media

Design Zoom Video Conferencing

The N×M problem: how do you route audio and video between N participants without N² connections? The answer — SFU (Selective Forwarding Unit) — is the single most important concept in this interview.

🏢 Zoom, Google Meet, Microsoft Teams, Webex
⏱️ 45 min interview
📹 Real-time media / WebRTC
🧠 The Pipeline Mental Model

Video conferencing = a pipeline with 5 stages:

CAPTURE → ENCODE → TRANSPORT → DECODE → RENDER

Your camera produces raw frames. A codec (H.264, VP8) compresses them (10× to 100× size reduction). WebRTC transports the compressed packets over UDP/RTP. The receiver decodes them and renders to screen.

The central architecture question is in the TRANSPORT stage: how do you route N×M streams? With 10 participants, naively each needs 9 incoming streams and uploads 1 outgoing stream. That's 90 streams total in a peer mesh — each participant needs enough upload bandwidth to send to 9 peers simultaneously. At 720p (1.5 Mbps), that's 13.5 Mbps upload per person. Impossible on typical broadband.

SFU is the answer: Insert a server (the SFU) in the middle. Every participant uploads ONE stream. The SFU handles distribution. N participants = N uploads + N × (N-1) forward paths managed server-side. Clients are happy; server bears the routing cost.

❓R — Requirements3–5 min

Functional Requirements

  • 1-to-1 video call: two users with video + audio
  • Group call: up to 1,000 participants (webinar scale)
  • Screen sharing (shares a display capture instead of camera)
  • Chat (text messages) during a call
  • Cloud recording: save call to storage, generate transcript
  • Virtual background and noise cancellation (client-side, ML-based)
  • Waiting room, host controls (mute all, remove participant, lock meeting)

Non-Functional Requirements

  • Audio latency < 150ms — human perception threshold. Above 150ms, turn-taking breaks down and conversation feels like walkie-talkie.
  • Video latency < 200ms — above this, lip-sync issues become perceptible
  • Packet loss tolerance: call must remain intelligible at 5% packet loss (UDP has no retransmission)
  • Scale: 300M daily meeting participants (Zoom peak during COVID)
  • Availability: 99.95% — calls must not drop mid-meeting
  • Security: optional end-to-end encryption; minimum TLS + DTLS for media
🎯 What to Clarify in the Interview
  • Max meeting size: 10 people (standard), 100 (large), 1,000 (webinar)? Changes layout strategy dramatically.
  • E2E encryption: Only possible with mesh (server never sees media). With SFU, server decrypts to forward. Clarify which is required.
  • Recording: Client-side (user records locally) or server-side (SFU captures streams)? Server-side is complex but required for host-initiated recording.
  • Mobile vs desktop: Mobile has battery and bandwidth constraints — adaptive quality is more critical.

🔢E — Estimation3–5 min

  • Meeting joins: 300M daily participants ÷ 86,400 seconds = 3,500 joins/second average; 50K/second peak
  • Active meetings: average 30-min duration, 10 participants → ~3M concurrent meetings at peak
  • Per-participant bandwidth: 720p video = 1.5 Mbps + audio 64 kbps ≈ 1.6 Mbps upload
  • 10-person meeting streams:
    • Naive mesh: 10 × 9 = 90 streams; each participant uploads 9 × 1.6 Mbps = 14.4 Mbps → infeasible
    • SFU: each participant uploads 1.6 Mbps (once); SFU forwards adapted streams → feasible
  • SFU server capacity: 10-person meeting = 10 uploads × 1.6 Mbps = 16 Mbps inbound + 10 × 9 outbound streams = 144 Mbps outbound. One 40 Gbps SFU handles ~275 such meetings. 3M meetings need ~11,000 SFU servers globally.
  • TURN server capacity: 25% of users need TURN relay (behind symmetric NAT) → 75M users × 1.6 Mbps = 120 Tbps total relay bandwidth. This is why TURN is geographically distributed and is a major cost driver.
  • Signaling messages: join, leave, mute, unmute, ICE candidates → small text messages, ~50 per participant per meeting = 300M × 50 = 15B signaling messages/day, trivially handled by WebSocket servers.

💡 Two-Tier State Storage

Meeting metadata (who was in a meeting, duration, recording URL) goes to PostgreSQL — it's needed for billing, compliance, and history. Real-time state (who's currently muted, which SFU server each participant is on) goes to Redis — it's high-frequency, ephemeral, and must be sub-millisecond to read. Never mix them.

🏗️H — High-level Design10 min

The Core Architecture Decision: Mesh vs MCU vs SFU

SFU Architecture in Detail

Key Architectural Points

  • SFU does NOT decode: It reads RTP packet headers (destination, sequence number, SSRC) and forwards the payload unchanged. This is 10× cheaper than MCU which must decode every frame, composite them into a grid, and re-encode.
  • Simulcast: Each client sends 3 quality tiers simultaneously (360p, 720p, 1080p). SFU selects which tier to forward to each receiver based on their current bandwidth. Users on mobile data get 360p; fiber users get 1080p. The sender's CPU cost is ~50% higher but the receiver experience is dramatically better.
  • Active Speaker Detection: SFU monitors the audio energy (RTP audio level extension) from all participants. The dominant speaker's video is sent at highest quality to all others. Non-speakers get thumbnail quality (180p). This makes 1,000-person meetings feasible.
  • Cascaded SFU: Tokyo participant connects to Tokyo SFU (low latency). US participants connect to US SFU. The two SFUs are linked by a single private backbone connection per meeting. This is far more reliable than 3 Tokyo clients each individually tunneling to US.

🔬D — Deep Dive15 min

1. WebRTC — SDP Offer/Answer Exchange

WebRTC is the browser API that enables peer-to-peer (and SFU) media. The connection setup sequence:

  1. Client A generates SDP Offer: "I can send H.264 video at up to 720p, Opus audio at 48kHz. My network candidates are: [192.168.1.5:5004, 203.45.67.89:5004, turn:turn-us.zoom.us:443]"
  2. Signaling Server relays offer to SFU (the other "peer" in this setup)
  3. SFU generates SDP Answer: "I accept H.264 at 720p and Opus. Here are MY network candidates."
  4. ICE (Interactive Connectivity Establishment): Client and SFU exchange network candidates, test them in priority order: direct (LAN), STUN-resolved public IP, TURN relay. Best working path wins.
  5. DTLS Handshake: Once ICE path is established, a DTLS (UDP-based TLS) handshake secures the media channel.
  6. Media flows over SRTP (encrypted RTP) on the established UDP path.

2. STUN vs TURN — NAT Traversal

/**
 * STUN Server: helps a client behind NAT discover its public IP:port mapping.
 * "What is my public IP address?" — reflected address tells client what the world sees.
 * Almost no bandwidth (just a UDP echo request/response).
 * Works for ~75% of users (full-cone NAT, restricted-cone NAT).
 *
 * TURN Server: relay for clients behind symmetric NAT (strict firewalls).
 * Client sends media to TURN; TURN relays to SFU. SFU replies to TURN; TURN relays back.
 * Full bandwidth passes through TURN server — expensive to operate.
 * Required for ~25% of users (corporate firewalls, strict mobile carrier NAT).
 *
 * ICE strategy: try candidates in order (lowest cost to highest):
 *   1. Host (local IP:port) — works only if both on same LAN
 *   2. Server-reflexive (STUN-discovered public IP:port) — works if no symmetric NAT
 *   3. Relay (TURN) — always works, highest latency
 */
public class IceServerConfig {

    // Returned from /v1/meetings/{id}/join to the client WebRTC peer connection
    public IceServerList buildIceConfig(String region, String participantId) {
        String turnCredential = turnCredentialGenerator.generate(participantId, Duration.ofHours(1));
        String turnUsername = participantId + ":" + Instant.now().plus(1, ChronoUnit.HOURS).getEpochSecond();

        return IceServerList.of(
            // STUN: free to operate, try first
            IceServer.stun("stun." + region + ".zoom.us:3478"),
            // TURN: pay-per-bandwidth, fallback for symmetric NAT users
            IceServer.turn("turn." + region + ".zoom.us:443", turnUsername, turnCredential)
        );
    }
}

3. Handling Packet Loss — Three-Layer Defense

RTP is UDP-based. No retransmission by default. Three mechanisms compensate:

  1. Opus PLC (Packet Loss Concealment): The Opus audio codec has built-in algorithms that synthesize a plausible continuation of the audio when a packet is missing. At 5% loss, it's imperceptible to the human ear. Audio quality degrades gracefully up to ~20% loss.
  2. FEC (Forward Error Correction): Sender redundantly encodes data across packets. If packet N is lost, receiver can reconstruct it from packets N-1 and N+1 plus the FEC parity packet. Costs ~20% extra bandwidth but eliminates visual artifacts. Used for video (where retransmission latency would be too high).
  3. NACK (Negative Acknowledgement): Receiver detects a gap in RTP sequence numbers → sends NACK to sender → sender retransmits the specific lost packet. Works for video (retransmission in 50–100ms is acceptable for video but not audio). Disabled for audio (latency too high).

4. Recording Architecture

/**
 * Two-phase recording: SFU captures individual participant streams (per-track),
 * then a post-processing job merges them into a composite video.
 *
 * Why not composite in real-time (like MCU)?
 * Real-time compositing requires an MCU-style decode+mix+encode pipeline, which is
 * CPU-intensive and tightly coupled to the live call. Post-processing is asynchronous
 * — it doesn't affect call quality and can use cheaper batch compute resources.
 *
 * Alternative: if instant replay is required, the SFU can write segments as they arrive
 * and composite with 30-second delay (live replay mode). Not shown here.
 */
@Service
public class RecordingService {

    private static final String RECORDINGS_BUCKET = "zoom-recordings";

    private final SfuRecordingClient sfuRecordingClient;
    private final VideoMergeJobQueue videoMergeJobQueue;
    private final RecordingRepository recordingRepository;
    private final SpeechToTextService speechToTextService;
    private final ObjectStorageClient objectStorageClient;

    /**
     * Starts per-track recording on the SFU for each participant.
     * Each participant's media stream is stored as a separate WebM/Opus file on S3.
     * Called when host clicks "Record" during an active meeting.
     */
    public void startRecording(UUID meetingId) {
        sfuRecordingClient.startCapture(meetingId);
        recordingRepository.save(Recording.started(meetingId));
    }

    /**
     * Stops capture and enqueues the merge job.
     * Called when meeting ends or host stops recording.
     */
    public void stopRecordingAndEnqueueMerge(UUID meetingId) {
        List<String> perTrackStorageKeys = sfuRecordingClient.stopCapture(meetingId);

        Recording recording = recordingRepository.findByMeetingId(meetingId)
            .orElseThrow(() -> new RecordingNotFoundException(meetingId));
        recording.setProcessingStatus(RecordingStatus.PROCESSING);
        recordingRepository.save(recording);

        // Enqueue async job — does not block the call ending
        videoMergeJobQueue.enqueue(
            VideoMergeJob.of(meetingId, recording.getRecordingId(), perTrackStorageKeys)
        );
    }

    /**
     * Processing job (runs asynchronously on batch compute):
     * 1. Download per-track WebM files from S3
     * 2. FFmpeg: synchronize tracks by timestamp, create grid composite, encode to MP4
     * 3. Upload composite MP4 to S3 (final recording)
     * 4. Submit audio track to speech-to-text for transcript
     * 5. Update recording record with final URL and transcript URL
     */
    @SqsListener("video-merge-jobs")
    public void processMergeJob(VideoMergeJob mergeJob) {
        try {
            String compositeMp4Key = mergeVideoTracks(mergeJob);
            String transcriptKey = speechToTextService.transcribe(
                RECORDINGS_BUCKET, mergeJob.getMeetingId() + "/audio.opus"
            );

            recordingRepository.markReady(
                mergeJob.getRecordingId(),
                "s3://" + RECORDINGS_BUCKET + "/" + compositeMp4Key,
                "s3://" + RECORDINGS_BUCKET + "/" + transcriptKey
            );
        } catch (VideoMergeException mergeException) {
            log.error("[RecordingService.processMergeJob] Failed for meeting {}: {}",
                mergeJob.getMeetingId(), mergeException.getMessage());
            recordingRepository.markFailed(mergeJob.getRecordingId());
        }
    }

    private String mergeVideoTracks(VideoMergeJob mergeJob) {
        // Downloads per-track files, runs FFmpeg with complex_filter for grid layout
        // ffmpeg -i track_user1.webm -i track_user2.webm ... -filter_complex "[0:v][1:v]xstack=inputs=N:layout=..."
        // Returns S3 key of composite output
        return ffmpegRunner.mergeTracksToGrid(mergeJob.getPerTrackStorageKeys(), mergeJob.getMeetingId());
    }
}

✅E — Evaluate3 min

  • SFU server failure mid-call: All participants on that SFU drop. Mitigation: client detects media stoppage within 3 seconds → signaling server provides new SFU URL → client reconnects within ~5 seconds. Meetings resume automatically without host intervention.
  • 1,000-person meeting: Sending 999 video streams to each participant = 999,000 stream pairs. Solved by Active Speaker Detection + simulcast: only the current speaker's video goes out at full quality; the other 998 get either thumbnail (180p) or audio-only. SFU already has these lower-quality simulcast tiers ready without any new encoding.
  • TURN server cost: 25% of users need TURN relay at 1.5 Mbps each. At 30M concurrent participants: 7.5M × 1.5 Mbps = 11.25 Tbps of TURN bandwidth. This is one of Zoom's largest infrastructure costs. Explains the business pressure to optimize STUN success rate (reducing TURN usage from 25% to 20% saves 1+ Tbps).
  • End-to-end encryption vs SFU: True E2E encryption means the SFU cannot decrypt packets — it can only forward opaque encrypted payloads. This breaks simulcast quality selection (SFU can't inspect the stream to select tier) and server-side recording. Zoom offers "Enhanced E2E Encryption" as an opt-in feature that sacrifices simulcast quality adaptation and recording.

🚀D — Deliver2 min

🎤 Your 60-Second Closing Summary

"Zoom's architecture is built around the SFU pattern — not mesh, not MCU. The key insight: SFU FORWARDS packets without decoding them. This makes it 10× cheaper per participant than MCU, which must decode every frame to composite them. Each participant uploads exactly one stream to their nearest regional SFU, and the SFU selects the right quality tier per receiver using simulcast.

WebRTC handles peer connection setup: SDP offer/answer negotiates codecs, ICE handles NAT traversal. STUN discovers public IPs for 75% of users; TURN relays for the remaining 25% behind strict firewalls. Packet loss is handled in three layers: Opus PLC for audio, FEC for video, NACK retransmission for video gaps.

For large meetings (1,000 people): active speaker detection + simulcast makes it tractable — only the speaker's video goes out at full quality; others get thumbnails. For cross-region meetings: cascaded SFU clusters connected by a private backbone, so Tokyo participants connect to Tokyo SFU rather than routing all media across the Pacific."

⚖️Trade-offs

DecisionOption AOption BOption CWinner & Why
Media routing P2P Mesh MCU (mix + re-encode) SFU (forward) SFU — efficient, scalable, simulcast-friendly. MCU is CPU-bound; mesh breaks at 5+ users.
NAT traversal STUN only TURN always STUN + TURN fallback STUN+TURN fallback — STUN for 75% (free, low latency), TURN for 25% (expensive but reliable).
Packet loss handling NACK retransmit only FEC only Codec PLC + FEC + NACK All three in layers — audio=PLC (no latency cost), video=FEC (no round-trip), video gaps=NACK.
Recording Real-time composite (MCU style) Per-track + async FFmpeg merge Client-side recording only Per-track + async merge — doesn't affect call quality; flexible output formats; cheaper compute (batch vs realtime).
Large meetings (100+) All streams at full quality Active speaker + thumbnails Audio-only for non-speakers Active speaker + thumbnails — practical for 100+ people; simulcast makes thumbnail delivery cheap.
E2E Encryption DTLS only (SFU can see media) True E2E (SFU blind to content) — DTLS by default, E2E opt-in — true E2E breaks simulcast quality selection and server recording. Trade-off is explicit.

☕Java Implementation

/**
 * @file VideoConferenceService.java
 * @description Orchestrates meeting join, SFU assignment, and real-time signaling.
 * Coordinates between the meeting DB, Redis participant state, and SFU capacity service.
 *
 * Public API:
 *   joinMeeting(meetingId, userId) — assigns SFU, creates participant record, returns WebRTC config
 *   leaveMeeting(participantId, meetingId) — cleans up state, publishes leave event
 *   broadcastSignalingEvent(meetingId, event, excludeParticipantId) — fan-out via Redis pub/sub
 */
@Service
public class VideoConferenceService {

    private static final String LOG_PREFIX = "[VideoConferenceService]";
    private static final Duration PARTICIPANT_STATE_TTL = Duration.ofHours(4);

    private final MeetingRepository meetingRepository;
    private final ParticipantRepository participantRepository;
    private final SfuCapacityService sfuCapacityService;
    private final IceServerConfigService iceServerConfigService;
    private final StringRedisTemplate redisTemplate;
    private final ObjectMapper objectMapper;

    /**
     * Handles a participant joining a meeting.
     * Validates meeting state, assigns nearest available SFU, and returns WebRTC configuration.
     *
     * @param meetingId  meeting to join
     * @param userId     joining user
     * @returns          JoinResponse with SFU WebSocket URL and ICE server config
     * @throws MeetingNotFoundException  if meeting does not exist
     * @throws MeetingEndedException     if meeting is already in ENDED state
     * @throws WaitingRoomActiveException if host has waiting room enabled
     */
    public MeetingJoinResponse joinMeeting(UUID meetingId, UUID userId) {
        Meeting meeting = meetingRepository.findById(meetingId)
            .orElseThrow(() -> new MeetingNotFoundException(meetingId));

        if (meeting.getStatus() == MeetingStatus.ENDED) {
            throw new MeetingEndedException(meetingId);
        }

        if (meeting.getSettings().isWaitingRoomEnabled()) {
            // Place in waiting room — host must admit before proceeding
            throw new WaitingRoomActiveException(meetingId, userId);
        }

        // Assign nearest SFU with available capacity
        SfuServer assignedSfu = sfuCapacityService.assignNearestSfuWithCapacity(meetingId, userId);

        // Create participant record (persisted for billing / meeting history)
        Participant participant = participantRepository.save(
            Participant.builder()
                .participantId(UUID.randomUUID())
                .meetingId(meetingId)
                .userId(userId)
                .joinAt(Instant.now())
                .role(deriveRole(meeting, userId))
                .sfuServerId(assignedSfu.getServerId())
                .build()
        );

        // Store real-time state in Redis (fast reads for signaling fan-out)
        storeParticipantStateInRedis(participant, assignedSfu.getServerId());

        // Notify all existing participants that a new person joined
        broadcastSignalingEvent(meetingId,
            SignalingEvent.participantJoined(participant.getParticipantId(), userId),
            participant.getParticipantId() // exclude the joiner from their own notification
        );

        IceServerList iceServers = iceServerConfigService.buildIceConfig(
            assignedSfu.getRegion(), participant.getParticipantId().toString()
        );

        return MeetingJoinResponse.builder()
            .sfuWebSocketUrl(assignedSfu.getWebSocketUrl())
            .meetingToken(generateMeetingToken(participant, meeting))
            .iceServers(iceServers)
            .participantId(participant.getParticipantId())
            .build();
    }

    /**
     * Handles a participant leaving — cleans DB record, Redis state, and notifies peers.
     */
    public void leaveMeeting(UUID participantId, UUID meetingId) {
        participantRepository.markLeaveTime(participantId, Instant.now());
        removeParticipantStateFromRedis(meetingId, participantId);

        broadcastSignalingEvent(meetingId,
            SignalingEvent.participantLeft(participantId),
            participantId // no need to notify the leaver
        );

        // Check if host left — if so, end the meeting or transfer host role
        Participant leavingParticipant = participantRepository.findById(participantId).orElse(null);
        if (leavingParticipant != null && leavingParticipant.getRole() == ParticipantRole.HOST) {
            handleHostDeparture(meetingId);
        }
    }

    /**
     * Broadcasts a signaling event to all participants currently in the meeting,
     * except the excluded participant (typically the sender of the event).
     * Uses Redis Pub/Sub so all WebSocket server instances receive and forward to their clients.
     */
    public void broadcastSignalingEvent(UUID meetingId, SignalingEvent event, UUID excludeParticipantId) {
        try {
            String eventJson = objectMapper.writeValueAsString(
                BroadcastMessage.of(event, excludeParticipantId)
            );
            String channel = "meeting:" + meetingId + ":signals";
            redisTemplate.convertAndSend(channel, eventJson);
        } catch (JsonProcessingException serializationException) {
            log.error("{} Failed to serialize signaling event for meeting {}: {}",
                LOG_PREFIX, meetingId, serializationException.getMessage());
        }
    }

    private void storeParticipantStateInRedis(Participant participant, String sfuServerId) {
        String redisKey = "meeting:" + participant.getMeetingId() + ":participants";
        String participantStateJson = serializeParticipantState(participant, sfuServerId);
        redisTemplate.opsForHash().put(
            redisKey,
            participant.getParticipantId().toString(),
            participantStateJson
        );
        redisTemplate.expire(redisKey, PARTICIPANT_STATE_TTL);
    }

    private void removeParticipantStateFromRedis(UUID meetingId, UUID participantId) {
        String redisKey = "meeting:" + meetingId + ":participants";
        redisTemplate.opsForHash().delete(redisKey, participantId.toString());
    }

    private void handleHostDeparture(UUID meetingId) {
        List<Participant> remainingParticipants =
            participantRepository.findActiveByMeetingId(meetingId);

        if (remainingParticipants.isEmpty()) {
            meetingRepository.updateStatus(meetingId, MeetingStatus.ENDED);
            return;
        }

        // Promote the longest-tenured participant to host
        Participant newHost = remainingParticipants.stream()
            .min(Comparator.comparing(Participant::getJoinAt))
            .orElse(remainingParticipants.get(0));

        participantRepository.updateRole(newHost.getParticipantId(), ParticipantRole.HOST);
        broadcastSignalingEvent(meetingId,
            SignalingEvent.hostTransferred(newHost.getParticipantId()),
            null // notify everyone including the new host
        );
    }

    private ParticipantRole deriveRole(Meeting meeting, UUID userId) {
        return meeting.getHostUserId().equals(userId)
            ? ParticipantRole.HOST
            : ParticipantRole.PARTICIPANT;
    }

    private String generateMeetingToken(Participant participant, Meeting meeting) {
        // JWT with participant_id, meeting_id, role claims — verified by SFU server
        return jwtTokenGenerator.generate(
            participant.getParticipantId(),
            meeting.getMeetingId(),
            participant.getRole()
        );
    }

    private String serializeParticipantState(Participant participant, String sfuServerId) {
        try {
            return objectMapper.writeValueAsString(Map.of(
                "userId", participant.getUserId(),
                "sfuServerId", sfuServerId,
                "audioMuted", participant.isAudioMuted(),
                "videoOff", participant.isVideoOff(),
                "joinedAt", participant.getJoinAt().toEpochMilli()
            ));
        } catch (JsonProcessingException exception) {
            throw new RuntimeException("[VideoConferenceService] Failed to serialize participant state", exception);
        }
    }
}

/**
 * ActiveSpeakerDetector — processes audio energy reports from SFU and detects dominant speaker.
 * The SFU reports audio levels via RTP header extension (RFC 6464) for each participant.
 * This service aggregates those levels and emits ACTIVE_SPEAKER events when the dominant speaker changes.
 */
@Service
public class ActiveSpeakerDetector {

    private static final int SPEAKER_CHANGE_THRESHOLD_DB = 6;   // dBov above average to qualify
    private static final Duration SPEAKER_CHANGE_DEBOUNCE = Duration.ofMillis(500); // prevents rapid toggling

    private final VideoConferenceService videoConferenceService;
    private final Map<UUID, ActiveSpeakerState> meetingActiveSpeakers = new ConcurrentHashMap<>();

    /**
     * Called by SFU server every 200ms with audio energy levels for all active participants.
     * Determines dominant speaker and broadcasts ACTIVE_SPEAKER event if speaker changed.
     *
     * @param meetingId      the meeting
     * @param audioLevels    map of participantId → audio level in dBov (0 = loudest, -127 = silence)
     */
    public void processAudioLevels(UUID meetingId, Map<UUID, Integer> audioLevels) {
        if (audioLevels.isEmpty()) {
            return;
        }

        // Find participant with highest audio energy (least negative dBov value)
        UUID currentDominantSpeaker = audioLevels.entrySet().stream()
            .max(Map.Entry.comparingByValue())
            .map(Map.Entry::getKey)
            .orElse(null);

        if (currentDominantSpeaker == null) {
            return;
        }

        int dominantLevel = audioLevels.get(currentDominantSpeaker);

        // Only qualify as active speaker if meaningfully above background noise
        int averageLevel = audioLevels.values().stream()
            .mapToInt(Integer::intValue)
            .sum() / audioLevels.size();

        if (dominantLevel - averageLevel < SPEAKER_CHANGE_THRESHOLD_DB) {
            return; // No clear dominant speaker (background noise / everyone quiet)
        }

        ActiveSpeakerState currentState = meetingActiveSpeakers.get(meetingId);
        boolean speakerChanged = currentState == null
            || !currentDominantSpeaker.equals(currentState.getSpeakerId());

        if (speakerChanged && isDebounced(currentState)) {
            meetingActiveSpeakers.put(meetingId, ActiveSpeakerState.of(currentDominantSpeaker, Instant.now()));
            videoConferenceService.broadcastSignalingEvent(
                meetingId,
                SignalingEvent.activeSpeakerChanged(currentDominantSpeaker),
                null // broadcast to all participants
            );
        }
    }

    private boolean isDebounced(ActiveSpeakerState previousState) {
        if (previousState == null) {
            return true;
        }
        return Duration.between(previousState.getLastChangedAt(), Instant.now())
            .compareTo(SPEAKER_CHANGE_DEBOUNCE) > 0;
    }
}
