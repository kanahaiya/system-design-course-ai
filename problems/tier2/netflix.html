Tier 2 — Should Know 45 min Video Streaming

Design Netflix

Netflix's core technical challenge is delivering cinematic-quality video to 250 million subscribers across wildly different network conditions — from 5G to congested hotel Wi-Fi — with zero buffering. Adaptive Bitrate Streaming (ABR) solves the client side; Open Connect CDN solves the network side; a massively parallel encoding farm solves the content side. This is a masterclass in building systems that handle 15% of global internet traffic.

🏢 Netflix, YouTube, Disney+
⏱️ 45 min interview
🎬 15% of global internet traffic

❓ R — Requirements 3–5 min

Interview signal: Interviewers at Netflix/FAANG expect you to distinguish ingestion (studio upload path) from playback (consumer streaming path). Nail both in requirements — many candidates only cover playback.

Functional Requirements

  • Content ingestion: Studios upload multi-terabyte source files (ProRes, RAW, DPX). System encodes to multiple quality profiles and packages for streaming.
  • Adaptive streaming: Client auto-adjusts quality (240p → 4K HDR) based on network conditions without interrupting playback.
  • Resume from last position: Seamless cross-device continuity — pause on phone, resume on TV at the same second.
  • Browse & search: Catalog browsing, search by title/genre/year, personalized rows per user profile.
  • Multiple profiles: Up to 5 profiles per account with separate watch histories and recommendations.
  • Downloads for offline: DRM-protected downloads for mobile, synced to cloud after re-connection.

Non-Functional Requirements

  • Scale: 250M subscribers; ~100M concurrent streams at peak (8–10 PM local time); 200 TB new content ingested per day.
  • Startup latency: First video frame in <2 seconds from play button press (P99 target across global users).
  • Rebuffering ratio: <0.1% of playback time spent buffering — industry-leading KPI.
  • Availability: 99.99% for streaming path (~52 minutes downtime/year). Buffering is directly correlated to churn.
  • Durability: Encoded content must never be lost — it is the company's entire asset base.
  • DRM compliance: Every stream must be protected; content licensing requires encryption and key management.

Out of Scope

  • Live streaming / sports events (different latency requirements)
  • Billing and subscription management
  • Content moderation (Netflix content is pre-approved via licensing)

🔢 E — Estimation 5 min

Concurrent Streaming Bandwidth

  • 250M subscribers × 40% daily active = 100M active users/day
  • Peak concurrent streams = ~100M (8–10 PM local — global spread softens peak vs US-only)
  • Average bitrate per stream ≈ 5 Mbps (mix of 1080p and 4K across devices)
  • Peak egress = 100M × 5 Mbps = 500 Tbps — roughly 15% of all internet traffic

Storage — Encoded Content Library

  • Netflix catalog: ~17,000 titles. 1 movie ≈ 2 hrs. 1 TV season ≈ 10 hrs.
  • Per title encoding ladder: 10 quality profiles × 2 codecs (H.264 + HEVC) × avg 50 GB/profile = ~1 TB/title
  • Total library ≈ 17,000 × 1 TB = 17 PB of encoded content
  • New content ingest: 200 TB/day of source material → ~100 TB/day encoded output after compression

Transcoding Compute

  • 1 hour of 4K source → 10 quality profiles × 2 codecs = 20 encoding jobs
  • Each 4K encoding job (HEVC): ~4× real-time on a 32-vCPU instance → 4 CPU-hours per profile
  • Total for one 2-hour movie: 20 jobs × 8 CPU-hours = 160 CPU-hours per movie
  • Netflix runs 10,000+ encoding workers concurrently on AWS EC2 spot instances

CDN & Cache Hit Rate

  • ~15,000 OCA appliances deployed globally in ISP data centers
  • OCAs proactively pre-position top-5,000 titles → ~95% of all streams served from OCA cache
  • Remaining 5% (long-tail/new) fetches from AWS S3 origin via CDN pull
What the interviewer wants to hear: "The bottleneck is CDN egress and encoding compute, not metadata storage. My design decisions — private CDN, parallel encoding workers, HEVC adoption — should all reduce one or both of these costs."

🏗️ H — High-level Design 10 min

System Architecture Overview

Netflix's architecture splits cleanly into two planes: the Content Ingestion Plane (studio → encoded content → CDN) and the Streaming Plane (user device → CDN → first byte of video). These are operationally independent — encoding failures don't affect ongoing streams of already-encoded content.

Content Ingestion Path (Studio → CDN)

  1. Studio upload: Content partners upload source files (often 50–200 GB ProRes/RAW) via pre-signed S3 URLs directly to AWS S3, bypassing Netflix's application servers entirely.
  2. Kafka trigger: S3 ObjectCreated event publishes to Kafka topic raw-content-available. The Encoding Orchestrator consumes this and creates a transcoding job plan.
  3. Encoding Farm: 10,000+ EC2 spot instances run FFmpeg-based transcoding workers. Each job encodes one (title, codec, quality-profile) tuple. Jobs are independent — a failed 4K HEVC job doesn't block 1080p H.264.
  4. VMAF quality gate: Each encoded output is scored by a VMAF model. If VMAF score falls below threshold (typically 90/100), the encoder retries at a higher bitrate. This is how Netflix achieves per-title optimized bitrate ladders — not one-size-fits-all.
  5. Packaging & manifests: Encoded segments are wrapped into HLS (master + variant .m3u8 playlists) and DASH (.mpd manifests). Segments are AES-128 encrypted with per-title keys for DRM. Packaged output lands in S3.
  6. OCA pre-positioning: At ~2 AM UTC, the Content Steering Service pushes popular titles to OCAs at every major ISP globally. By the time users hit peak hour, the content is already 5 ms away.

Streaming Path (User Device → First Frame)

  1. Play button press: Client calls GET /v1/titles/{titleId}/manifest. The Manifest Service determines the best OCA cluster based on user location and ISP (via BGP anycast), then returns a CDN URL to the master manifest.
  2. Manifest fetch: Client fetches the 1–2 KB master .m3u8 from the CDN OCA. The manifest lists all available quality tiers with URLs to their segment playlists.
  3. DRM license: Client simultaneously requests a license from the DRM License Server. The server validates the user's entitlement, then returns a decryption key. This happens in parallel with manifest fetch to avoid adding latency.
  4. Initial quality selection: ABR algorithm picks a conservative quality (not the highest) for the first segment to minimize startup latency. It will ramp up as bandwidth is measured.
  5. Segment fetching loop: Client downloads 2–6 second segments, measures download speed, updates its EWMA bandwidth estimate, and selects quality for the next segment via BOLA or similar algorithm.
  6. Resume: Client fetches the last-watched position from GET /v1/resume/{titleId} (Redis, <1 ms) and seeks to that byte offset before starting playback.
L6 Insight — Open Connect Economics: Netflix pre-positions content during off-peak hours. By 9 AM, popular movies are already on OCAs at every major ISP. The user's first byte comes from 5 ms away, not 150 ms from a distant AWS region. More importantly: ISPs love this arrangement. Without OCA, Netflix traffic traverses expensive peering links between ISPs — the ISP pays. With OCA, that traffic never leaves the ISP's network. Netflix gets free co-location; the ISP gets bandwidth relief. Both win.

Microservices Architecture

Netflix runs 700+ microservices, all on AWS. Key services in the streaming path:

  • Zuul API Gateway: Edge proxy handling authentication, rate limiting, A/B test routing, and request logging. Handles 100,000+ RPS at peak.
  • Eureka Service Registry: Services register themselves; Zuul routes to healthy instances. Netflix open-sourced both.
  • Hystrix Circuit Breaker (now Resilience4j): Every service call is wrapped in a circuit breaker. If the Recommendation Service starts failing at >50% error rate, the circuit opens — callers get a fallback (e.g., popular titles) rather than waiting for timeouts that cascade.
  • Manifest Service: Stateless service returning CDN URLs. Scales horizontally; each instance serves thousands of concurrent manifest requests.
  • DRM License Service: Issues content decryption keys after validating user entitlement. Backed by a hardware security module (HSM) for key storage.
  • Recommendation Service: Pre-computed offline; real-time re-ranking layer adjusts for context (time of day, device, recently watched).

🔬 D — Deep Dive 10 min

1. Video Ingestion Pipeline

The ingestion pipeline is the most operationally complex part of Netflix's infrastructure. A single movie generates hundreds of encoding jobs, all of which must complete before the title is visible to subscribers.

Source File Characteristics

  • Studios deliver in ProRes 4444, ProRes RAW, or DPX (Digital Picture eXchange) format
  • A 2-hour movie in ProRes 4444 4K = ~500 GB – 2 TB of source data
  • Audio: typically multi-channel (7.1 Dolby Atmos) as separate WAV files
  • Subtitles: per-language TTML files, separately processed

Encoding Ladder (per-title optimization)

Netflix does not use a fixed bitrate ladder. Instead, they run a "per-title encoding" algorithm:

  1. Sample 20 "complex" scenes and 20 "simple" scenes from the film
  2. For each candidate bitrate, encode the samples and compute VMAF score
  3. Find the minimum bitrate at which each quality tier achieves VMAF ≥ 90
  4. Use those per-title bitrates rather than the fixed ladder

Result: an action film (complex motion) might need 8 Mbps for 1080p while an animated film might achieve the same quality at 4 Mbps. This saves 20–40% bandwidth and storage.

Codec Strategy

CodecCompression vs H.264Encoding CostDevice SupportUse Case
H.264 (AVC)Baseline1×Universal (every device since 2010)Fallback for all devices
HEVC (H.265)~40% better5–10×Modern devices (iOS 11+, 2018+ TVs)Primary for 1080p+ on supported devices
VP9~30% better3×Chrome, Android, some Smart TVsWeb browser fallback to HEVC
AV1~50% better20–50×Modern devices only (2022+)Mobile data-saving mode, future primary
L6 Insight — Why two codecs? Netflix encodes every title in both H.264 and HEVC (and increasingly AV1). The client advertises its codec support in the manifest request; the Manifest Service returns the highest-efficiency codec the device can hardware-decode. Hardware decoding is critical — software decoding H.265 4K on a phone drains battery in minutes and causes thermal throttling.

Segment Packaging

  • Segment duration: 2–6 seconds. Shorter segments = finer quality switching granularity but more HTTP requests. Netflix uses 6-second segments for most titles, 2-second segments for live events.
  • Container format: fMP4 (fragmented MPEG-4) for both HLS and DASH — more efficient than legacy MPEG-TS (.ts files). Every segment is independently decodable — no dependencies on prior segments.
  • Encryption: AES-128-CTR (CBCS mode). Each segment's decryption key is fetched from the DRM License Server before the segment is decrypted. The key ID is embedded in the manifest.

2. Adaptive Bitrate Streaming (ABR) — BOLA Algorithm

Netflix's ABR algorithm has evolved from simple bandwidth-matching to BOLA (Buffer Occupancy based Lyapunov Algorithm), a mathematically optimal buffer-based approach published by Netflix Research.

Why Buffer-Based ABR (not pure bandwidth-based)

Pure bandwidth estimation has a flaw: the internet is bursty. A single packet loss event can cause the EWMA estimate to crater, making the client drop from 1080p to 480p unnecessarily. Buffer-based ABR uses the playback buffer depth as the true signal of whether the client is downloading fast enough:

  • Buffer > 30s: Downloading faster than playing. Have room to step up quality.
  • Buffer 10–30s: Healthy. Hold current quality or make conservative upgrades.
  • Buffer < 10s: Panic zone. Drop to a quality tier that can be downloaded at least 1.5× playback speed.
  • Buffer < 2s: Emergency. Drop to lowest quality (240p at 300 Kbps) to prevent rebuffering. This is the spinner.

Bandwidth Estimation (EWMA)

The client maintains two EWMA estimates: a "fast" estimate (α=0.5, responds quickly to drops) and a "slow" estimate (α=0.1, tracks long-term throughput). Quality decisions use the minimum of the two — biasing toward caution:

// EWMA update formula
slowEstimateKbps = 0.1 * measuredKbps + 0.9 * slowEstimateKbps;
fastEstimateKbps = 0.5 * measuredKbps + 0.5 * fastEstimateKbps;
conservativeEstimateKbps = Math.min(slowEstimateKbps, fastEstimateKbps);

Quality Switching Hysteresis

Rapid up-down switching (oscillation) is jarring. Netflix's ABR prevents it by:

  • Only stepping up one quality tier at a time
  • Requiring the higher tier's bitrate to be ≤ 80% of estimated bandwidth (safety margin)
  • Not stepping up during the first 10 seconds of playback (startup stability)

3. Netflix Open Connect CDN

Why Build a Private CDN?

In 2012, Netflix was the largest customer of Akamai and Level 3 CDN. At its traffic scale (15% of internet), per-GB CDN fees were enormous. More importantly, Netflix had a unique advantage: it could predict what content subscribers would watch. At 9 PM, 30% of traffic is the top 100 titles. A private CDN with pre-positioning turns this predictability into a latency advantage that no public CDN can match.

OCA Architecture

  • Hardware: Custom-built 1U servers with 100–400 TB of SSD storage per appliance, 10–40 Gbps uplinks
  • Placement: Inside ISP data centers (not Netflix data centers). Netflix provides the hardware and pays for rack space + power. The ISP provides the physical environment and network peering.
  • Routing: BGP anycast — when a user's DNS resolver queries for oca.netflix.com, it returns the IP of the geographically closest (in BGP hops) OCA cluster
  • Cache fill: OCAs pull uncached content from S3 origin on first request, then serve from local SSD for all subsequent requests. Popular content is also proactively pushed nightly.

Content Steering

Netflix's Content Steering protocol (part of HLS spec they contributed) allows the manifest to specify multiple CDN origins ranked by preference. If the first OCA is overloaded or slow, the client can transparently switch to the next one — no user-visible interruption.

L6 Insight — ISP Peering Economics: Without Open Connect, Netflix video traverses expensive public internet peering points between ISPs. These inter-ISP links have limited capacity — Netflix peak traffic was literally saturating them circa 2012, causing ISPs like Comcast and Verizon to demand peering fees. By placing content inside the ISP, Netflix eliminates this traffic entirely. The ISP saves bandwidth costs; Netflix gets better latency and avoids peering fees. This is why Netflix paid ~$100M to build Open Connect — it saved billions over a decade.

4. Digital Rights Management (DRM)

DRM is a legal requirement for all licensed content. Netflix must prove to studios that content is protected — otherwise they cannot license Marvel, Disney, or HBO content.

Three DRM Systems (because three OS ecosystems)

DRM SystemOwnerPlatformHow It Works
Widevine Google Android, Chrome, Chromecast Three security levels: L1 (hardware TEE decryption, required for 4K), L2, L3 (software, SD only). Netflix 4K on Android requires L1 device.
FairPlay Apple iOS, macOS, Apple TV, Safari Proprietary to Apple. License server must be Apple-approved. Key exchange via Apple's KSM protocol. Hardware decryption in Apple Secure Enclave.
PlayReady Microsoft Windows, Edge, Xbox Required for Netflix UWP app on Windows. Supports SL3000 (hardware) required for 4K HDR on Windows 10+.

DRM License Flow

  1. Client requests manifest → Manifest Service returns licenseUrl and drmType
  2. Client generates a DRM challenge (opaque blob containing device credentials)
  3. Client POSTs challenge to Netflix DRM License Service
  4. License Service validates: Is user subscribed? Is the device registered? Is this content licensed in user's country?
  5. License Service calls the appropriate DRM vendor's key system (Widevine STS, Apple KSM) to generate an encrypted license
  6. License (containing content decryption key, usage rules, and expiry) is returned to client
  7. Client's DRM module (in hardware TEE) decrypts segments — the key never leaves the secure enclave

Key Rotation

Netflix rotates content encryption keys periodically. The new key ID is referenced in the updated segment manifest. Clients automatically fetch a new license for the new key ID — transparent to the user. This limits the damage if a key is ever compromised.

5. Personalization & Recommendation Engine

Two-Stage Architecture

  1. Candidate Generation (offline, runs every 4 hours): Collaborative filtering (matrix factorization on watch-history) produces ~1000 candidate titles per user. These are stored in DynamoDB pre-computed per profile.
  2. Re-ranking (online, <100 ms): The 1000 candidates are re-ranked by a real-time model considering: current time of day, device type, what the user just finished watching, trending titles, and A/B test assignment.

Collaborative Filtering

Netflix's core algorithm: if User A and User B have similar viewing histories, titles User B watched that User A hasn't are good recommendations for User A. Implemented as matrix factorization — decompose the (user × title) viewing matrix into two lower-rank matrices (user embeddings and title embeddings). Dot-product similarity retrieves nearest titles.

A/B Testing Thumbnails (Contextual Bandits)

Netflix A/B tests every artwork variant for every title. The same movie might show a different thumbnail depending on whether you watch mostly action, romance, or drama. This is not a standard A/B test — it uses a contextual bandit algorithm (Thompson Sampling) that:

  • Explores new thumbnail variants for a fraction of impressions
  • Exploits the current best variant for the majority
  • Personalizes per user based on their genre preferences

A/B test on thumbnail artwork increased click-through rates by ~20–30% for some titles — equivalent to a massive marketing spend, at zero marginal cost.

6. Chaos Engineering — Netflix's Most Famous Contribution

Netflix invented Chaos Engineering and open-sourced Chaos Monkey in 2012. The core insight: a system that has never experienced failure in production will fail unpredictably in production. A system that fails regularly, in controlled ways, becomes robust.

The Simian Army

  • Chaos Monkey: Randomly kills production EC2 instances during business hours. Forces services to be stateless and auto-healing. If your service panics when an instance dies, you find out on a Tuesday afternoon — not during a Friday night traffic peak.
  • Chaos Gorilla: Simulates an entire AWS Availability Zone going offline. Verifies that traffic reroutes to other AZs within seconds.
  • Chaos Kong: Simulates an entire AWS Region failing. Verifies cross-region failover. Netflix can shift all traffic from us-east-1 to us-west-2 in minutes.
  • Latency Monkey: Introduces artificial latency between services. Forces all service clients to implement timeouts and fallbacks — services that hang indefinitely rather than failing fast are found and fixed.
  • Conformity Monkey: Finds instances that don't comply with best practices (e.g., no auto-scaling group) and terminates them.
L6 Insight — Hystrix Circuit Breaker Pattern: Chaos Engineering only works if services are designed with circuit breakers. Netflix's Hystrix (now Resilience4j) wraps every inter-service call: if the downstream service returns errors or times out in >50% of calls over a 10-second window, the circuit "opens" — all subsequent calls immediately return a fallback response without attempting the network call. The circuit tries a single "probe" call every 5 seconds; if it succeeds, the circuit "closes" again. This prevents cascade failures where one slow service takes down every service that calls it.

✅ E — Evaluate 3 min

Failure Scenarios & Mitigations

OCA Appliance Failure

What happens: An OCA in a specific ISP loses power or has a disk failure.
Mitigation: Multiple OCA clusters serve each region (typically 3–5 per major ISP). BGP routing automatically redirects clients to the next closest cluster within seconds. If all OCAs for an ISP fail, clients fall back to the regional CDN PoP, then to S3 origin. Degraded latency but no outage.

Encoding Worker Crash Mid-Job

What happens: A spot instance encoding a title is reclaimed by AWS mid-job.
Mitigation: Each encoding job is tracked in the job state table. Workers heartbeat every 30 seconds; jobs without heartbeats for 2 minutes are marked STALE and re-queued. Jobs write output to S3 with a checksum; the orchestrator validates on completion. Re-runs are idempotent — they overwrite the same S3 keys.

DRM License Service Unavailable

What happens: The DRM License Service goes down during peak hours.
Mitigation: Licenses have a validity period (typically 24 hours). Clients cache their license locally. Ongoing streams continue uninterrupted. New streams requiring a license will fail to start — but this affects <5% of users at any moment (most have a valid cached license). License Service has 3-region active-active deployment.

AWS Region Outage

What happens: us-east-1 (Netflix's primary region) goes down.
Mitigation: Netflix runs active-active in 3 AWS regions (us-east-1, us-west-2, eu-west-1). The control plane (API services) fails over via Route 53 health checks within 60 seconds. The data plane (OCA CDN) is region-independent — OCAs don't route through AWS, they peer directly at ISPs. Video streaming continues uninterrupted for active sessions even if the entire AWS control plane is down.

Recommendation Service Degradation

What happens: The real-time re-ranking service starts returning errors at >50% rate.
Mitigation: Hystrix circuit breaker opens. The fallback response returns the pre-computed top-1000 candidates without re-ranking. Users see slightly less personalized recommendations (editorial picks rather than ML-personalized) — but the app works normally. The degradation is invisible to users.

Quality of Service (QoE) Metrics

  • Rebuffering Ratio: Time spent buffering / total stream time. Target <0.1%. Directly correlates with subscriber churn.
  • Video Start Failure (VSF): % of play attempts that fail before first frame. Every 1% VSF increase = 2% increase in next-day cancellation rate.
  • Average Bitrate: Higher = better perceived quality. Tracked per ISP to identify network peering issues.
  • VMAF Score: Perceptual quality of delivered video, computed from segment bitrate + title profile. Used to trigger re-encoding if quality degrades.

🚀 D — Deliver 2 min

We designed Netflix handling 250M subscribers and 500 Tbps of peak egress. The five architectural pillars:

  1. Per-title adaptive encoding using VMAF-guided per-title bitrate ladders in both H.264 and HEVC, saving 20–40% bandwidth vs fixed ladders. Jobs are parallelized across 10,000+ EC2 spot workers, stored durably on S3.
  2. HLS + ABR with BOLA algorithm for client-side quality selection. The client monitors buffer depth (not just bandwidth) to avoid unnecessary quality switches. Manifests are tiny; all video bytes come from CDN edge.
  3. Open Connect CDN with 15,000 OCA appliances co-located inside ISPs globally. Proactive pre-positioning ensures 95% cache hit rate. Video bytes never traverse expensive peering links.
  4. Multi-DRM (Widevine/FairPlay/PlayReady) with hardware TEE decryption on client devices. Key rotation limits blast radius of any key compromise.
  5. Chaos Engineering + Hystrix circuit breakers ensure every service degrades gracefully. The system is hardened by deliberate, daily failure injection in production.

The key insight Netflix's architecture embeds: video bytes are 99.9% of the data volume. Every design decision — private CDN, per-title encoding, buffer-based ABR — is about getting those bytes to users as cheaply and reliably as possible. The remaining 0.1% (metadata, recommendations, auth) is standard microservices architecture.

Streaming protocol HLS (HTTP-based, CDN-friendly) DASH (MPEG-DASH) HLS has native support on all Apple devices (iOS + Safari). Netflix uses both — DASH for non-Apple, HLS for Apple. HLS caches perfectly on HTTP CDNs; DASH requires slightly more manifest negotiation.
CDN strategy Private OCA (embedded in ISPs) Public CDN (CloudFront, Akamai) At Netflix's volume (500 Tbps peak), public CDN per-GB fees are prohibitive. OCA co-location eliminates inter-ISP transit entirely. Break-even was reached at ~1 Tbps — Netflix is 500× that. Public CDN remains the right choice for smaller streaming platforms.
ABR algorithm Buffer-based (BOLA) Bandwidth-based only Pure bandwidth estimation is brittle on bursty networks. Buffer depth is the ground truth — if the buffer is growing, downloading is outpacing playback. BOLA is mathematically optimal: maximizes average quality while minimizing rebuffering as a constrained optimization problem.

Server-driven requires round-trips and requires the server to model millions of diverse client contexts. Client-side scales to hundreds of millions of concurrent streams with zero server cost per quality decision.
Encoding codec HEVC + H.264 (dual encode) H.264 only HEVC saves ~40% bandwidth on modern devices. With 100M+ streams, 40% bandwidth reduction = ~$100M/year in CDN and bandwidth cost savings. The dual-encoding cost (higher compute, more storage) is easily justified. AV1 is the next transition in progress.

Pre-computing every 4 hours captures 99% of the value — viewing history doesn't change fast enough to need sub-second freshness. The online re-ranking layer captures real-time signals (just finished a title, trending now) within milliseconds.

☕ Java Implementation — ABR Quality Selector

This implementation models the client-side ABR algorithm used by Netflix players. It tracks bandwidth using dual EWMA (fast + slow), maps bandwidth to quality profiles, and implements buffer-based switching with hysteresis to prevent oscillation.

/**
 * @file AbrQualitySelector.java
 * @description Client-side Adaptive Bitrate quality selector for HLS/DASH streaming.
 *              Implements dual-EWMA bandwidth estimation and buffer-occupancy based
 *              quality switching (inspired by Netflix's BOLA algorithm).
 *
 * @requires none (standalone implementation)
 *
 * Public API:
 *   selectNextQuality(downloadedBytes, downloadDurationMs, bufferLevelSeconds)
 *     — returns the quality tier name to request for the next segment
 *   getCurrentQualityName() — returns the currently selected quality tier name
 *   getEstimatedBandwidthKbps() — returns the current bandwidth estimate
 */

import java.util.List;

public class AbrQualitySelector {

    // ── Constants ─────────────────────────────────────────────────────

    /**
     * Quality tiers in ascending order of required bandwidth.
     * Bitrates match Netflix's actual per-title ladder for a typical drama.
     */
    private static final List<QualityProfile> QUALITY_PROFILES = List.of(
        new QualityProfile("240p",       300,  "h264"),
        new QualityProfile("480p",       800,  "h264"),
        new QualityProfile("720p",      2500,  "h264"),
        new QualityProfile("1080p",     5000,  "h264"),
        new QualityProfile("1080p_HDR", 8000,  "hevc"),
        new QualityProfile("4K_HDR",   16000,  "hevc")
    );

    // Buffer thresholds in seconds
    private static final int BUFFER_EMERGENCY_SECONDS  = 2;   // spinner imminent: go to floor quality
    private static final int BUFFER_PANIC_SECONDS      = 10;  // drop one tier immediately
    private static final int BUFFER_HEALTHY_SECONDS    = 30;  // safe to step up quality
    private static final int STARTUP_STABILITY_SECONDS = 10;  // don't step up during cold start

    // Dual EWMA alpha values — fast reacts to drops, slow tracks long-term
    private static final double EWMA_ALPHA_FAST = 0.5;
    private static final double EWMA_ALPHA_SLOW = 0.1;

    // Safety margin: only use this fraction of estimated bandwidth
    // to leave headroom for TCP slow-start and network jitter
    private static final double BANDWIDTH_SAFETY_MARGIN = 0.8;

    // ── State ─────────────────────────────────────────────────────────

    private double fastBandwidthKbps  = 1000.0; // conservative initial estimate
    private double slowBandwidthKbps  = 1000.0;
    private int    currentProfileIndex = 0;      // start at lowest quality
    private int    segmentsDownloaded  = 0;      // tracks startup period

    // ── Core logic functions ──────────────────────────────────────────

    /**
     * Called after each segment download completes. Updates the bandwidth
     * estimate and selects the quality tier for the next segment.
     *
     * This is the main decision loop: it runs once per 2–6 seconds during
     * active playback and is the only place where quality changes happen.
     *
     * @param downloadedBytes     number of bytes in the segment just downloaded
     * @param downloadDurationMs  wall-clock time in milliseconds to download it
     * @param bufferLevelSeconds  current playback buffer depth in seconds
     * @return name of the quality profile to use for the next segment fetch
     */
    public String selectNextQuality(
            long downloadedBytes,
            long downloadDurationMs,
            int  bufferLevelSeconds) {

        updateDualEwmaBandwidth(downloadedBytes, downloadDurationMs);
        segmentsDownloaded++;

        final int targetIndex = determineTargetProfileIndex(bufferLevelSeconds);
        currentProfileIndex   = applyHysteresisConstraints(targetIndex, bufferLevelSeconds);

        return QUALITY_PROFILES.get(currentProfileIndex).name();
    }

    /**
     * Determines the ideal quality profile index given current network and
     * buffer state, ignoring hysteresis constraints (applied separately).
     *
     * Priority order:
     *   1. Emergency: buffer critically low → drop to floor
     *   2. Panic: buffer low → drop one tier
     *   3. Normal: highest tier that fits within safe bandwidth estimate
     */
    private int determineTargetProfileIndex(int bufferLevelSeconds) {
        if (bufferLevelSeconds <= BUFFER_EMERGENCY_SECONDS) {
            return 0; // floor quality — prevent spinner at all costs
        }

        if (bufferLevelSeconds <= BUFFER_PANIC_SECONDS) {
            return Math.max(0, currentProfileIndex - 1);
        }

        return findHighestAffordableProfileIndex();
    }

    /**
     * Finds the highest quality profile whose required bandwidth fits within
     * the conservative (minimum of fast/slow) bandwidth estimate, with safety margin.
     *
     * Using min(fast, slow) biases toward caution: if either estimator detects
     * a drop, quality decreases. The safety margin prevents downloading segments
     * faster than they play (which would drain the buffer).
     */
    private int findHighestAffordableProfileIndex() {
        final double conservativeBandwidthKbps =
                Math.min(fastBandwidthKbps, slowBandwidthKbps) * BANDWIDTH_SAFETY_MARGIN;

        int affordableIndex = 0;
        for (int profileIndex = 0; profileIndex < QUALITY_PROFILES.size(); profileIndex++) {
            if (QUALITY_PROFILES.get(profileIndex).requiredKbps() <= conservativeBandwidthKbps) {
                affordableIndex = profileIndex;
            }
        }
        return affordableIndex;
    }

    /**
     * Applies hysteresis to prevent rapid quality oscillation:
     *   - Never step up more than one tier at a time
     *   - Don't step up during the startup period (first 10 seconds)
     *   - Allow instant drops (no hysteresis on drops — latency is real)
     *
     * Drops are allowed to jump multiple tiers at once because a buffer
     * emergency requires immediate action — gradual drops cause rebuffering.
     */
    private int applyHysteresisConstraints(int targetIndex, int bufferLevelSeconds) {
        final boolean isInStartupPeriod =
                segmentsDownloaded * 4 < STARTUP_STABILITY_SECONDS; // assume ~4s segments

        if (targetIndex > currentProfileIndex) {
            if (isInStartupPeriod) {
                return currentProfileIndex; // hold during startup
            }
            return currentProfileIndex + 1; // step up at most one tier
        }

        // Drops: allow any size drop immediately (buffer emergencies are urgent)
        return targetIndex;
    }

    /**
     * Updates both EWMA estimators with the latest measured throughput.
     *
     * Dual EWMA rationale: the fast estimator quickly captures bandwidth drops
     * (to protect against rebuffering), while the slow estimator tracks steady-state
     * throughput (to avoid over-reacting to transient TCP slow-start dips).
     * Taking the minimum of both gives us the worst-case estimate — deliberately
     * conservative to prioritize playback continuity over quality.
     */
    private void updateDualEwmaBandwidth(long downloadedBytes, long downloadDurationMs) {
        if (downloadDurationMs <= 0) {
            return; // guard against division by zero on cached segments
        }
        final double measuredKbps = (downloadedBytes * 8.0) / downloadDurationMs; // bits/ms = kbps
        fastBandwidthKbps = EWMA_ALPHA_FAST * measuredKbps + (1 - EWMA_ALPHA_FAST) * fastBandwidthKbps;
        slowBandwidthKbps = EWMA_ALPHA_SLOW * measuredKbps + (1 - EWMA_ALPHA_SLOW) * slowBandwidthKbps;
    }

    // ── DOM functions (accessors for player UI) ───────────────────────

    /** Returns the name of the quality currently being streamed. */
    public String getCurrentQualityName() {
        return QUALITY_PROFILES.get(currentProfileIndex).name();
    }

    /**
     * Returns the conservative bandwidth estimate in Kbps.
     * Useful for QoE analytics — sent to the server in each watch-event POST.
     */
    public double getEstimatedBandwidthKbps() {
        return Math.min(fastBandwidthKbps, slowBandwidthKbps);
    }

    // ── Data types ────────────────────────────────────────────────────

    /**
     * Immutable description of one quality tier in the encoding ladder.
     *
     * @param name         human-readable name ("1080p_HDR") returned to the caller
     * @param requiredKbps minimum bandwidth needed to sustain this quality without rebuffering
     * @param codec        preferred codec for this tier (client checks hardware support before use)
     */
    private record QualityProfile(String name, int requiredKbps, String codec) {}
}

Hystrix-Style Circuit Breaker (simplified)

/**
 * @file CircuitBreaker.java
 * @description Simplified circuit breaker for inter-service calls.
 *              Mirrors Netflix Hystrix behavior: CLOSED → OPEN → HALF_OPEN → CLOSED.
 *              Used by every Netflix microservice to prevent cascade failures.
 */
public class CircuitBreaker {

    private enum State { CLOSED, OPEN, HALF_OPEN }

    private static final int    FAILURE_THRESHOLD_PCT  = 50;   // open if >50% calls fail
    private static final int    SAMPLE_WINDOW_SECONDS  = 10;   // rolling window for failure rate
    private static final long   OPEN_DURATION_MS       = 5_000; // probe after 5 seconds open
    private static final int    MIN_CALLS_TO_EVALUATE  = 20;   // avoid tripping on 1/2 calls

    private State  currentState       = State.CLOSED;
    private int    callsInWindow       = 0;
    private int    failuresInWindow    = 0;
    private long   openedAtMs          = 0;

    /**
     * Executes serviceCall if circuit is CLOSED or HALF_OPEN; returns fallback if OPEN.
     * The fallback is a Supplier so it's only evaluated when needed (lazy).
     *
     * @param serviceCall the actual downstream call to attempt
     * @param fallback    what to return if the circuit is open or the call fails
     * @param <T>         return type of both the call and fallback
     * @return result of serviceCall, or fallback if the circuit is open
     */
    public <T> T execute(java.util.function.Supplier<T> serviceCall,
                          java.util.function.Supplier<T> fallback) {
        if (currentState == State.OPEN) {
            if (shouldAttemptReset()) {
                currentState = State.HALF_OPEN;
            } else {
                return fallback.get(); // circuit still open: return fallback immediately
            }
        }

        try {
            final T result = serviceCall.get();
            onCallSuccess();
            return result;
        } catch (Exception callFailure) {
            onCallFailure();
            return fallback.get();
        }
    }

    private void onCallSuccess() {
        if (currentState == State.HALF_OPEN) {
            reset(); // probe succeeded: close the circuit
        }
        callsInWindow++;
    }

    private void onCallFailure() {
        callsInWindow++;
        failuresInWindow++;

        if (currentState == State.HALF_OPEN) {
            openCircuit(); // probe failed: stay open
            return;
        }

        if (callsInWindow >= MIN_CALLS_TO_EVALUATE) {
            final int failureRatePct = (failuresInWindow * 100) / callsInWindow;
            if (failureRatePct > FAILURE_THRESHOLD_PCT) {
                openCircuit();
            }
        }
    }

    private void openCircuit() {
        currentState   = State.OPEN;
        openedAtMs     = System.currentTimeMillis();
        callsInWindow  = 0;
        failuresInWindow = 0;
    }

    private void reset() {
        currentState     = State.CLOSED;
        callsInWindow    = 0;
        failuresInWindow = 0;
    }

    private boolean shouldAttemptReset() {
        return System.currentTimeMillis() - openedAtMs > OPEN_DURATION_MS;
    }
}
