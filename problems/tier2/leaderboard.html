Tier 2 — Should Know45 minRedis data structures

Design Gaming Leaderboard

Redis Sorted Set is the perfect data structure for leaderboards: O(log N) insert, O(log N) rank lookup, O(log N + M) range query. Know the operations cold. The challenge: a single sorted set can't hold 100M entries in one Redis node — sharding is required.

🏢 Riot Games, Activision, Epic
⏱️ 45 min interview
🏆 100M players

❓R — Requirements3–5 min

Functional Requirements

  • Update player score after each game
  • View global top-N leaderboard (e.g., top 100)
  • Look up a specific player's rank and score
  • Friend leaderboard — ranking among friends only
  • Weekly/monthly/all-time leaderboard windows

Non-Functional Requirements

  • Scale: 100M players, 10M score updates/day, 50M leaderboard reads/day
  • Latency: Score update <50ms; rank lookup <100ms; top-N <200ms
  • Read/write ratio: 5:1 (more reads than score updates)

🔢E — Estimation3–5 min

  • 100M players × (8 bytes score + 8 bytes player_id + 40 bytes overhead) = ~5.6GB for the sorted set — fits in one Redis node RAM but is large
  • 10M score updates/day = ~115 updates/sec average; peak 10K/sec during game completion spike
  • Redis ZADD: 500K ops/sec single-threaded → can handle peak comfortably on one node
  • Sharded across 10 nodes: 10M players/node → 560MB/node → very manageable

🗄️S — Schema3–5 min

// Redis Sorted Set (primary leaderboard)
// Key: leaderboard:{gameId}:{period}  e.g., leaderboard:fortnite:weekly:2024-W52
// Score: player score (double)
// Member: player_id

// Redis key operations:
// ZADD leaderboard:fortnite:global {score} {playerId}      -- O(log N)
// ZRANK leaderboard:fortnite:global {playerId}             -- O(log N), 0-indexed
// ZSCORE leaderboard:fortnite:global {playerId}            -- O(1)
// ZREVRANGE leaderboard:fortnite:global 0 99 WITHSCORES   -- O(log N + M) top 100

// Player profile (PostgreSQL — source of truth for scores)
players: player_id, username, all_time_score, weekly_score, monthly_score, last_updated

// Redis populated from DB on startup; DB is the durable source of truth

🏗️H — High-level Design10 min

  • Score Update Flow: Game server → Score Update Service → atomically update PostgreSQL + ZADD to Redis sorted set.
  • Top-N Query: ZREVRANGE leaderboard:game:global 0 99 from Redis. Enrich with player usernames from Redis hash (cached) or PostgreSQL.
  • Rank Lookup: ZREVRANK leaderboard:game:global {playerId} → returns 0-based rank. Add 1 for display rank.
  • Friend Leaderboard: Fetch friend list from social graph. For each friend, ZSCORE to get score. Sort in application layer. (For large friend counts: create a temporary sorted set with ZUNIONSTORE.)
  • Weekly reset: Weekly leaderboard keys have week suffix. New key each week. Old key expires after 1 month (Redis TTL).

🔌A — APIs5 min

POST /v1/scores                         // update player score
  Body: { gameId, playerId, newScore, period: "global|weekly|monthly" }

GET  /v1/leaderboard/{gameId}/top?limit=100&period=weekly
  Returns: [{ rank, playerId, username, score }]

GET  /v1/leaderboard/{gameId}/rank?playerId={}&period=global
  Returns: { rank, score, percentile }

GET  /v1/leaderboard/{gameId}/friends?playerId={}&period=weekly
  Returns: [{ rank, playerId, username, score }]

🔬D — Deep Dive: Sharded Leaderboard for 100M Players10 min

Problem: Single Redis sorted set with 100M members = 5.6GB. While it fits in memory, a single Redis node has throughput limits (~500K ops/sec). For games with burst score updates (e.g., 10K/sec at end-of-match), sharding helps.

Shard by score range:

  • Shard 0: scores 0–999 (leaderboard:game:shard:0)
  • Shard 1: scores 1000–9999
  • Shard 2: scores 10000–99999
  • Shard 3: scores 100000+ (top players)

Score update: Determine shard from score, ZADD to that shard.

Top-N query: Query top shard (Shard 3) for top N. If shard has fewer than N players, also query Shard 2, etc. Merge results in application layer.

Rank lookup: Sum of (ZCARD of all higher shards) + ZREVRANK within own shard = global rank.

Alternative: hash sharding: Shard by hash(player_id) % N. Top-N requires querying all shards and merging — O(shards × top_N) comparisons.

✅E — Evaluate3 min

  • Score tie-breaking: Two players with the same score: ZADD uses lexicographic ordering of member names. For fair tie-breaking, encode time-of-achievement in score (e.g., score × 10000 + (MAX_TIME - time_achieved)).
  • Weekly reset: At week boundary, create a new sorted set key. Don't clear the old key — use expiry. Use Redis keyspace notifications to trigger reset logic.

🚀D — Deliver2 min

We designed a leaderboard handling 100M players with sub-100ms rank lookups. Key decisions: Redis Sorted Set for O(log N) all operations, score-range sharding for large datasets, application-layer merge for top-N queries, PostgreSQL as durable source of truth, and Redis TTL for time-windowed leaderboards.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Primary data structureRedis Sorted SetPostgreSQL with ORDER BYRedis ZRANK is O(log N) vs PostgreSQL COUNT(*) which is O(N) without pre-computed rank column. Redis handles 500K ops/sec.
Sharding strategyScore-range shardingHash shardingScore-range: top-N query hits only the top shard (fast). Hash sharding: top-N requires querying all shards and merging.
Friend leaderboardPer-request ZSCORE for each friendDedicated friend leaderboard sorted setFriend lists are dynamic (constantly changing). Per-request ZSCORE is accurate. Dedicated sorted set requires maintenance on every friend add/remove.

☕Java Implementation

/**
 * ShardedLeaderboard — distributes a global leaderboard across multiple Redis
 * sorted sets using score-range sharding for efficient top-N queries.
 */
public class ShardedLeaderboard {

    private static final String SHARD_KEY_PREFIX = "leaderboard:shard:";
    private static final int[] SHARD_THRESHOLDS = {1_000, 10_000, 100_000, Integer.MAX_VALUE};

    private final JedisPool jedisPool;
    private final String leaderboardName;

    public ShardedLeaderboard(JedisPool jedisPool, String leaderboardName) {
        this.jedisPool = jedisPool;
        this.leaderboardName = leaderboardName;
    }

    /**
     * Updates a player's score in the appropriate shard.
     * If the score crosses a shard boundary, the player is moved between shards.
     */
    public void updateScore(String playerId, double newScore) {
        int newShardIndex = resolveShardIndex(newScore);
        String newShardKey = buildShardKey(newShardIndex);

        try (Jedis jedis = jedisPool.getResource()) {
            // Remove from all other shards (player may have been in a different shard before)
            for (int shardIndex = 0; shardIndex < SHARD_THRESHOLDS.length; shardIndex++) {
                if (shardIndex != newShardIndex) {
                    jedis.zrem(buildShardKey(shardIndex), playerId);
                }
            }
            jedis.zadd(newShardKey, newScore, playerId);
        }
    }

    /**
     * Returns the top-N players globally by merging results from shards top-down.
     * Starts from the highest shard (top players) and works down until N players found.
     */
    public List<PlayerRank> getTopPlayers(int topN) {
        List<PlayerRank> results = new ArrayList<>();

        try (Jedis jedis = jedisPool.getResource()) {
            // Iterate shards from highest score to lowest
            for (int shardIndex = SHARD_THRESHOLDS.length - 1; shardIndex >= 0; shardIndex--) {
                if (results.size() >= topN) break;

                int remaining = topN - results.size();
                String shardKey = buildShardKey(shardIndex);
                Set<Tuple> shardTopPlayers = jedis.zrevrangeWithScores(shardKey, 0, remaining - 1);

                for (Tuple playerTuple : shardTopPlayers) {
                    results.add(new PlayerRank(playerTuple.getElement(), playerTuple.getScore(),
                                               results.size() + 1));
                }
            }
        }
        return results;
    }

    /**
     * Computes a player's global rank by summing the cardinality of higher shards
     * plus their rank within their own shard.
     */
    public long getGlobalRank(String playerId) {
        try (Jedis jedis = jedisPool.getResource()) {
            Double score = null;
            int playerShardIndex = -1;

            // Find which shard this player is in
            for (int shardIndex = 0; shardIndex < SHARD_THRESHOLDS.length; shardIndex++) {
                score = jedis.zscore(buildShardKey(shardIndex), playerId);
                if (score != null) {
                    playerShardIndex = shardIndex;
                    break;
                }
            }
            if (score == null) return -1; // player not found

            // Count players in higher-scoring shards (they all rank ahead of this player)
            long playersAhead = 0;
            for (int higherShard = playerShardIndex + 1; higherShard < SHARD_THRESHOLDS.length; higherShard++) {
                playersAhead += jedis.zcard(buildShardKey(higherShard));
            }

            // Rank within this player's shard (0-indexed)
            long rankWithinShard = jedis.zrevrank(buildShardKey(playerShardIndex), playerId);
            return playersAhead + rankWithinShard + 1; // 1-indexed global rank
        }
    }

    private int resolveShardIndex(double score) {
        for (int shardIndex = 0; shardIndex < SHARD_THRESHOLDS.length; shardIndex++) {
            if (score < SHARD_THRESHOLDS[shardIndex]) {
                return shardIndex;
            }
        }
        return SHARD_THRESHOLDS.length - 1;
    }

    private String buildShardKey(int shardIndex) {
        return SHARD_KEY_PREFIX + leaderboardName + ":" + shardIndex;
    }

    public record PlayerRank(String playerId, double score, int rank) {}
}
