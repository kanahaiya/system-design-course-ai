Tier 2 — Should Know45 minObservability

Design Metrics Dashboard (Datadog)

Metrics systems have a specific storage problem called the cardinality explosion: adding even one high-cardinality tag (like user_id) can increase storage by 1,000×. Understanding why, and how to mitigate it, is the signal the interviewer is looking for.

🏢 Datadog, Prometheus, New Relic
⏱️ 45 min interview
📈 Time-series at scale

❓R — Requirements3–5 min

Functional Requirements

  • Ingest metrics: metric_name, tags (key:value pairs), timestamp, value
  • Query: time-range aggregations (avg, sum, p99) by metric + tag filters
  • Dashboard: visualize metrics as line/bar charts
  • Alerting: trigger alert when metric crosses threshold for N minutes
  • Downsampling: roll up high-resolution data to lower resolution over time

Non-Functional Requirements

  • Scale: 1M metrics/sec ingestion; 10B data points/day
  • Query latency: <1s for dashboard queries over last 24h
  • Retention: Raw (1s) for 7 days; 1-min aggregates for 1 year; 1-hour for 5 years

🔢E — Estimation3–5 min

  • 1M metrics/sec × 16 bytes per data point = 16MB/sec = 1.4TB/day raw
  • After 7-day raw retention + rollup: 1.4TB × 7 + (1-min aggregate: 1.4TB/60 × 365) + (1-hour: ~250GB × 5) = ~15TB total
  • Compression (Gorilla XOR encoding): ~10× ratio → 1.5TB actual storage

🗄️S — Schema3–5 min

// Time-series data (column-oriented storage — ClickHouse or custom like Gorilla)
// Each unique (metric_name, tag_set) combination = one time series
metric_data:
    metric_name  VARCHAR(200),    -- "http.request.latency"
    tags         MAP<STRING, STRING>, -- {service: "auth", region: "us-east"}
    timestamp    UINT32,          -- Unix epoch seconds (not ms — saves 50% space)
    value        DOUBLE,

// Series index (Inverted index — for tag-based queries)
// "Find all series for service=auth" → lookup tag index → get series IDs
tag_index: tag_key, tag_value → [series_id_1, series_id_2, ...]

🏗️H — High-level Design10 min

  • Metric Agent: Runs on each monitored host. Collects system/app metrics every 10s. Sends to Kafka in batch.
  • Ingestion Service: Consumes Kafka. Assigns series IDs. Writes to write buffer (in-memory, 2h). Flushes to SSD in compressed blocks (Gorilla format).
  • Time-Series Store (TSDB): Hot data in SSD (last 7 days), warm in HDD, cold in S3. Read path: merge SSD + in-memory buffer.
  • Query Engine: Parses PromQL-like queries. Resolves tag filters to series IDs via inverted index. Fetches and merges time series data. Aggregates per time bucket.
  • Alerting Engine: Evaluates alert rules every 60s. Checks if metric crosses threshold for configured duration. Triggers PagerDuty/Slack on alert fire.
  • Downsampling Job: Runs every hour. Aggregates 1s data to 1-min buckets. Runs nightly for 1-min to 1-hour rollup.

🔬D — Deep Dive: Cardinality Problem + Gorilla Compression10 min

Cardinality explosion: Metric http.request.latency with tags {service, region} = 10 services × 5 regions = 50 unique time series. Add tag {user_id} with 10M users = 500M time series. Storage × 10,000,000. This is cardinality explosion.

Mitigation: Never use high-cardinality tags (user_id, request_id, trace_id) in metrics. Use histograms/percentiles for distribution. Use logs/traces for per-request data.

Gorilla compression (Facebook's TSDB):

  • Timestamp delta-delta encoding: Store timestamp differences (deltas), then differences of differences. Regular 10s intervals → delta = 10, delta-delta = 0. Encodes to ~1.5 bits per timestamp vs 4 bytes uncompressed.
  • Value XOR encoding: XOR consecutive doubles. If value changes little (e.g., CPU% 45.1, 45.3, 44.9), the XOR has many leading zeros. Use variable-length encoding: XOR=0 (1 bit), XOR changes only trailing bits (shorter code), full XOR (worst case).
  • Result: ~10× compression. 1.4TB/day → 140GB/day.

✅E — Evaluate3 min

  • Alert evaluation latency: Evaluating 1M alert rules every 60s = 1M queries/min on TSDB. Pre-compute common aggregations; evaluate alert rules from pre-aggregated data, not raw.
  • Stale metrics: If an agent stops sending (host dies), the last data point should not project forward. TSDB should mark series as stale after missing N intervals.

🚀D — Deliver2 min

We designed a metrics system handling 1M metrics/sec. Key decisions: Kafka for ingestion buffering, Gorilla compression for 10× storage reduction, inverted tag index for fast series lookup, tiered storage (SSD→HDD→S3) for retention, and downsampling jobs for long-term rollup.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Storage formatColumn-oriented (Gorilla blocks)Row-oriented (RDBMS)Time-series queries access one column (value) across many rows (time). Column store reads only the value column — 10× less I/O than row store.
Timestamp compressionDelta-delta encodingRaw 4-byte timestampsMetrics arrive at regular intervals; delta-delta of a constant interval = 0, encodes to 1–2 bits instead of 32 bits.
Retention strategyTiered (raw→1min→1hr rollup)Keep raw data foreverRaw 1s data for 5 years = 250TB. Downsampled data captures trends at 100× compression. Use raw only for short-term (7 days) debugging.

☕Java Implementation

/**
 * TimeSeriesStore — Gorilla-style delta-delta encoding for timestamps
 * and XOR encoding for double values.
 * Stores a single time series as a compact byte sequence.
 */
public class TimeSeriesStore {

    private final List<Long> timestamps = new ArrayList<>();
    private final List<Double> values = new ArrayList<>();

    // For delta-delta encoding
    private long previousTimestamp = 0;
    private long previousDelta = 0;

    // For XOR encoding
    private long previousValueBits = 0;

    /**
     * Appends a data point to the time series.
     * In a real implementation, this would write compressed bits to a buffer.
     * Here we compute the compression metrics to illustrate the algorithm.
     */
    public void append(long timestamp, double value) {
        long delta = timestamp - previousTimestamp;
        long deltaOfDelta = delta - previousDelta;

        // Delta-delta encoding: small changes encode in few bits
        // deltaOfDelta == 0: encode as 1 bit (regular interval, the common case)
        // deltaOfDelta in [-64, 64]: 7 bits
        // deltaOfDelta in [-512, 512]: 9 bits
        // Otherwise: full 64 bits
        int timestampBitsUsed = estimateTimestampBits(deltaOfDelta);

        // XOR encoding for value
        long currentValueBits = Double.doubleToLongBits(value);
        long xorValue = currentValueBits ^ previousValueBits;
        int valueBitsUsed = estimateValueBits(xorValue);

        timestamps.add(timestamp);
        values.add(value);

        previousTimestamp = timestamp;
        previousDelta = delta;
        previousValueBits = currentValueBits;
    }

    private int estimateTimestampBits(long deltaOfDelta) {
        if (deltaOfDelta == 0) return 1;
        if (deltaOfDelta >= -64 && deltaOfDelta <= 63) return 7;
        if (deltaOfDelta >= -512 && deltaOfDelta <= 511) return 9;
        if (deltaOfDelta >= -65536 && deltaOfDelta <= 65535) return 12;
        return 64;
    }

    private int estimateValueBits(long xorValue) {
        if (xorValue == 0) return 1; // identical value — just flag bit
        // Count leading and trailing zeros to find meaningful bits
        int leadingZeros = Long.numberOfLeadingZeros(xorValue);
        int trailingZeros = Long.numberOfTrailingZeros(xorValue);
        int meaningfulBits = 64 - leadingZeros - trailingZeros;
        return 1 + 5 + 6 + meaningfulBits; // flag + leading_zeros_count + length + bits
    }

    /**
     * Returns the theoretical compression ratio compared to storing raw values.
     * Raw: 8 bytes timestamp + 8 bytes value = 16 bytes per point.
     */
    public double getCompressionRatio() {
        if (timestamps.isEmpty()) return 1.0;
        int rawBits = timestamps.size() * 128; // 16 bytes × 8 bits

        int compressedBits = 0;
        long prevTs = 0;
        long prevDelta = 0;
        long prevValBits = 0;
        for (int i = 0; i < timestamps.size(); i++) {
            long ts = timestamps.get(i);
            long delta = ts - prevTs;
            compressedBits += estimateTimestampBits(delta - prevDelta);
            long valBits = Double.doubleToLongBits(values.get(i));
            compressedBits += estimateValueBits(valBits ^ prevValBits);
            prevTs = ts;
            prevDelta = delta;
            prevValBits = valBits;
        }
        return (double) rawBits / compressedBits;
    }

    public int getDataPointCount() { return timestamps.size(); }
}
