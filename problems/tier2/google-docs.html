Design Google Docs (Collaborative Editing)

Google Docs' hardest problem: two users edit the same position simultaneously. Without conflict resolution, one user's change overwrites the other. Operational Transformation (OT) transforms operations to account for concurrent changes — ensuring convergence.

🏢 Google, Notion, Figma
⏱️ 45 min interview
📝 Real-time collaboration

❓R — Requirements3–5 min

Functional Requirements

  • Real-time collaborative text editing — multiple users editing simultaneously
  • Cursor position sharing — see where other users are editing
  • Version history — view and restore previous document states
  • Permission model — owner, editor, commenter, viewer
  • Offline editing — changes sync when reconnected
  • Comments and suggestions

Non-Functional Requirements

  • Convergence: All users must see the same document state after all operations are applied
  • Latency: Local edits appear instantly; remote edits appear <500ms
  • Scale: 1B documents, 10M concurrent editors

🔢E — Estimation3–5 min

  • 10M concurrent editors; avg 10 ops/min = 100M ops/min = 1.6M ops/sec
  • Each operation: ~50 bytes → 80MB/sec → Kafka easily handles this
  • Version history: 1B docs × avg 100 versions × 500 bytes = 50TB → S3 for compressed snapshots

🗄️S — Schema3–5 min

// Documents (PostgreSQL)
documents: doc_id, owner_id, title, created_at, last_modified

// Operations (append-only log — Cassandra or PostgreSQL)
// The document state = apply all ops in order from revision 0
operations:
    doc_id      UUID,
    revision    BIGINT,    -- monotonically increasing per document
    user_id     UUID,
    op_type     ENUM(insert, delete),
    position    INT,
    content     TEXT,       -- for insert ops
    length      INT,        -- for delete ops
    applied_at  TIMESTAMP,
    PRIMARY KEY (doc_id, revision)

// Document snapshots (S3 — compressed JSON every 1000 ops)
// Avoids replaying all ops from the beginning on load

🏗️H — High-level Design10 min

  • Client: Applies operations locally immediately (optimistic UI). Sends operations to server tagged with client's current revision number.
  • Collaboration Server: Receives operations. Applies OT to transform against concurrent operations. Assigns global revision number. Broadcasts to all clients editing the document via WebSocket.
  • Operation Log: All operations stored in Cassandra (partition by doc_id, cluster by revision) — the source of truth.
  • Document Load: Load latest snapshot from S3, then replay operations since the snapshot.
  • Presence Service: Tracks cursor positions and user presence in each document. Redis-based with 5s TTL.

🔌A — APIs5 min

// WebSocket events (client ↔ server)
// Client → Server
{ type: "op", docId, baseRevision, op: {type: "insert", position: 5, content: "a"} }
{ type: "cursor", docId, position: 42 }

// Server → Client
{ type: "op", revision: 102, op: {...}, userId }  // broadcast to all other editors
{ type: "ack", revision: 102 }                    // confirm client's op was accepted

// REST
GET  /v1/documents/{docId}              // load doc (latest snapshot + ops since)
GET  /v1/documents/{docId}/revisions    // version history
POST /v1/documents/{docId}/restore?revision=50  // restore to specific revision

🔬D — Deep Dive: Operational Transformation10 min

The problem: User A inserts 'X' at position 5. Simultaneously, User B inserts 'Y' at position 5. If both apply in sequence without transformation, 'X' shifts and 'Y' is at the wrong position.

OT transform rules:

  • insert(pos1, c1) ∘ insert(pos2, c2): If pos2 ≤ pos1: shift pos1 right by 1. Reason: B's insert at position ≤ pos1 shifts A's content right.
  • delete(pos1) ∘ insert(pos2, c): If pos2 ≤ pos1: shift pos1 right by 1.
  • insert(pos1, c) ∘ delete(pos2): If pos2 < pos1: shift pos1 left by 1. If pos2 == pos1: keep pos1 (insert at same position as delete).

Server-side OT: Server receives op with baseRevision. All server-side ops since baseRevision are transformed against the incoming op. The transformed op is applied and broadcast.

CRDT as an alternative: CRDTs (Conflict-free Replicated Data Types) automatically merge without a central server. Used by Figma, Linear. More complex to implement but enables true peer-to-peer. OT requires a central server; CRDT does not.

✅E — Evaluate3 min

  • OT correctness: OT with a central server is provably correct for convergence (CP1 and CP2 properties). Without a central server, OT becomes exponentially complex. Google Docs uses server-side OT.
  • Offline editing: Client buffers ops locally. On reconnect, sends buffered ops with the revision number from when it went offline. Server transforms each buffered op against all ops that happened during offline period.

🚀D — Deliver2 min

We designed Google Docs handling 10M concurrent editors. Key decisions: server-side OT for conflict resolution (proven convergence), append-only operation log in Cassandra (source of truth), periodic S3 snapshots for fast document loading, and WebSocket for real-time operation broadcast.

⚖️Trade-offs

DecisionChosenAlternativeWhy Chosen
Conflict resolutionOT (Operational Transformation)CRDTOT: proven, used by Google. Requires central server. CRDT: no central server needed, but larger document footprint and more complex implementation.
Operation storageAppend-only log (Cassandra)Mutable document stateAppend-only log = complete history, replay capability, audit trail, version rollback. Mutable state = faster reads but no history.
Document sync protocolWebSocketSSE (Server-Sent Events)WebSocket: bidirectional — client sends ops, server sends ops. SSE: server→client only, client needs separate HTTP requests to send. Bidirectional needed for collaborative editing.

☕Java Implementation

/**
 * OperationalTransformer — transforms operations for concurrent insert/delete conflicts.
 * Ensures all clients converge to the same document state regardless of operation order.
 */
public class OperationalTransformer {

    /**
     * Transforms operationA against a concurrent operationB.
     * Returns a new operation that, when applied after operationB, produces the same
     * result as applying the original operationA before operationB.
     *
     * @param operationA  the operation to transform
     * @param operationB  the concurrent operation that was applied first by the server
     * @return transformed version of operationA
     */
    public Operation transform(Operation operationA, Operation operationB) {
        if (operationA.getType() == OperationType.INSERT && operationB.getType() == OperationType.INSERT) {
            return transformInsertVsInsert(operationA, operationB);
        }
        if (operationA.getType() == OperationType.INSERT && operationB.getType() == OperationType.DELETE) {
            return transformInsertVsDelete(operationA, operationB);
        }
        if (operationA.getType() == OperationType.DELETE && operationB.getType() == OperationType.INSERT) {
            return transformDeleteVsInsert(operationA, operationB);
        }
        // DELETE vs DELETE
        return transformDeleteVsDelete(operationA, operationB);
    }

    /** insert(pos_a) vs insert(pos_b): shift A right if B inserted before or at A's position */
    private Operation transformInsertVsInsert(Operation insertA, Operation insertB) {
        int transformedPosition = insertA.getPosition();
        if (insertB.getPosition() <= insertA.getPosition()) {
            transformedPosition += insertB.getContent().length();
        }
        return new Operation(OperationType.INSERT, transformedPosition, insertA.getContent());
    }

    /** insert(pos_a) vs delete(pos_b, len_b): shift A left if B deleted text before A */
    private Operation transformInsertVsDelete(Operation insertA, Operation deleteB) {
        int transformedPosition = insertA.getPosition();
        if (deleteB.getPosition() < insertA.getPosition()) {
            int overlap = Math.min(deleteB.getLength(),
                                    insertA.getPosition() - deleteB.getPosition());
            transformedPosition -= overlap;
        }
        return new Operation(OperationType.INSERT, transformedPosition, insertA.getContent());
    }

    /** delete(pos_a) vs insert(pos_b): shift A right if B inserted before A */
    private Operation transformDeleteVsInsert(Operation deleteA, Operation insertB) {
        int transformedPosition = deleteA.getPosition();
        if (insertB.getPosition() <= deleteA.getPosition()) {
            transformedPosition += insertB.getContent().length();
        }
        return new Operation(OperationType.DELETE, transformedPosition, deleteA.getLength());
    }

    /** delete(pos_a) vs delete(pos_b): adjust A's position and length based on B's deletion */
    private Operation transformDeleteVsDelete(Operation deleteA, Operation deleteB) {
        if (deleteB.getPosition() >= deleteA.getPosition() + deleteA.getLength()) {
            return deleteA; // B is after A — no effect
        }
        if (deleteB.getPosition() + deleteB.getLength() <= deleteA.getPosition()) {
            // B is entirely before A — shift A left
            return new Operation(OperationType.DELETE,
                deleteA.getPosition() - deleteB.getLength(), deleteA.getLength());
        }
        // Overlapping deletes — shrink A's length by the overlap
        int overlapStart = Math.max(deleteA.getPosition(), deleteB.getPosition());
        int overlapEnd = Math.min(deleteA.getPosition() + deleteA.getLength(),
                                   deleteB.getPosition() + deleteB.getLength());
        int reducedLength = deleteA.getLength() - (overlapEnd - overlapStart);
        int newPosition = Math.min(deleteA.getPosition(), deleteB.getPosition());
        return new Operation(OperationType.DELETE, newPosition, Math.max(0, reducedLength));
    }
}
