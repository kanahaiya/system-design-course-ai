Tier 2 — Should Know 45 min Media heavy

Design Instagram

Instagram combines two distinct hard problems: media storage/delivery at scale (photos/video) and social graph feed fanout. The celebrity problem (Kylie Jenner has 400M followers) forces a hybrid fanout strategy.

🏢 Meta, Google, Pinterest
⏱️ 45 min interview
📸 100M photos/day

❓R — Requirements3–5 min

Functional Requirements

  • Upload photos and short videos; view posts from followed accounts
  • Like, comment, and share posts
  • Follow/unfollow users; public and private accounts
  • Explore page — content discovery from non-followed accounts
  • Stories — 24-hour expiry content
  • Search users and hashtags

Non-Functional Requirements

  • Scale: 1B MAU, 100M photos uploaded/day, 10B feed views/day
  • Latency: Feed load <500ms; image render <200ms from CDN
  • Availability: 99.99%; eventual consistency acceptable for feed
  • Storage: Each photo stored at 3 resolutions; ~1PB new data per year

🔢E — Estimation3–5 min

  • 100M photos/day × 3 resolutions avg 200KB each = 60TB/day storage
  • 10B feed views/day = 115K read QPS; 100M uploads/day = 1,150 write QPS → 100:1 read/write ratio
  • CDN serves 99% of media reads; origin only sees cache misses
  • Fan-out: avg 500 followers × 1,150 writes/sec = 575K feed writes/sec at peak

🗄️S — Schema3–5 min

// PostgreSQL — users and social graph
users: user_id, username, bio, is_private, follower_count, following_count
follows: follower_id, followee_id, created_at  // INDEX on followee_id for fan-out

// Posts table (PostgreSQL for metadata)
posts: post_id (Snowflake), user_id, caption, location, created_at
post_media: media_id, post_id, media_type (photo/video), s3_key, width, height

// Feed table (Redis Sorted Set per user — fanout-on-write)
// Key: feed:{user_id}  Value: sorted set of post_ids scored by timestamp
// Max 300 posts per feed, trim on overflow

// Cassandra — likes and comments (high write volume)
likes: (post_id, user_id) PRIMARY KEY  → for dedup
like_counts: post_id → counter column (atomic increment)

🏗️H — High-level Design10 min

  • Upload flow: Client → Upload Service → S3 (original) → Image Processing Service (async) → 3 resolutions → CDN push
  • Feed flow: Client → Feed Service → Redis (pre-built feed) → return post_ids → Post Metadata Service → render
  • Fanout Service: Triggered after upload. Reads follower list from DB, writes post_id to each follower's Redis feed sorted set. For celebrities: skip fanout-on-write, use fanout-on-read (pull).
  • CDN: Images served from CDN edge nodes. URL format: cdn.instagram.com/{user_id}/{post_id}/720w.jpg
  • Explore page: ML ranking service. Candidate generation (posts from similar users, trending hashtags) + re-ranking by engagement signals.

🔌A — APIs5 min

GET  /v1/posts/{postId}                // single post + metadata

POST /v1/users/{userId}/follow         // follow user

🔬D — Deep Dive: Image Processing Pipeline10 min

Raw uploads are large (5–20MB DSLR JPEGs, 500MB 4K videos). The pipeline must produce multiple optimized variants asynchronously.

  1. Client uploads original to S3 via pre-signed URL (bypasses app servers)
  2. S3 event notification triggers Image Processing Service via SQS
  3. Processing service generates: thumbnail (150×150), mobile (720px wide), full (1080px wide), WebP variants
  4. Processed images written back to S3 with CDN-friendly keys
  5. CDN origin pull: first request pulls from S3, subsequent requests served from edge cache (TTL: 1 year for immutable media)

Why async? Processing a single image takes 100ms–2s. Doing it synchronously blocks the upload API. By queuing via SQS, the upload API returns immediately (201 Created) and the post becomes visible once processing completes (typically <5s).

✅E — Evaluate3 min

  • Celebrity problem: Fanout-on-write for Kylie Jenner (400M followers) = 400M Redis writes per post. Use fanout-on-read: pull from celebrity's post list at feed read time, merge with pre-built fanout feeds.
  • Feed consistency: Eventual consistency is fine for Instagram. A follower seeing a post 1s late is acceptable.
  • Storage cost: 3 resolutions × CDN replication across 100+ PoPs is expensive. Mitigate with on-the-fly resizing at CDN edge for rare sizes.

🚀D — Deliver2 min

We designed a photo-sharing system handling 1B MAU, 100M uploads/day, and 10B feed views/day. Key decisions: S3 + CDN for media, async image processing pipeline via SQS, Redis sorted sets for pre-built feeds (fanout-on-write for normal users, fanout-on-read for celebrities), and Cassandra for high-volume like/comment counters.

☕Java Implementation

/**
 * ImageProcessingPipeline — async resize of uploaded photos to multiple resolutions.
 * Triggered by S3 event via SQS. Processes one image per invocation.
 */
public class ImageProcessingPipeline {

    private static final List<ImageVariant> VARIANTS = List.of(
        new ImageVariant("thumbnail", 150, 150, true),   // square crop
        new ImageVariant("mobile",    720, -1, false),   // width=720, height proportional
        new ImageVariant("full",     1080, -1, false)    // width=1080, height proportional
    );

    private final S3Client s3Client;
    private final String bucketName;

    public ImageProcessingPipeline(S3Client s3Client, String bucketName) {
        this.s3Client = s3Client;
        this.bucketName = bucketName;
    }

    /**
     * Entry point: download original from S3, generate all variants, upload back.
     *
     * @param originalS3Key e.g. "originals/user123/post456.jpg"
     * @return list of S3 keys for each generated variant
     */
    public List<String> processImage(String originalS3Key) throws IOException {
        byte[] originalImageBytes = downloadFromS3(originalS3Key);
        BufferedImage originalImage = ImageIO.read(new ByteArrayInputStream(originalImageBytes));

        List<String> generatedKeys = new ArrayList<>();
        for (ImageVariant variant : VARIANTS) {
            BufferedImage resizedImage = resizeImage(originalImage, variant);
            byte[] resizedBytes = encodeAsJpeg(resizedImage);
            String variantKey = buildVariantKey(originalS3Key, variant.getName());
            uploadToS3(variantKey, resizedBytes, "image/jpeg");
            generatedKeys.add(variantKey);
        }
        return generatedKeys;
    }

    private BufferedImage resizeImage(BufferedImage source, ImageVariant variant) {
        int targetWidth = variant.getWidth();
        int targetHeight = variant.isSquareCrop()
            ? variant.getHeight()
            : (int) ((double) source.getHeight() / source.getWidth() * targetWidth);

        BufferedImage resized = new BufferedImage(targetWidth, targetHeight, BufferedImage.TYPE_INT_RGB);
        Graphics2D graphics = resized.createGraphics();
        graphics.setRenderingHint(RenderingHints.KEY_INTERPOLATION, RenderingHints.VALUE_INTERPOLATION_BILINEAR);
        graphics.drawImage(source, 0, 0, targetWidth, targetHeight, null);
        graphics.dispose();
        return resized;
    }

    private byte[] encodeAsJpeg(BufferedImage image) throws IOException {
        ByteArrayOutputStream outputStream = new ByteArrayOutputStream();
        ImageIO.write(image, "jpeg", outputStream);
        return outputStream.toByteArray();
    }

    private String buildVariantKey(String originalKey, String variantName) {
        // originals/user123/post456.jpg → processed/user123/post456_mobile.jpg
        return originalKey.replace("originals/", "processed/")
                          .replace(".jpg", "_" + variantName + ".jpg");
    }

    private byte[] downloadFromS3(String key) {
        return s3Client.getObjectAsBytes(builder -> builder.bucket(bucketName).key(key)).asByteArray();
    }

    private void uploadToS3(String key, byte[] data, String contentType) {
        s3Client.putObject(
            builder -> builder.bucket(bucketName).key(key).contentType(contentType),
            RequestBody.fromBytes(data)
        );
    }

    private record ImageVariant(String name, int width, int height, boolean isSquareCrop) {
        public String getName() { return name; }
        public int getWidth() { return width; }
        public int getHeight() { return height; }
        public boolean isSquareCrop() { return isSquareCrop; }
    }
}
