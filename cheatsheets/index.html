📐 CAP Theorem
CA (PostgreSQL, MySQL)Strong consistency + availability; no partition tolerance
CP (HBase, ZooKeeper, etcd)Strong consistency + partition tolerance; sacrifice availability on partition
AP (Cassandra, DynamoDB, CouchDB)Availability + partition tolerance; eventual consistency
RuleAll distributed systems must tolerate partitions — choose C or A, not both
🗄️ SQL vs NoSQL Decision
SQL (Postgres/MySQL)ACID needed, relational data, stable schema, complex joins, <10K QPS
Document (MongoDB)Schema varies, full-doc reads, catalog/profile data
Wide-column (Cassandra)Time-series, write-heavy, multi-DC, >100K QPS
Key-value (Redis, DynamoDB)Simple lookup, cache, session, <1ms latency needed
Graph (Neo4j)Relationship traversal is core — social graph, recommendations
🔄 Consistent Hashing
Virtual nodes per physical100–200
Placementhash(key) → clockwise successor on ring
Adding nodeTakes ~K/N keys from successor
Removing nodeKeys migrate to successor
Load balance benefitVirtual nodes even out skew from uneven key distribution
vs Modulo hashingModulo remaps ~90% of keys when adding node; consistent hashing remaps only K/N
🚦 Rate Limiting Algorithms
Fixed WindowSimple; boundary burst problem (2× allowed at window edge)
Sliding Window LogAccurate; O(1) per req with Redis sorted set; high memory
Sliding Window CounterApprox accurate; O(1) memory; smooth; recommended default
Token BucketAllows burst; O(1) with Redis + Lua atomic script
Leaky BucketSmooth output rate; no burst allowed; good for payment APIs
💾 Caching Strategies
Cache-aside (Lazy)Read: check cache → miss → DB → fill cache. Write: update DB, invalidate cache. Best for read-heavy.
Write-throughWrite to cache + DB simultaneously. Always fresh. Extra write latency.
Write-backWrite to cache only, async flush to DB. Fast writes; data loss risk.
Write-aroundWrite to DB only. Cache filled on read miss. Good for write-once data.
🔁 Database Replication
Leader-followerLeader handles writes; followers serve reads. Simple; limited write scale. Failover complexity.
Multi-leaderMultiple write nodes; conflict resolution needed. Good for multi-DC active-active.
Leaderless (Dynamo)Any node accepts writes; quorum W+R>N ensures consistency. No SPOF; complex conflict resolution.
Quorum formulaW+R > N for strong consistency. Common: N=3, W=2, R=2.

🏗️ Key Architecture Patterns
Fanout on Write (Push)Pre-populate feed on post. Fast reads; expensive writes; bad for celebrities (>1M followers).
Fanout on Read (Pull)Build feed on request. Slow reads; no write amplification.
HybridPush for normal users; pull for celebrities.
CQRSSeparate read/write models for independent scaling.
Event SourcingStore events, not state. Full audit trail; replay to rebuild state.
SagaDistributed transactions via compensating actions. Choreography vs orchestration.
Circuit BreakerCLOSED → OPEN → HALF-OPEN on failure threshold. Prevents cascade failures.
